## [0.5.11] — 2026-09-14

### Добавлено

**Этап 5, подэтап 5.8 — реальный Telegram, часть E: панель подключения**

- Панель «Telegram-бот» на Панели управления (русский интерфейс,
  `src/features/telegram/TelegramBotPanel.tsx`): подключение бота,
  замена токена, отключение, статус и имя/ник бота, привязка к
  проекту. Если сервер не запущен или вход не выполнен — панель
  показывает подсказку; симулятор схем продолжает работать без
  сервера.
- Токен вводится один раз в поле пароля и уходит только на сервер
  (в шифрованное хранилище); после подключения показываются лишь имя
  секрета, имя/ник бота и статус. Токен не сохраняется в браузере и
  не попадает в файл проекта.
- АПИ-клиент фронтенда `src/lib/server-api.ts`: относительные
  запросы (в разработке проксируются Vite на `127.0.0.1:4210`),
  сессия — в куке сервера, не в `localStorage`; ошибки — тип
  `ApiClientError` с кодом и деталями.
- Чистая модель панели `src/features/telegram/bot-connect-model.ts`
  (валидация формата токена и имени секрета до отправки, оркестрация
  «секрет → бот»).
- 11 новых тестов (всего 225/225): АПИ-клиент и модель подключения —
  без сети.

## [0.5.10] — 2026-09-14

### Добавлено

**Этап 5, подэтап 5.8 — реальный Telegram, часть D: LIVE-рантайм из вебхука**

- Обработчик `server/src/telegram/handler.ts` подключён к вебхуку по
  умолчанию: обновление → бот по секретному пути → токен из Secrets
  Vault → исполнение **только опубликованной (LIVE) версии** с общими
  лимитами рантайма → исходящие сообщения через транспорт.
- Черновик никогда не исполняется вебхуком (проверено тестом: правки
  черновика после публикации не влияют на ответы бота); бот без
  привязки или без публикации молчит; отсутствие секрета не роняет
  вебхук.
- Сквозной тест цепочки «обновление → сервер → LIVE → рантайм →
  действие → мок-транспорт» (5 тестов); реальный Telegram в тестах
  не вызывается.

### Изменено

- Миграция `008_telegram_bots` (до релиза Этапа 5): `secret_id`
  получил `ON DELETE CASCADE` — удаление секрета каскадно отключает
  бота, вебхук-путь перестаёт отвечать.

## [0.5.7] — 2026-09-14

### Добавлено

**Этап 5, подэтап 5.8 — реальный Telegram, часть A: конфигурация ботов**

- Миграция `008_telegram_bots`: бот привязывается к рабочему
  пространству и (опционально) к проекту; токен хранится **только**

  существования; проект и пространство проверяются сервером; без
  сессии — 401.
- Хранилище секретов получило чтение метаданных без значения
  (`SecretStore.meta`) — связывание бота с секретом не касается
  шифротекста.

- 5 новых тестов (всего 189/189). Реальный токен для разработки и
  тестов не нужен; симулятор продолжает работать без токена.

## [0.5.6] — 2026-09-14

### Добавлено

**Этап 5, подэтап 5.7 — серверный рантайм с лимитами**

- Маршрут `POST /api/projects/:id/execute`: исполнение схемы на
  сервере через общий движок (`executeCanvas`) и общий реестр блоков.
  Рантайм использует **только опубликованную (LIVE) версию** —
  черновик не исполняется; правки черновика после публикации на
  исполнение не влияют.
- Лимиты исполнения: число шагов и повторов узла — внутренние
  константы движка; таймаут — `NODEZZLE_EXEC_TIMEOUT_MS` (по умолчанию
  10 с, исполнение отменяется, ответ `{"result":{"status":"timeout"}}`);
  параллельные исполнения — `NODEZZLE_EXEC_PARALLEL` (по умолчанию 2,
  превышение — `429`); размер полезной нагрузки — общий лимит тела
  запроса.
- Валидация публикации дополнена статическими проверками моделей:
  `MODEL_DEPTH_EXCEEDED` (вложенность > 5) и `MODEL_CYCLE`
  (циклический вызов моделей).
- 10 новых тестов (всего 184/184): исполнение с исходящими
  сообщениями, неизменяемость публикации, таймаут, параллельный отказ,
  400/401/404, глубина и цикл моделей.

## [0.5.4] — 2026-09-14

### Добавлено

**Этап 5, подэтап 5.5 — Secrets Vault**

- Миграция `006_secrets`: шифротекст + IV + тег аутентификации,
  уникальность имени секрета в пространстве.
- Модуль `server/src/security/vault.ts`: AES-256-GCM через

  `DELETE /api/workspaces/:id/secrets/:secretId`. АПИ отдаёт только
  метаданные (имя, идентификатор, даты); значения не возвращаются
  клиенту и расшифровываются только внутри сервера для рантайма.
- 10 новых тестов (всего 167/167): крипто-модуль (ключи, шифрование,
  неверный ключ) и маршруты (значения не утекают в ответы, дубли,
  изоляция, удаление).
- `.env.example`: переменная `NODEZZLE_VAULT_KEY`.

## [0.5.1] — 2026-09-14

### Добавлено

**Этап 5, подэтап 5.2 — аккаунты и сессии**

- Маршруты аккаунтов: `POST /api/auth/register` (сразу входит),
  `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`.
- Пароли — только scrypt-хеши с солью (`серверная` проверка за

  (`scrypt$N$r$p$salt$hash`).
- Сессии: случайный токен (32 байта); в базе хранится только его
  SHA-256 дайджест (миграция `002_sessions`); cookie — `HttpOnly`,
  `SameSite=Lax`, подпись HMAC-SHA256; в продакшне
  `NODEZZLE_SESSION_SECRET` обязателен (≥ 32 символов), в разработке —
  случайный.
- Ограничитель частоты входа/регистрации: 20 попыток / 10 минут с
  одного адреса (429).
- Ошибка входа единая — «Неверный адрес или пароль» (не раскрывает
  зарегистрированные адреса).
- 19 новых тестов (всего 146/146): хеши/сессионные подписи, подделки,
  истечение окна лимитов, полный сценарий регистрации/входа/выхода.

**Этап 5 (продуктовый), подэтап 5.1 — каркас сервера**

  «не найдено» / «метод не разрешён».

  нумерованные идемпотентные `.sql`-файлы только вперёд, учёт в

- 17 новых тестов (всего 127/127), включая **дымовой запуск реального
  процесса** `node server/src/index.ts` (ловит несовместимость со

- `.env.example` и `.gitignore` обновлены под сервер (`server/data/`).

- `npm run typecheck` проверяет и сервер (`tsc -p server/tsconfig.json`);
  новый скрипт `npm run server:dev` (`node --watch server/src/index.ts`).
- Витест включает тесты `server/src/**`.

- Система типов портов: 16 базовых типов (Text, Number, Boolean, JSON, Object, Array, File, Image, User, Date, URL, Secret, TelegramMessage, Any, Event, Error) + TypeRegistry для пользовательских типов.
- Умные соединения: правила совместимости INPUT/OUTPUT (data ↔ data по типу, `any` со всем, event ↔ event, error ↔ error); несовместимые соединения запрещены.
- Runtime (`executeCanvas`): живое выполнение схем — состояния IDLE/WAITING/RUNNING/SUCCESS/ERROR/STOPPED, pull-выполнение «холодных» источников, защита от циклов, отмена (Stop), телеметрия (входы/выходы/время/ошибки), outbox для Telegram-отправок (симуляция).
- Модели: контракт (INPUT/OUTPUT/ERROR), рекурсивное выполнение «модель внутри модели» (`executeModel`), блоки «Вход модели»/«Выход модели»/«Вызов модели».
- Формат проекта v1 (Zod-схема): canvas, узлы, соединения, модели, контракты, переменные, meta; адаптер ProjectStorage (LocalStorage, flush при закрытии вкладки).

**Блоки (24 зарегистрированы, 18 в палитре)**

- Ядро: Текст, Число, JSON, Вход модели, Выход модели.
- Данные (конвертеры): Текст→Число, Число→Текст, Текст→Логическое, Текст→JSON, JSON→Текст, В объект, Из объекта.
- Логика: Условие (8 операторов, значения веток), Переключатель (3 случая + Иначе).
- Поток: Задержка (с отменой).
- Telegram: Получено сообщение (триггер), Команда (триггер), Отправить сообщение, Отправить фото (симуляция).
- Web: Страница, Кнопка, Форма (триггеры событий, симуляция).
- Модели: Вызов модели.
- Отладка: Лог.
