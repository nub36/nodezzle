## [0.2.8] — 2026-09-14

### Добавлено

**Этап 2 (Промпт №2), подэтап G — Создание моделей из Canvas**

- Пункт контекстного меню «Создать модель из выделенного» (правый клик по
  детали): выделенные детали переносятся внутрь новой модели, а на их месте
  на внешнем холсте появляется одна деталь «Вызов модели».
- Диалог «Новая модель»: имя, число выделенных деталей, автоматически
  определённый контракт (ВХОД/ВЫХОД/ОШИБКА) из граничных связей, честные
  сообщения об ошибках извлечения.
- Граничные связи увязываются через конвертеры «В объект» / «Из объекта»
  (тот же приём, что в демо-проекте): внешний источник → ключ → `вход`
  «Вызова модели»; `результат` → ключ → внешние цели; ошибки — напрямую
  через error-порт «Вызова модели».
- Чистая функция ядра `extractModel()` (`src/core/models/extract.ts`):
  контракт из типов граничных портов, внутренний холст модели с
  нормализованными позициями, пересборка внешнего холста; не зависит от
  React и пригодна для тестов.
- Работает и на главном холсте проекта, и внутри модели (модель из модели);
  после создания узел «Вызов модели» выделяется, состояние попадает в историю
  (отмена доступна).
- Текущие честные ограничения (фиксируются в диалоге и статусе): не более
  одного внешнего входа (многопортовые контракты — вместе с динамическими
  портами), триггеры внутри выделения и внешние связи-события отклоняются,
  стикеры-заметки в извлечении не участвуют.
- 11 новых тестов (всего 78): ядро `extractModel` — 8, интеграция экшена
  стора `createModelFromSelection` — 3.

## [0.2.6] — 2026-09-14

### Добавлено

**Этап 2 (Промпт №2), подэтап H — Спуск внутрь (Drill Down)**

- Двойной клик по детали «Вызов модели» открывает её внутренний холст.
- Хлебные крошки `Проект › Модели › Название модели` с возвратом на уровень проекта.
- Автосохранение и мгновенное сохранение учитывают активный уровень (`withActiveCanvas`): правки записываются в холст проекта либо во внутренний холст модели (`StoredModel.canvas`), формат проекта не менялся.
- Действия стора `openModel` / `closeModel`; при смене уровня очищается история правок и сбрасывается состояние выполнения.
- Подсказка в инспекторе «Вызов модели»: как открыть модель изнутри.

### Известные ограничения (честно)

- История правок не сквозная между уровнями (очищается при переходе) — приемлемо для этапа, развитие возможно позже.
- Выполнение (симулятор) запускает основную схему; вложенные модели исполняются через неё, как и в фундаменте.

## [0.1.0] — 2026-09-13

### Добавлено

**Фундамент проекта**

- Инициализация структуры NODEZZLE: ядро, блоки, экраны, документация (12 документов на русском).
- Технологический стек: Vite + React 19 + TypeScript, @xyflow/react (React Flow 12), Zustand, i18next (ru-RU), Tailwind CSS 4, Zod 4, Vitest. Обоснование — [docs/DECISIONS.md](docs/DECISIONS.md).
- `.gitignore` и безопасный `.env.example` (только названия переменных и фиктивные значения).

**Ядро (src/core)**

- Block Definition + BlockRegistry: расширяемая регистрация деталей; ядро не привязано к конкретным платформам.
- Система типов портов: 16 базовых типов (Text, Number, Boolean, JSON, Object, Array, File, Image, User, Date, URL, Secret, TelegramMessage, Any, Event, Error) + TypeRegistry для пользовательских типов.
- Умные соединения: правила совместимости INPUT/OUTPUT (data ↔ data по типу, `any` со всем, event ↔ event, error ↔ error); несовместимые соединения запрещены.
- Runtime (`executeCanvas`): живое выполнение схем — состояния IDLE/WAITING/RUNNING/SUCCESS/ERROR/STOPPED, pull-выполнение «холодных» источников, защита от циклов, отмена (Stop), телеметрия (входы/выходы/время/ошибки), outbox для Telegram-отправок (симуляция).
- Модели: контракт (INPUT/OUTPUT/ERROR), рекурсивное выполнение «модель внутри модели» (`executeModel`), блоки «Вход модели»/«Выход модели»/«Вызов модели».
- Формат проекта v1 (Zod-схема): canvas, узлы, соединения, модели, контракты, переменные, meta; адаптер ProjectStorage (LocalStorage, flush при закрытии вкладки).

**Блоки (24 зарегистрированы, 18 в палитре)**

- Ядро: Текст, Число, JSON, Вход модели, Выход модели.
- Данные (конвертеры): Текст→Число, Число→Текст, Текст→Логическое, Текст→JSON, JSON→Текст, В объект, Из объекта.
- Логика: Условие (8 операторов, значения веток), Переключатель (3 случая + Иначе).
- Поток: Задержка (с отменой).
- Telegram: Получено сообщение (триггер), Команда (триггер), Отправить сообщение, Отправить фото (симуляция).
- Web: Страница, Кнопка, Форма (триггеры событий, симуляция).
- Модели: Вызов модели.
- Отладка: Лог.
- Дата и время: Текущее время.
- Зарезервированы (available: false): Переменная, Общее хранилище, Обработчик ошибок, Отправить/Получить событие, HTTP-запрос, AI: запрос.

**Интерфейс (ru-RU)**

- Главная: Hero с анимацией соединяющихся деталей, Playground (интерактивная демонстрация с демо-чатом), возможности, Premium Dark UI (glassmorphism, aurora, glow).
- Dashboard: проекты, создание (Telegram-бот / Web / HTML / Telegram + Web / Пустой), загрузка демо-примера, удаление.
- Canvas: библиотека деталей (категории, поиск, drag & drop), кастомные узлы из Block Definition, умные соединения с подсветкой совместимых портов, undo/redo (Ctrl+Z/Ctrl+Shift+Z), копировать/вставить/дублировать (Ctrl+C/V/D), Delete, minimap, autosave (debounce 900 мс + beforeunload), инспектор детали (конфигурация + результат последнего выполнения).
- Debug-панель: Симулятор (Telegram/Web payload), Чат Telegram (outbox), Журнал выполнения (LOG), История (execution history); частицы/анимация по соединениям во время выполнения.

**Демо**

- Демонстрационный проект «Пример: Telegram-приветствие»: `Получено сообщение → В объект → Вызов модели «Приветствие» → Из объекта → Отправить сообщение`; модель с контрактом (text → reply).

**Тесты**

- 34 unit-теста: система совместимости, реестр, формат проекта, хранилище, runtime (демо-схема, ветвление, конвертеры, ошибки, команды, логи, циклы, задержка, отмена, модель внутри модели).
