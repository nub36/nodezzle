## [0.2.9] — 2026-09-14

### Добавлено

**Этап 2 (Промпт №2), подэтап F часть 2 — Группы (визуальные рамки)**

- Опциональное поле `groups` в `CanvasDocument` (формат v1, без смены версии
  и без миграции — старые проекты остаются валидными): рамка = `id`,
  подпись и список деталей-участников.
- Рамки на холсте (`GroupFrames`): пунктирная рамка по габаритам участников,
  ярлык с названием. Клик по ярлыку выделяет участников, перетаскивание
  ярлыка двигает всю группу, двойной клик — переименование, крестик —
  убрать рамку (детали остаются).
- Пункты контекстного меню: «Сгруппировать выделенное» (2+ детали, на узле
  и на пустом холсте) и «Разгруппировать» (узел в рамке).

  вычищается из рамок, опустевшие рамки исчезают.
- Группы входят в снапшоты истории (undo/redo) и сохраняются в документ
  на обоих уровнях (холст проекта и холст модели), переживают смену уровня
  (Drill Down) и перезагрузку.
- При создании модели из выделенного рамки внешнего холста обрезаются:
  ушедшие в модель детали исключаются, пустые рамки удаляются.

### Добавлено

**Этап 2 (Промпт №2), подэтап G — Создание моделей из Canvas**

- Пункт контекстного меню «Создать модель из выделенного» (правый клик по

  сообщения об ошибках извлечения.
- Граничные связи увязываются через конвертеры «В объект» / «Из объекта»
  (тот же приём, что в демо-проекте): внешний источник → ключ → `вход`
  «Вызова модели»; `результат` → ключ → внешние цели; ошибки — напрямую
  через error-порт «Вызова модели».
- Чистая функция ядра `extractModel()` (`src/core/models/extract.ts`):
  контракт из типов граничных портов, внутренний холст модели с
  нормализованными позициями, пересборка внешнего холста; не зависит от
  React и пригодна для тестов.
- Работает и на главном холсте проекта, и внутри модели (модель из модели);
  после создания узел «Вызов модели» выделяется, состояние попадает в историю
  (отмена доступна).
- Текущие честные ограничения (фиксируются в диалоге и статусе): не более
  одного внешнего входа (многопортовые контракты — вместе с динамическими
  портами), триггеры внутри выделения и внешние связи-события отклоняются,
  стикеры-заметки в извлечении не участвуют.
- 11 новых тестов (всего 78): ядро `extractModel` — 8, интеграция экшена
  стора `createModelFromSelection` — 3.

- Умные соединения: правила совместимости INPUT/OUTPUT (data ↔ data по типу, `any` со всем, event ↔ event, error ↔ error); несовместимые соединения запрещены.
- Runtime (`executeCanvas`): живое выполнение схем — состояния IDLE/WAITING/RUNNING/SUCCESS/ERROR/STOPPED, pull-выполнение «холодных» источников, защита от циклов, отмена (Stop), телеметрия (входы/выходы/время/ошибки), outbox для Telegram-отправок (симуляция).
- Модели: контракт (INPUT/OUTPUT/ERROR), рекурсивное выполнение «модель внутри модели» (`executeModel`), блоки «Вход модели»/«Выход модели»/«Вызов модели».
- Формат проекта v1 (Zod-схема): canvas, узлы, соединения, модели, контракты, переменные, meta; адаптер ProjectStorage (LocalStorage, flush при закрытии вкладки).

- Данные (конвертеры): Текст→Число, Число→Текст, Текст→Логическое, Текст→JSON, JSON→Текст, В объект, Из объекта.
- Логика: Условие (8 операторов, значения веток), Переключатель (3 случая + Иначе).
- Поток: Задержка (с отменой).
- Telegram: Получено сообщение (триггер), Команда (триггер), Отправить сообщение, Отправить фото (симуляция).
- Web: Страница, Кнопка, Форма (триггеры событий, симуляция).
