# NODEZZLE — Web Layer

Web / HTML — второе главное направление NODEZZLE. Как и Telegram, Web-слой построен **поверх общего ядра**: веб-элементы — Block Definitions категории `web`; их события — триггеры, их данные — обычные INPUT/OUTPUT.

## Элементы Web

Полный список (концепция):

```
PAGE · SECTION · CONTAINER · GRID · TEXT · IMAGE · BUTTON · INPUT ·
TEXTAREA · FORM · MODAL · MENU · LINK · HTML · CSS · JS
```

Русские названия в UI: Страница, Секция, Контейнер, Сетка, Текст, Изображение, Кнопка, Поле ввода, Текстовая область, Форма, Модальное окно, Меню, Ссылка, HTML, CSS, JS.

**Этап 0:** реализованы триггер-события `web.page` (Страница), `web.button` (Кнопка), `web.form` (Форма) — каждая отдаёт «Данные» (payload события). **Рендеринг собранной страницы (живое превью)** — ROADMAP этап 2: canvas → DOM-дерево (PAGE/SECTION/GRID/… + события).

## События Web

| Событие (англ.) | Событие (ru) |
|---|---|
| Page Load | Загрузка страницы |
| Button Click | Нажатие кнопки |
| Form Submit | Отправка формы |
| Input Change | Изменение поля |
| Modal Open / Modal Close | Открытие / закрытие окна |

События — это **триггеры** (то же понятие, что в Telegram): они запускают схему, затем данные текут по общей логике NODEZZLE.

## Пример

```
Форма → Отправка формы → INPUT модели → Модель → OUTPUT модели → Окно «Успешно»
```

Схема (задел):

```
web.form (→ Данные: {name, email, …})
  → data.to_object (ключи полей)
  → models.call (Order Model)
  → web.modal (показать результат)
```

## Web-события в runtime

События Web создаёт Симулятор (Debug-панель, источник «Web» + JSON-данные) и **веб-превью** (вкладка «Веб» в Debug-панели, Этап 2 подэтап I часть 2): загрузка страницы, клик по кнопке и отправка формы генерируют те же `TriggerPayload` (`source: 'web'`), поэтому схемы не меняются. Текст, структуры, URL, поля и информационные окна реализованы в 09B1–B5 ниже. Полная публикация сайта не реализована; не все runtime-события автоматически связаны с UI.

## Telegram + Web — одна система

Telegram и Web — **не** две отдельные системы. Один проект может содержать:

```
Telegram Bot → WebApp URL → Telegram WebApp → HTML Page → Button Click
→ Order Model → Order Created → Telegram Message
```

Общее ядро: одна система блоков, один runtime, общий формат проекта, общие модели и переменные. Тип проекта «Telegram + Web» создаётся с Dashboard.

## Принципы

- Web-элементы используют те же INPUT/OUTPUT, что и Telegram: совместимость, конвертеры, модели — общие.
- HTML/CSS/JS-элементы (в будущем) — как блоки с типом `json`/`text` на выходе (содержимое) и событиями (триггеры).
- Превью Web-страницы — в отдельной вкладке Canvas (этап 2): страница рендерится из той же схемы (единый источник правды).
- Безопасность: пользовательский JS в `JS`-блоках — в изолированном окружении (iframe/sandbox, этап 4), секреты — только в backend (тип `secret`).


## Уточнение маршрутизации событий (0.5.32)

`payload.web.event`, когда задан, фильтрует тип триггера:
`page_load` → `web.page`, `button_click` → `web.button`,
`form_submit` → `web.form`. Загрузка превью больше не запускает кнопку.
Неизвестное явное событие не запускает ни один из этих обработчиков;
источник Telegram также не подходит. Без поля `event` сохранён общий
запуск веб-триггеров для старых схем и JSON симулятора.

Это фильтрация по **типу события**, не адресация экземпляров: несколько
кнопок одного типа пока реагируют вместе. Рендеринг/адресация отдельного
элемента не расширялись. Веб-превью и симулятор используют один runtime;
урок проверен настоящим кликом с сопоставлением выходных/входных данных.


## Адресация экземпляров в превью (0.5.38, 09A)

Ограничение 0.5.32 «все кнопки одного типа реагируют вместе» устранено
для событий превью. `fireWebTrigger(web, targetNodeId)` передаёт ID узла
отдельно от объекта данных события. Runtime сначала выбирает адресованную
точку входа активного холста, затем проверяет `matches` (тип/источник).
Клик запускает свою кнопку, submit — свою форму. Подписи могут совпадать:
они не служат адресами. Неверный ID/не-триггер дают ожидание `ERR_NO_TRIGGER`,
а не запуск всех узлов. Без targetNodeId сохраняется прежняя рассылка
подходящим триггерам — в том числе старые вызовы и JSON симулятора.

Превью по-прежнему показывает первую `web.page`; загрузка и кнопка
перезагрузки адресуют именно её. Маркер загрузки различает проект,
активную модель и ID страницы. Черновики форм относятся к текущему
контексту/монтированию превью; не сохраняются в проекте и после F5.
Форме разрешён только JSON-объект. Ошибка видна рядом с полем, кнопка
отправки недоступна; массив/примитив/null не подменяются пустым объектом.
Служебный targetNodeId не попадает в `outputs.data`; форма отдаёт values,
кнопка/страница — прежние данные события.

Проверки: 9 runtime + 9 парсера + 1 стора, 3 браузерных сценария:
две одинаковые кнопки/формы с раздельными логами, F5, ошибочные данные и
две страницы. Общий набор — **493 + 55**. Это не полноценный DOM-рендерер,
не публикация сайта по адресу рамки и не новое серверное хранилище.


## Текст и заголовок (0.5.39, 09B1)

`web.text` и `web.heading` теперь implemented/доступны. Это два листовых
элемента, не полный конструктор DOM. Они выводятся после названия первой
страницы, перед кнопками/формами, в порядке узлов; работают и без web.page.
Позиции на холсте не задают расположение элементов страницы.

- Настройки text (по умолчанию пустая строка), heading.level (по умолчанию 2).
- Вход, отличный от undefined, приоритетнее настройки; undefined означает
  отсутствие данных (runtime заполняет им также неподключённые порты).
  Пустая строка сохраняется, null/объекты/числа не преобразуются в текст.
- level — только целое число 1–6. Неверный тип/уровень даёт ERR_WEB_ELEMENT,
  а не успешный элемент. Старые узлы без настроек используют defaults.
- Выходной порт element остаётся object: `{kind:'text', text:string}` либо
  `{kind:'heading', text:string, level:number}`. Это инертные данные.
  React создаёт p/h1–h6 с текстовыми детьми; HTML, script и атрибуты из
  данных не вставляются/не выполняются. Переносы строк сохраняются.
- Без подключённых входов превью строится из настроек сразу. С проводом
  показывается только успешный выход данного узла последнего актуального
  запуска, иначе — подсказка ожидания. Во время запуска старый текст скрыт.
  Ошибку выполнения можно уточнить на вкладке «Порты»/в журнале.
- Сравнивается ключ схемы на **старте** выполнения и текущие узлы (ID,
  blockId, config), связи, проект, активная модель и определения моделей.
  Перемещение/выделение узлов активного холста не сбрасывает результат.
  Изменения определения модели консервативно инвалидируют результат целиком,
  включая её метаданные/геометрию. Undo к идентичной схеме допускает её результат.
  После F5 результат не восстанавливается из истории — нужен новый запуск.

Превью не запускает автономные вычисления и не меняет правила входа runtime:
при наличии триггера подключённый элемент должен выполняться в его цепочке;
просто соседний несвязанный источник не становится частью события страницы.
Текущий рендерер не показывает внутренности модели из внешнего холста.
Контейнеры/секции/сетки, изображения/ссылки/поля остаются planned.

Проверки: 15 новых unit/integration + 3 E2E, всего **508 + 58**.
Реальные провода и запуск, смена текста, перенос узла без сброса, F5,
HTML как строка, ошибочный уровень и исправление; 09A и все уроки сохранены.


## Вложенная структура (0.5.40, 09B2)

Ограничение раздела 09B1 «контейнеры planned» снято для container/section/grid.
Это развитие безопасного дерева, не завершённый конструктор всех Web UI.

### Контракт

- `web.container`: children:array → element:object.
- `web.section`: title:text, children:array → element:object.
- `web.grid`: columns:number, children:array → element:object.
- Дескрипторы: `{kind:'container',children:[...]}`,
  `{kind:'section',title:string,children:[...]}`,
  `{kind:'grid',columns:number,children:[...]}`. Внутри допустимы эти же
  структуры и прежние text/heading. Порядок массива сохраняется.
- Нет данных children (undefined) — пустой массив; null/объект/массив строк
  не заменяются пустым содержимым. children задаётся входом, не строковым
  полем JSON в инспекторе. Section.title по умолчанию '', grid.columns — 2.
  Вход, отличный от undefined, приоритетнее настройки. Колонки — целое 1–6.
- `core.array` задаёт исходный массив, `data.array_add` добавляет дескриптор.
  Существующая совместимость object/array не меняется: прямой провод
  element:object → children:array недопустим; нужен массив.
- Валидатор создаёт очищенную копию, не распространяет HTML/атрибуты в DOM.
  Вложенная секция имеет текстовый h2, контейнер — div, сетка — CSS Grid
  с равными колонками. Пустое содержимое объясняется подсказкой.
- Лимит на одно дерево структуры: 16 уровней (корень — первый), 256 узлов,
  65536 символов суммарного текста/заголовков. Соседние повторения одного
  значения разрешены и учитываются отдельно. Циклы запрещены.
  Неверный ребёнок/тип/лимит — ERR_WEB_TREE; частичный выход не возвращается.
  Отдельные корневые листья сохраняют поведение 09B1 без нового лимита текста.

### Корни превью и свежесть

Начальный порядок корней — порядок узлов. UI-узел, от которого по data-связям
зависит children структуры, не показывается ещё раз отдельным корнем.
Обход проходит и промежуточные блоки массивов/моделей. Общий ребёнок может
отображаться в нескольких родителях — это разные места использования.

Это консервативное правило графа, не анализ равенства JSON и не учёт
фактически выбранной ветки: если промежуточный блок удалил ребёнка из массива,
его источник всё равно считается использованным. После удаления связи он
снова может стать корнем. Цикл зависимости структуры от себя отображается
подсказкой даже при наличии других независимых корней.

Подключённый корень требует успешного собственного результата на актуальном
ключе 09B1. ERR_WEB_TREE виден в превью, подробности запуска — в отладке.
Правка данных/связей скрывает старый вывод, перенос узлов — нет; после F5
нужен запуск. Правила триггеров runtime не меняются: наличие page не делает
несвязанные источники частью её события. Кнопки/формы/первая page пока живут
отдельным слоем 09A, а не дочерними дескрипторами дерева.

### Практика: текст внутри сетки

Для первого примера создайте **пустой проект без триггеров**.

1. В библиотеке включите режим **«Все»** (структуры и константа-массив —
   расширенные детали).
2. Добавьте «Текст» из Web (`web.text`) и задайте текст в настройках.
3. Добавьте «Массив» (`core.array`), значение оставьте `[]`.
4. Добавьте «Добавить в массив» (`data.array_add`). Соедините выход
   «Значение» массива с его входом «Массив», а выход «Элемент» Web-текста —
   со входом «Элемент» блока добавления.
5. Добавьте «Сетка» (`web.grid`). Соедините выход «Массив» блока добавления
   со входом «Дочерние элементы» сетки. В настройках задайте 2 колонки.
6. Откройте «Веб» в отладке и нажмите «Запустить». Текст виден внутри сетки,
   а не вторым отдельным абзацем снаружи. Один ребёнок занимает первую ячейку.
7. Для второго ребёнка добавьте ещё один Web-текст/заголовок и ещё один
   «Добавить в массив»: предыдущий массив → следующий вход «Массив», новый
   элемент → вход «Элемент». Последний массив подключите вместо первого
   к сетке. Так задаётся явный порядок детей.
8. Для вложенности добавьте результат сетки в другой массив и передайте
   его контейнеру/секции тем же способом. Позиция блоков на холсте не
   определяет вёрстку страницы.

Проверки: 26 новых unit/integration + 4 E2E, общий набор **534 + 62**.
Реальные провода, вложенная секция/контейнер/сетка, HTML как текст,
порядок/колонки, отсутствие дубля, ошибки/исправление и F5. Публикация,
картинки/ссылки/поля/модальные окна этим подэтапом не реализованы.


## Изображения и ссылки (0.5.41, 09B3)

Ограничение B2 «image/link planned» снято. Поля и модальное окно реализованы ниже в B4/B5.

### Контракт и адреса

- `web.image`: src:url, caption:text → element:object;
  `{kind:'image',src:string,caption:string}`.
- `web.link`: href:url, text:text → element:object;
  `{kind:'link',href:string,text:string}`.
- Настройки совпадают с именами входов, по умолчанию пустые строки.
  Пока адрес пуст, выводится подсказка, runtime возвращает ERR_WEB_URL_ELEMENT.
  Вход не undefined приоритетнее настройки; null не означает fallback.
  Caption/text — строка до 65536 символов. Пустая подпись изображения
  допустима (alt=""); у пустой/пробельной подписи ссылки видимым текстом
  становится канонический адрес.
- URL — только абсолютный HTTPS, без credentials, с портом 443 либо без
  явного порта. Относительные адреса, http, data, blob, file, javascript,
  mailto и protocol-relative не поддерживаются. До 2048 символов как до,
  так и после канонизации URL; внешние пробелы обрезаются, управляющие
  символы, обратные слеши и внутренние пробельные символы запрещены.
- Нужен DNS-host из двух и более корректных меток. IP (включая числовые,
  шестнадцатеричные формы IPv4 и IPv6), single-label и суффиксы localhost,
  local, localdomain, internal, lan, home, home.arpa, test, invalid запрещены.
  Unicode-домены канонизируются в punycode. Это синтаксическая защита,
  **не гарантия доверия к домену и не проверка DNS/редиректов**.
- Валидатор един для runtime, отдельных корней и вложенных дескрипторов.
  В дереве B2 длины URL/подписей входят в общий бюджет строк 65536;
  неподдерживаемый URL ребёнка отклоняет всё дерево с ERR_WEB_TREE.
  Произвольные srcset/style/onclick/onerror/target не копируются в DOM.

### Поведение браузера

Изображение сначала показывает адрес, подпись и «Загрузить изображение».
До нажатия img отсутствует: сохранённый проект/JSON не инициирует загрузку.
После нажатия браузер обращается к источнику с referrerPolicy=no-referrer.
Источник всё равно получает IP и может получить свои cookies по правилам
браузера. Внешние ресурсы следует загружать только из доверенных источников.
Нет серверного скачивания, proxy или проверки MIME/редиректа на сервере.

Есть состояние загрузки, понятная ошибка и повторная попытка. Изображение
ограничено шириной контейнера/высотой 320 px, подпись выводится текстом.
Смена src сбрасывает согласие; смена проекта/активной модели также
перемонтирует корень. После F5/размонтирования согласие не восстанавливается.
Новый запуск проводной цепочки снимает её вывод на время выполнения,
поэтому загрузку картинки нужно разрешить вновь. Статическое изображение
с тем же src может оставаться загруженным при переносе/правке подписи.

Ссылка — настоящий a с target=_blank, rel="noopener noreferrer" и
referrerPolicy=no-referrer. Есть подсказка с адресом и уведомление новой
вкладки для скринридера. Редактор не покидается. Внешний сайт не получает
window.opener, но это не защита от фишинга/вредного содержимого самого сайта.

### Практика

1. Добавьте «Картинка» (`web.image`), задайте HTTPS-адрес и подпись.
2. Откройте вкладку «Веб», проверьте показанный адрес, нажмите «Загрузить
   изображение». Ошибка доступности источника не считается ошибкой runtime.
3. Добавьте «Ссылка» (`web.link`), настройте HTTPS-адрес и подпись «Открыть».
   Клик откроет отдельную вкладку. Не требуется запуск без подключённых входов.
4. Для данных по проводу используйте «URL» (`core.url`) → src/href;
   после изменения значений запускайте свою цепочку заново.
5. Для вложения передайте element в data.array_add и далее массив в
   children сетки/контейнера, как в практике B2. URL проверяется и в этом пути.

Проверки: 42 новых unit/integration + 4 E2E; всего **576 + 66**.
Внешняя сеть E2E замокана: факт отсутствия запроса до согласия, загрузка,
ошибка/повтор, no-referrer, opener, реальный провод, F5 и вложенное дерево.
Проверки не доказывают доступность произвольного внешнего сайта.


## Поля ввода и формы (0.5.42, 09B4)

На момент B4 input/textarea стали implemented; modal реализован ниже в B5.

### Контракт

- `web.input` и `web.textarea`: прежние входы label:text, placeholder:text,
  выход element:object. Настройки label/placeholder, fieldName, formNodeId,
  initialValue. Входы label/placeholder приоритетнее настроек, undefined —
  fallback, null — ошибка. Начальные значения и имя данных задаются настройками.
- Дескриптор: `{kind:'input'|'textarea', name, formNodeId, label, placeholder,
  value}`. Все дополнительные атрибуты отбрасываются. value — **начальное**
  значение, а не текущее содержимое DOM-контрола. Runtime не читает клавиатуру.
- name: 1–64 ASCII-символа, первая — латинская буква, далее буквы/цифры/_;
  constructor/prototype запрещены (__proto__ не проходит шаблон). Это простой
  ключ данных, не путь объекта; точки и [] не поддерживаются.
- Подпись/подсказка/начальное и введённое значения — до 4096 символов.
  formNodeId — строка до 256 без управляющих символов; пустая означает
  отсутствие привязки. Ошибка дескриптора — ERR_WEB_FIELD, внутри дерева —
  ERR_WEB_TREE. Строки поля входят в общий бюджет дерева 09B2.
- У `web.form` настройка formMode: `json` (по умолчанию) или `fields`.
  JSON-режим 09A сохранён без смешивания с полями, вложенные объекты/0/false
  передаются как раньше. В режиме fields отправляются только строки,
  включая пустые, до 64 полей на форму. Новых портов у формы нет.

### Привязка и отправка

В инспекторе поля выбирается **экземпляр** формы активного холста, не её
название. В списке одинаковые подписи различаются порядковым номером.
У целевой формы нужен режим «Поля». Без подходящего экземпляра поле
отключено и объясняет причину. Поля могут располагаться внутри деревьев B2:
стандартный HTML-атрибут form связывает input/textarea с отдельной формой,
не требуя вложенного HTML form. Каждый WebPreview получает свой DOM-префикс.

Список ожидаемых полей строится из тех же проверенных дескрипторов, что
рендерятся. При submit native FormData проверяется повторно: никаких
дубликатов, лишних/пропущенных ключей, файлов или превышенных значений.
Пустая форма, повтор имени (включая повторное вложение одного поля),
превышение 64 полей блокируют отправку. Одинаковые имена в **разных** формах
допустимы. Событие передаётся прежним fireWebTrigger с targetNodeId формы;
служебная привязка не входит в outputs.data. На вводе событий не запускаем.

Режим fields **консервативно блокируется для всех таких форм**, если
хотя бы один корень превью неактуален/невалиден или обнаружен цикл: иначе
скрытые поля могли бы исчезнуть из отправляемого набора. JSON-формы от этой
проверки не зависят. Ошибки загрузки внешнего изображения не делают его
дескриптор невалидным и не относятся к этой блокировке.

Неотправленные черновики живут только в DOM. F5, смена контекста,
размонтирование (в том числе переключение вкладки отладки) или изменение
дескриптора сбрасывают их к initialValue. Перенос узла не сбрасывает ввод.
После submit значения попадают в обычные выходы, журналы и историю запуска;
это не защищённое хранилище паролей. Предлагаются только текстовые поля.

### Копирование и ограничения

При duplicate/copy+paste поля вместе с его формой config.formNodeId
переназначается на новую форму. Копия одного поля теряет внешнюю привязку;
оригинал не меняется. Undo/redo сохраняет новые ID и их связи. Правило
применяется только к явным настройкам web.input/web.textarea — произвольный
JSON в core.array и определения моделей не переписываются. После переноса
таких данных привязки проверяются вручную; ID не переносит контекст модели.

Правила runtime не меняются: проводные дескрипторы должны быть выполнены
своей цепочкой, наличие формы не запускает соседние холодные источники.
Для первого примера используйте **статические настройки** полей, без проводов.
Дерево с проводными детьми можно подготовить событием страницы. После
другого запуска его результат может стать неактуальным; повторите событие
подготовки. Возврат к вкладке «Веб» вновь монтирует превью и вызывает page_load,
если страница есть (прежнее поведение 09A).

### Практика: форма с именем и сообщением

1. В библиотеке включите «Все», добавьте «Форма» (`web.form`).
2. В инспекторе выберите «Режим формы» → «Поля».
3. Добавьте «Поле ввода» (`web.input`). Имя поля — `name`, подпись — «Имя».
   В «Форма для поля» выберите созданную форму.
4. Добавьте «Многострочное поле» (`web.textarea`): имя `message`, подпись
   «Сообщение», та же форма. Начальное значение можно оставить пустым.
5. Соедините выход «Данные» формы со входом «Значение» `debug.log`.
6. Откройте «Веб», заполните поля и нажмите кнопку своей формы. На вкладке
   «Порты»/в журнале увидите объект `{name: '...', message: '...'}`.
7. Для проверки независимости выделите форму, поля и лог и дублируйте
   фрагмент. Вторая форма отправляет только значения собственных полей.
8. Если нужен прежний произвольный JSON-объект — переключите форму обратно
   в JSON. Поля не добавятся к нему автоматически.

Проверки: 24 новых unit/integration + 5 E2E; всего **600 + 71**.
Обе формы/копирование, реальные строки и переносы, пустые значения, F5,
отсутствующая форма, дубликаты, JSON-совместимость, вложенное поле и
блокировка неактуального дерева. Все 12 уроков сохранены.


## Информационное модальное окно (0.5.43, 09B5)

Все 10 деталей web_ui доступны; это **не** полная публикация Web-сайта.
Прежние ограничения modal в разделах B1–B4 описывают соответствующие версии.

### Контракт и поведение

- `web.modal`: title:text, children:array → element:object, настройка title
  по умолчанию пустая. Дескриптор `{kind:'modal',title,children}` — только
  инертные данные, без open, HTML и обработчиков. Вход приоритетнее настройки;
  undefined использует настройку, null недопустим. Без children окно пустое.
- Общие ограничения дерева B2: глубина 16, узлов 256, строк 65536 символов,
  включая заголовок. Текст/заголовки, HTTPS-картинки/ссылки и структуры разрешены.
  Поля input/textarea и другие modal **на любой глубине внутри окна запрещены**:
  ошибка ERR_WEB_TREE вместо частичного дерева. Окно внутри обычной структуры
  и несколько окон-соседей допустимы. Невалидный корень блокирует режим «Поля»
  так же, как другие ошибки дерева B4; JSON-режим не меняется.
- В превью появляется компактная кнопка «Открыть окно: …», а не автоматически
  открытый диалог. Пустой/пробельный заголовок получает имя «Модальное окно».
  Нативный dialog/showModal выводит окно поверх рамки превью, фон недоступен.
  Кнопка закрытия получает фокус; Tab/Shift+Tab остаются внутри. Escape/кнопка
  закрывают окно и возвращают фокус существующей кнопке открытия. Клик по
  фону не закрывает. Клавиши редактора не удаляют/дублируют фоновые узлы.
- Дети монтируются только после открытия. Картинка по-прежнему требует
  отдельного согласия; закрытие удаляет её и сбрасывает согласие. Исчезновение
  сфокусированной кнопки загрузки возвращает фокус в диалог.
- Состояние открытия локально: новый дескриптор/контекст, запуск, F5 и
  размонтирование закрывают окно. В проект/undo/историю оно не сохраняется.
  Проводные дети требуют актуального запуска своей цепочки, как в B2.

**Важно:** открытие/закрытие этого информационного окна не запускает схему
и не вызывает `web.modal_open`/`web.modal_close`. Эти существующие триггеры
остаются событиями симулятора/API. Автоматическая связь с UI — отдельный
контракт: новый запуск сейчас может заменить результат и уничтожить диалог.
Схема-концепция «форма → окно» выше пока не означает автоматическое открытие.
Нет форм внутри окна, стека диалогов, публикации или нового транспорта.

### Практика: окно «О проекте»

1. В библиотеке выберите «Все», найдите `web.modal` («Модальное окно»).
   В свойствах задайте «Заголовок окна» — «О проекте».
2. Откройте вкладку «Веб», нажмите «Открыть окно: О проекте». Пока внутри
   пусто — это нормально. Закройте кнопкой или Escape.
3. Добавьте Web-текст (`web.text`) с описанием проекта. Добавьте «Массив»
   (`core.array`, значение `[]`) и «Добавить в массив» (`data.array_add`).
4. Соедините core.array → вход «Массив» data.array_add; выход «Элемент»
   web.text → вход «Элемент» data.array_add; выход «Массив» → вход
   «Дочерние элементы» web.modal. Напрямую object → array соединить нельзя.
5. В новом холсте без других триггеров нажмите «Запустить». В существующей
   событийной схеме сначала выполните цепочку подготовки этих данных.
   Откройте окно: описание внутри, а не отдельным дубликатом в превью.
6. Проверьте Tab/Shift+Tab и Escape. Для второго ребёнка продолжите цепочку
   data.array_add, как в практике контейнеров. Картинку нужно разрешать
   заново после каждого закрытия. Поля оставляйте вне модального окна.
7. Исправили текст/провод — выполните цепочку повторно. F5 восстанавливает
   схему, но не открытое окно и не согласие на внешние картинки.

Проверки: 10 новых unit/integration + 4 E2E, всего **610 + 75**. Нативная
модальность, фокус/клавиши Canvas, независимые экземпляры, отсутствие запуска
по открытию/закрытию, проводные данные/ошибки, согласие на изображение и F5,
экран 390 px. Все 12 уроков и формы B4 повторно пройдены. Решение — ADR-024.
