# NODEZZLE — Web Layer

Web / HTML — второе главное направление NODEZZLE. Как и Telegram, Web-слой построен **поверх общего ядра**: веб-элементы — Block Definitions категории `web`; их события — триггеры, их данные — обычные INPUT/OUTPUT.

## Элементы Web

Полный список (концепция):

```
PAGE · SECTION · CONTAINER · GRID · TEXT · IMAGE · BUTTON · INPUT ·
TEXTAREA · FORM · MODAL · MENU · LINK · HTML · CSS · JS
```

Русские названия в UI: Страница, Секция, Контейнер, Сетка, Текст, Изображение, Кнопка, Поле ввода, Текстовая область, Форма, Модальное окно, Меню, Ссылка, HTML, CSS, JS.

**Этап 0:** реализованы триггер-события `web.page` (Страница), `web.button` (Кнопка), `web.form` (Форма) — каждая отдаёт «Данные» (payload события). **Рендеринг собранной страницы (живое превью)** — ROADMAP этап 2: canvas → DOM-дерево (PAGE/SECTION/GRID/… + события).

## События Web

| Событие (англ.) | Событие (ru) |
|---|---|
| Page Load | Загрузка страницы |
| Button Click | Нажатие кнопки |
| Form Submit | Отправка формы |
| Input Change | Изменение поля |
| Modal Open / Modal Close | Открытие / закрытие окна |

События — это **триггеры** (то же понятие, что в Telegram): они запускают схему, затем данные текут по общей логике NODEZZLE.

## Пример

```
Форма → Отправка формы → INPUT модели → Модель → OUTPUT модели → Окно «Успешно»
```

Схема (задел):

```
web.form (→ Данные: {name, email, …})
  → data.to_object (ключи полей)
  → models.call (Order Model)
  → web.modal (показать результат)
```

## Web-события в runtime

События Web создаёт Симулятор (Debug-панель, источник «Web» + JSON-данные) и **веб-превью** (вкладка «Веб» в Debug-панели, Этап 2 подэтап I часть 2): загрузка страницы, клик по кнопке и отправка формы генерируют те же `TriggerPayload` (`source: 'web'`), поэтому схемы не меняются. Полный рендеринг собранной страницы (ответные элементы — текст, поля, окна) появится вместе с библиотекой веб-элементов (Этап 4).

## Telegram + Web — одна система

Telegram и Web — **не** две отдельные системы. Один проект может содержать:

```
Telegram Bot → WebApp URL → Telegram WebApp → HTML Page → Button Click
→ Order Model → Order Created → Telegram Message
```

Общее ядро: одна система блоков, один runtime, общий формат проекта, общие модели и переменные. Тип проекта «Telegram + Web» создаётся с Dashboard.

## Принципы

- Web-элементы используют те же INPUT/OUTPUT, что и Telegram: совместимость, конвертеры, модели — общие.
- HTML/CSS/JS-элементы (в будущем) — как блоки с типом `json`/`text` на выходе (содержимое) и событиями (триггеры).
- Превью Web-страницы — в отдельной вкладке Canvas (этап 2): страница рендерится из той же схемы (единый источник правды).
- Безопасность: пользовательский JS в `JS`-блоках — в изолированном окружении (iframe/sandbox, этап 4), секреты — только в backend (тип `secret`).


## Уточнение маршрутизации событий (0.5.32)

`payload.web.event`, когда задан, фильтрует тип триггера:
`page_load` → `web.page`, `button_click` → `web.button`,
`form_submit` → `web.form`. Загрузка превью больше не запускает кнопку.
Неизвестное явное событие не запускает ни один из этих обработчиков;
источник Telegram также не подходит. Без поля `event` сохранён общий
запуск веб-триггеров для старых схем и JSON симулятора.

Это фильтрация по **типу события**, не адресация экземпляров: несколько
кнопок одного типа пока реагируют вместе. Рендеринг/адресация отдельного
элемента не расширялись. Веб-превью и симулятор используют один runtime;
урок проверен настоящим кликом с сопоставлением выходных/входных данных.


## Адресация экземпляров в превью (0.5.38, 09A)

Ограничение 0.5.32 «все кнопки одного типа реагируют вместе» устранено
для событий превью. `fireWebTrigger(web, targetNodeId)` передаёт ID узла
отдельно от объекта данных события. Runtime сначала выбирает адресованную
точку входа активного холста, затем проверяет `matches` (тип/источник).
Клик запускает свою кнопку, submit — свою форму. Подписи могут совпадать:
они не служат адресами. Неверный ID/не-триггер дают ожидание `ERR_NO_TRIGGER`,
а не запуск всех узлов. Без targetNodeId сохраняется прежняя рассылка
подходящим триггерам — в том числе старые вызовы и JSON симулятора.

Превью по-прежнему показывает первую `web.page`; загрузка и кнопка
перезагрузки адресуют именно её. Маркер загрузки различает проект,
активную модель и ID страницы. Черновики форм относятся к текущему
контексту/монтированию превью; не сохраняются в проекте и после F5.
Форме разрешён только JSON-объект. Ошибка видна рядом с полем, кнопка
отправки недоступна; массив/примитив/null не подменяются пустым объектом.
Служебный targetNodeId не попадает в `outputs.data`; форма отдаёт values,
кнопка/страница — прежние данные события.

Проверки: 9 runtime + 9 парсера + 1 стора, 3 браузерных сценария:
две одинаковые кнопки/формы с раздельными логами, F5, ошибочные данные и
две страницы. Общий набор — **493 + 55**. Это не полноценный DOM-рендерер,
не публикация сайта по адресу рамки и не новое серверное хранилище.


## Текст и заголовок (0.5.39, 09B1)

`web.text` и `web.heading` теперь implemented/доступны. Это два листовых
элемента, не полный конструктор DOM. Они выводятся после названия первой
страницы, перед кнопками/формами, в порядке узлов; работают и без web.page.
Позиции на холсте не задают расположение элементов страницы.

- Настройки text (по умолчанию пустая строка), heading.level (по умолчанию 2).
- Вход, отличный от undefined, приоритетнее настройки; undefined означает
  отсутствие данных (runtime заполняет им также неподключённые порты).
  Пустая строка сохраняется, null/объекты/числа не преобразуются в текст.
- level — только целое число 1–6. Неверный тип/уровень даёт ERR_WEB_ELEMENT,
  а не успешный элемент. Старые узлы без настроек используют defaults.
- Выходной порт element остаётся object: `{kind:'text', text:string}` либо
  `{kind:'heading', text:string, level:number}`. Это инертные данные.
  React создаёт p/h1–h6 с текстовыми детьми; HTML, script и атрибуты из
  данных не вставляются/не выполняются. Переносы строк сохраняются.
- Без подключённых входов превью строится из настроек сразу. С проводом
  показывается только успешный выход данного узла последнего актуального
  запуска, иначе — подсказка ожидания. Во время запуска старый текст скрыт.
  Ошибку выполнения можно уточнить на вкладке «Порты»/в журнале.
- Сравнивается ключ схемы на **старте** выполнения и текущие узлы (ID,
  blockId, config), связи, проект, активная модель и определения моделей.
  Перемещение/выделение узлов активного холста не сбрасывает результат.
  Изменения определения модели консервативно инвалидируют результат целиком,
  включая её метаданные/геометрию. Undo к идентичной схеме допускает её результат.
  После F5 результат не восстанавливается из истории — нужен новый запуск.

Превью не запускает автономные вычисления и не меняет правила входа runtime:
при наличии триггера подключённый элемент должен выполняться в его цепочке;
просто соседний несвязанный источник не становится частью события страницы.
Текущий рендерер не показывает внутренности модели из внешнего холста.
Контейнеры/секции/сетки, изображения/ссылки/поля остаются planned.

Проверки: 15 новых unit/integration + 3 E2E, всего **508 + 58**.
Реальные провода и запуск, смена текста, перенос узла без сброса, F5,
HTML как строка, ошибочный уровень и исправление; 09A и все уроки сохранены.
