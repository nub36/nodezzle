# LOCAL_RUN — локальный запуск NODEZZLE (для владельца, без VPS)

**Обновлено: 2026-09-14 (подэтап 5.10).** Эта инструкция — про запуск
NODEZZLE на своём компьютере (в первую очередь Windows 10/11).
Никакого VPS, Docker и Telegram-токена не требуется.

---

## 1. Требования

| Что | Минимум | Где взять |
|---|---|---|
| Система | Windows 10/11 (также работают Linux и macOS) | — |
| Node.js | LTS, версия ≥ 20.19 | <https://nodejs.org/> (кнопка «LTS») |
| npm | идёт в комплекте с Node.js | — |
| Браузер | любой современный (Chrome, Edge, Firefox) | — |

Node.js устанавливается обычным установщиком «Далее → Далее → Готово».
После установки **откройте новое окно командной строки** — старое может
не видеть свежий `node`.

Проверка:

```bat
node -v
npm -v
```

Обе команды должны напечатать версии (например, `v22.22.3` и `10.9.7`).

## 2. Скачивание и распаковка

1. Скачайте ZIP проекта (кнопка **Code → Download ZIP** на GitHub:
   <https://github.com/nub36/nodezzle>).
2. Распакуйте архив **целиком** в любую папку, например
   `C:\nodezzle`. Внутри должен оказаться файл `start-nodezzle.bat`,
   папки `src`, `server`, `docs`, файл `package.json`.
3. Путь лучше выбирать без кириллицы и пробелов — так надёжнее.

## 3. Первый запуск (двойной клик)

1. Дважды кликните **`start-nodezzle.bat`**.
2. Скрипт проверит окружение: «Проверяем окружение…».
3. При первом запуске (папки `node_modules` нет) он напишет
   «Первый запуск. Устанавливаем зависимости…» и выполнит
   `npm install` — это занимает несколько минут.
4. Затем запустятся сервер и интерфейс; появятся строки:
   - `Сервер: работает (http://127.0.0.1:4210/api/health)`;
   - `Интерфейс: http://localhost:5173/` — браузер откроется сам.
5. Пользуйтесь. Остановка — **Ctrl+C** в окне запуска.

При повторном запуске установка зависимостей пропускается — старт
занимает несколько секунд.

## 4. Запуск вручную (без .bat)

```bat
npm install      :: один раз (и после обновления зависимостей)
npm run dev:all  :: сервер АПИ + интерфейс вместе
```

Отдельные части (редко нужны сами по себе):

```bat
npm run dev         :: только интерфейс (Vite)
npm run server:dev  :: только сервер АПИ
```

## 5. Какие процессы стартуют и какие порты заняты

| Процесс | Адрес по умолчанию | Зачем |
|---|---|---|
| Сервер АПИ (Node) | `http://127.0.0.1:4210` | аккаунты, секреты, исполнение схем, журналы |
| Интерфейс (Vite) | `http://localhost:5173` | редактор схем; запросы `/api` проксируются на сервер |

- Порт интерфейса не жёсткий: если 5173 занят, Vite сам возьмёт
  следующий свободный и напечатает фактический адрес.
- Порт сервера задаётся переменной `NODEZZLE_API_PORT` (по умолчанию 4210).
  **Порты 3000 и 3001 для NODEZZLE запрещены всегда.**
- Сервер сообщает фактический адрес при старте; проверить его можно по
  `http://127.0.0.1:4210/api/health` (ответ `{"status":"ok",…}`).
- Браузеру достаточно адреса интерфейса — ходить на порт сервера
  напрямую не нужно.

## 6. Где хранятся локальные данные

| Данные | Где |
|---|---|
| Локальная база данных (аккаунты, рабочие пространства, опубликованные проекты, секреты, журналы) | `server/data/nodezzle.db` (+ служебные `-wal`/`-shm`) |
| Черновики схем редактора | LocalStorage вашего браузера |
| Настройки окружения | `.env` (если создали; пример — `.env.example`) |

Папка `server/data/` игнорируется Git'ом и **никогда не коммитится**.
Если удалить папку `server/data`, база создастся заново при следующем
запуске: аккаунты, опубликованные проекты и журналы этого компьютера
будут потеряны, черновики в браузере останутся.

### Резервное копирование

1. Остановите NODEZZLE (Ctrl+C).
2. Скопируйте папку `server/data` в безопасное место.
3. Для восстановления верните её на место при остановленном продукте.

### Полный сброс локальных данных разработки

```bat
npm run dev:reset
```

Команда удаляет **только** `server/data/` (локальные аккаунты, проекты,
секреты, журналы). Код, документы и настройки она не трогает, никогда не
запускается автоматически и всегда спрашивает подтверждение
(введите `ДА`). Без подтверждения — `npm run dev:reset -- --yes`.

## 7. Остановка

- Нажмите **Ctrl+C** в окне запуска — лаунчер корректно завершит и
  сервер, и интерфейс; висящих процессов не остаётся (проверено).
- Если окно закрыли крестиком, а процесс чудом остался, найдите и
  завершите его в диспетчере задач (процессы `node`).
- Файлы `-wal`/`-shm` рядом с базой после остановки исчезают сами.

## 8. Обновление до новой версии

1. Скачайте новый ZIP и распакуйте поверх старой папки (или в новую).
2. Если ставите в новую папку — скопируйте туда старую `server/data`,
   чтобы сохранить локальные данные (см. раздел 6).
3. Запустите `start-nodezzle.bat`: при изменении зависимостей скрипт
   обновит их сам (шаг `npm install` в нём выполняется только при
   отсутствии `node_modules`; после обновлений при необходимости
   выполните `npm install` вручную).
4. Миграции базы применяются автоматически при старте сервера.

## 9. Секреты и переменные окружения

- Локальный запуск **не требует** файла `.env` вовсе: сервер сам
  создаёт случайный секрет сессии для разработки (в консоли честно
  печатается предупреждение об этом). Это **не продакшн-режим**.
- Реальный токен Telegram-бота для локального запуска **не нужен** —
  симулятор Телеграма работает без токена. Подключение настоящего бота
  делается через интерфейс «Секреты/Боты» и хранится только на сервере
  в зашифрованном виде.
- Пример всех переменных — `.env.example` (только фиктивные значения;
  реальные секреты в репозиторий не попадают никогда).

## 10. Типовые ошибки

| Симптом | Что делать |
|---|---|
| `«node» не является внутренней или внешней командой` | Установите Node.js LTS с <https://nodejs.org/> и откройте **новое** окно командной строки. |
| `npm не найден` / нет `npm -v` | Переустановите Node.js (npm идёт в комплекте); проверьте переменную `PATH` — в ней должен быть каталог установки Node. |
| `Порт сервера уже занят` / `EADDRINUSE` в окне запуска | Порт 4210 занят другим процессом. Найдите его: `netstat -ano \| findstr :4210` и завершите в диспетчере задач, либо задайте другой порт: `set NODEZZLE_API_PORT=4211` и запустите снова. Интерфейс сам возьмёт свободный порт. |
| `Интерфейс запустился, но АПИ-запросы не отвечают` | Сервер не поднялся — прокрутите окно запуска вверх: лаунчер печатает причину на русском («Порт занят…», «Неверные настройки окружения…», «Не найдены зависимости…»). |
| `npm install завершился ошибкой` | 1) проверьте интернет; 2) запустите `npm install` вручную и прочитайте последнюю ошибку; 3) попробуйте `npm cache verify` и повтор; 4) не отключайте антивирус без необходимости — если он блокирует файлы, добавьте папку проекта в исключения средствами самого антивируса. |
| Окно запуска сразу закрывается | Запустите через правую кнопку → «Запуск от имени администратора» не требуется; вместо этого откройте `cmd` в папке проекта и выполните `start-nodezzle.bat` вручную — окно останется открытым и покажет ошибку. |
| Миграции не применяются / база «битая» | Остановите продукт, сделайте резервную копию `server/data`, затем удалите её — база создастся заново (см. раздел 6). |

## 11. Чего здесь нет (честно)

- Это локальная среда разработки: секрет сессии временный, деплоя нет.
- Реальный вебхук Телеграма требует публичного адреса и токена — это
  серверная возможность, для локальной работы не нужна.
- Порты 3000/3001 и VPS владельца в локальном запуске не используются.
