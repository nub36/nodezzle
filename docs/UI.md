# NODEZZLE — UI и визуальный стиль

## Направления

**Premium Dark UI · Glassmorphism · Aurora Gradients · Neon Accents · Depth · Glow · Smooth Motion.**

Основные цвета: black, deep navy, deep blue, purple, cyan, electric blue. Дополнительный акцент: pink/magenta.

Основные эффекты (используются **аккуратно**): aurora gradient, blurred glow, медленно движущиеся переливы, canvas grid, noise, particles, parallax, depth.

> Правило: **читаемость Canvas и блоков важнее декоративных эффектов.** Эффекты не должны мешать работе со схемой.

## Экраны

### Главная (Landing, `/`)

1. **Hero-анимация**: отдельные светящиеся детали (Telegram, Логика, Модель, Ответ) — чистый CSS + SMIL: пунктирные «провода», светящиеся частицы (`animateMotion`) и в финале подсветка «готовой системы».
2. Заголовок **NODEZZLE** — «Не программируй. Собери.» + CTA «Начать собирать».
3. **Playground** — интерактивная демонстрация без регистрации: детали `Сообщение → Логика → Ответ`, пользователь вводит сообщение и нажимает «Запустить» — данные «текут» по соединениям, в демо-чате справа появляется ответ.
4. Возможности (6 карточек): Canvas, Модели, Telegram + Web, Живое выполнение, Умные соединения, Русский интерфейс.
5. Footer: «Не программируй. Собери.»

### Dashboard (`/dashboard`)

Проекты (карточки: тип, имя, дата изменения), создание нового проекта: **Telegram-бот · Web / HTML · Telegram + Web · Пустой проект**, кнопка «Загрузить пример: Telegram-бот», удаление (с подтверждением).

### Canvas (`/projects/:id`)

- **Toolbar**: назад, название проекта (инлайн-переименование), тип, undo/redo,
  **масштаб** (−, проценты, +, «вписать в экран»), **поиск по схеме** (неподходящие узлы
  приглушаются, счётчик «Найдено: N»), переключатель **«Черновик / Живой»** и
  **эффектов выполнения** (Этап 2, подэтап B; состояние хранится в UI-store),
  статус autosave («Сохранено …»), статус выполнения, **Запустить/Стоп**, кнопка Debug-панели.
  Примечание: семантика «Живого» режима будет дополнена вместе с публикацией
  (зафиксированная идея) — сейчас переключатель хранит режим и отображает его.
- **Библиотека деталей** (`BlockLibrary`, слева; до Этапа 2 — палитра `NodePalette`):
  - вкладки **Основные** (детали сложности `basic`), **Все** (все доступные), **Избранное**, **Недавние**, **Мои детали**, **Мои модели**;
  - поиск по названию, описанию, техническому идентификатору и ключевым словам блока (`keywords`);
  - звёздочка «Избранное» у каждой детали; последние 10 вставленных деталей — в «Недавних»;
  - категории с иконками и цветовыми точками (`CATEGORY_ICONS` / `CATEGORY_COLORS`), сворачивание;
  - «Мои модели»: модели проекта вставляются блоком «Вызов модели» с предзаполненным `modelId`;
  - «Мои детали»: раздел в подготовке — пользовательские детали появятся после «Сохранить как деталь» (Этап 2, раздел G);
  - drag & drop на Canvas или клик — вставка в центр. Метка у триггеров. Зарезервированные блоки скрыты;
  - настройки библиотеки (вкладка, избранное, недавние, свёрнутые категории) сохраняются в LocalStorage — UI-store `src/store/ui-store.ts` (persist, ключ `nodezzle-ui-v1`).
- **Узлы** (NodezzleNode): рендерятся из Block Definition; порты INPUT (слева) / OUTPUT (справа) с типами и цветами; бейдж «триггер»; строка статуса/ошибки выполнения.
  Визуальный язык портов (Этап 2, подэтап C): **форма маркера = вид порта**
  (данные — круг, событие — ромб, ошибка — квадрат), **глиф + цвет = тип данных**
  (`Т`, `#`, `✓`, `{}`, `◇`, `[]`, … — `PORT_TYPE_GLYPHS` / `PORT_TYPE_COLORS`);
  живые состояния детали: пульс при выполнении, зелёное свечение успеха,
  красное — ошибки, приглушение пропущенных, лёгкая подсветка при наведении.
- **Умные соединения**: во время перетаскивания совместимые порты подсвечиваются (`.port-compatible`), несовместимые приглушаются (`.port-incompatible`); `isValidConnection` запрещает несовместимые соединения.
- **Minimap** (цвета категорий), Controls, zoom 0.15–2.2.
- **Инспектор** (`InspectorPanel`, справа; до Этапа 2 — `ConfigPanel` только для узла) — контекстный:
  - **Деталь**: переименование, параметры (из `defaults`), технический ID, результат последнего выполнения (входы/выходы, время, ошибка); для «Вызов модели» — контракт выбранной модели (входы/выходы/ошибки, версия);
  - **Соединение**: порты и типы с двух сторон, последнее значение по связи, удаление (входит в историю undo/redo);
  - **Холст** (ничего не выбрано): свойства проекта, формат, счётчики, переменные;
  - веб-элементы инспектируются инспектором детали (их свойства — конфигурация), без дублирования панели.
- **Спуск внутрь модели — Drill Down (Этап 2, подэтап H)**: двойной клик по детали
  «Вызов модели» открывает её внутренний холст; над схемой появляются хлебные
  крошки `Проект › Модели › Название` (клик «Проект» — возврат). Правки
  внутренней схемы сохраняются в модель (автосохранение учитывает активный
  уровень); история правок при переходе между уровнями очищается.
- **Контекстное меню (Этап 2, подэтап F)**: правый клик по детали — дублировать,
  копировать, отключить связи, удалить, «следовать по связи» вперёд/назад,
  добавить заметку; правый клик по холсту — добавить заметку.
- **Режим фокуса** (кнопка 🎯 в тулбаре): приглушает всё, кроме выбранной детали
  и её непосредственных связей.
- **Стикеры-заметки**: служебная деталь `note.sticky` — комментарий на схеме,
  не участвует в выполнении; текст редактируется прямо на стикере.
- **Быстрая вставка (Этап 2, подэтап D)**: на пустой схеме — панель стартовых
  деталей (триггеры Telegram, триггеры Web, базовые значения); если соединение
  отпущено на пустом месте — меню только совместимых деталей, выбор создаёт
  деталь и автоматически подключает её к исходному порту (`QuickInsert.tsx`,
  `quickInsertCandidates`).
- Клавиатура: `Ctrl+Z`/`Ctrl+Shift+Z` (undo/redo), `Ctrl+D` (дублировать), `Ctrl+C`/`Ctrl+V` (копировать/вставить), `Delete` (удалить).

### Debug-панель (низ Canvas)

Вкладки:
- **Симулятор** — payload запуска (Telegram: текст/команда/userId/chatId; Web: JSON).
- **Чат Telegram** — outbox: входящее эхо + отправленные схемы-сообщения.
- **Телефон** — предпросмотр телефона с Telegram (Этап 2, подэтап I ч. 1): рамка телефона,
  шапка бота, пузыри сообщений (входящее пользователя + ответы бота, фото — плейсхолдер).
  Это превью симуляции; реальный транспорт — в следующих этапах дорожной карты.
- **Веб** — предпросмотр веб-страницы (Этап 2, подэтап I ч. 2): окно браузера,
  собранное из веб-деталей схемы; загрузка страницы, клики по кнопкам и отправка
  форм запускают схему веб-событиями (`source: 'web'`).
- **Порты** — значения входов/выходов каждой детали после последнего запуска
  (статус, длительность) — Этап 2, подэтап I ч. 2.
- **Журнал** — LOG (уровни info/warn/error, время, JSON-данные).
- **История** — execution history (статус, длительность, ошибка).

## Живое выполнение (визуальные состояния)

```
IDLE → WAITING → RUNNING → SUCCESS | ERROR | STOPPED
```

| Состояние | Визуал |
|---|---|
| RUNNING | неоновый пульс узла (`.status-running`) |
| SUCCESS | мягкая зелёная подсветка (`.status-success`) |
| ERROR | красная подсветка + строка ошибки (`.status-error`) |
| SKIPPED | приглушённый узел (триггер не сработал) |
| данные в движении | анимация рёбер (`.animated`) + цвет по типу порта |

## i18n

- Основная (и единственная на MVP) локаль — **ru-RU** (`src/i18n/locales/ru.json`).
- Все строки UI, кнопки, меню, ошибки, уведомления, онбординг, Dashboard, Canvas, библиотека деталей, названия/описания блоков, подсказки, Debug UI — через i18n-ключи.
- Технические идентификаторы (ID, имена полей, типы TS) — английские и не переводятся.
- Структура ключей: `app.*`, `common.*`, `landing.*`, `dashboard.*`, `canvas.*`, `execution.*`, `errors.*`, `portTypes.*`, `categories.*`, `blocks.*`.
- Добавление языка: новый файл `src/i18n/locales/<lang>.json` + выбор локали (UI выбора — в планах).

## Компактная подача (0.5.29)

- **Деталь на холсте**: фиксированная ширина 240 px, заголовок с меньшими
  отступами, триггер отмечен ⚡ с подсказкой. INPUT и OUTPUT расположены
  двумя независимыми колонками: высота определяется большей из них,
  а не суммой числа портов. Строка — 24 px, маркер — прежние 13 px.
- Тип показывается цветным глифом без повторения длинного названия.
  Полное имя и тип доступны в `title` подписи/маркера и `aria-label` маркера.
  Длинная подпись сокращается многоточием; ни один порт не скрывается.
- Маркеры позиционируются относительно **своей строки**: раньше несколько
  абсолютных маркеров могли накладываться в центре узла.
- Начальное автовписывание ограничено 100%, чтобы первая деталь не
  увеличивалась до 220%. Ручное масштабирование 0.15–2.2 сохранено.
- **Академия**: разделы в двух колонках от 768 px, на узком экране — в одной;
  компактные карточки с кратким результатом урока. На странице урока
  запуск расположен перед планом, шаги раскрываются через `details/summary`.
- **Учебная карточка**: 304 px, ограничена высотой окна и прокручивается.
  Кнопка «−/+» сворачивает тело без остановки урока. На следующем шаге тело
  раскрывается, дополнительная теория снова закрыта. При цели `inspector`
  карточка сдвигается влево (проверено E2E на 1440 px), чтобы не закрывать
  нужные настройки. Это не полная мобильная адаптация редактора: отдельно
  проверены Академия и теоретический урок на 390×640.

### Практические шаги отладки (0.5.30)

В уроках конвертеров и эхо-бота просмотр результата ждёт конкретную вкладку
(«Порты» / «Чат Telegram»), а не любую открытую панель. Автопереключение
для этих шагов выключено. Подсветка указывает на соответствующую кнопку
вкладки, а при закрытой панели — на кнопку 🐞. Выбранная вкладка помечена
`aria-pressed`. Инструкции остаются короткими; компактная раскладка не менялась.


### Условия и команды в обучении (0.5.31)

Краткие инструкции совпадают с полями инспектора: выходы «Да»/«Нет»,
«Сравнивать с», «Команда». Условие требует нужную ветку и лог, команда —
/start и отправленный ответ, а не только успешный статус схемы. Для
команды просмотр результата ждёт вкладку «Чат Telegram» без автоперехода.
Готовая настройка /start принимается без искусственного редактирования.
Поле команды в симуляторе отделено от текста сообщения; это явно сказано
в уроке. Габариты деталей и учебных карточек не увеличены.


### Практика веба, моделей и отладки (0.5.32)

Выделение нескольких деталей для модели объяснено через Ctrl (Mac — Cmd),
а не Shift. В уроке показаны пустой контракт и ожидаемый результат `{}`.
Веб-инструкция предлагает JSON события или клик в превью. В отладке
журнал, порты и история проверяются как три отдельных действия, без
автопереключения и кнопки подтверждения вместо просмотра. Локальная
история не сохраняется после F5 — инструкция отделяет её от серверной.
Компактные размеры деталей, карточек и панелей не менялись.


### Первая цепочка и вводные уроки (0.5.33)

Первая цепочка требует реальную передачу текста в лог и отдельно ждёт
вкладку «Журнал», не завершаясь при любой открытой панели. Подсказка
объясняет, где задать текст симулятора и какую связь проверить. В уроке
портов используется название «ID чата», совпадающее с интерфейсом.
Знакомство и публикация проходят без редактора и не изменяют рабочие
проекты. Компактная раскладка и способы взаимодействия сохранены.
