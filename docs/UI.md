# NODEZZLE — UI и визуальный стиль

## Направления

**Premium Dark UI · Glassmorphism · Aurora Gradients · Neon Accents · Depth · Glow · Smooth Motion.**

Основные цвета: black, deep navy, deep blue, purple, cyan, electric blue. Дополнительный акцент: pink/magenta.

Основные эффекты (используются **аккуратно**): aurora gradient, blurred glow, медленно движущиеся переливы, canvas grid, noise, particles, parallax, depth.

> Правило: **читаемость Canvas и блоков важнее декоративных эффектов.** Эффекты не должны мешать работе со схемой.

## Экраны

### Главная (Landing, `/`)

1. **Hero-анимация**: отдельные светящиеся детали (Telegram, Логика, Модель, Ответ) — чистый CSS + SMIL: пунктирные «провода», светящиеся частицы (`animateMotion`) и в финале подсветка «готовой системы».
2. Заголовок **NODEZZLE** — «Не программируй. Собери.» + CTA «Начать собирать».
3. **Playground** — интерактивная демонстрация без регистрации: детали `Сообщение → Логика → Ответ`, пользователь вводит сообщение и нажимает «Запустить» — данные «текут» по соединениям, в демо-чате справа появляется ответ.
4. Возможности (6 карточек): Canvas, Модели, Telegram + Web, Живое выполнение, Умные соединения, Русский интерфейс.
5. Footer: «Не программируй. Собери.»

### Dashboard (`/dashboard`)

Проекты (карточки: тип, имя, дата изменения), создание нового проекта: **Telegram-бот · Web / HTML · Telegram + Web · Пустой проект**, кнопка «Загрузить пример: Telegram-бот», удаление (с подтверждением).

### Canvas (`/projects/:id`)

- **Toolbar**: назад, название проекта (инлайн-переименование), тип, undo/redo,
  **масштаб** (−, проценты, +, «вписать в экран»), **поиск по схеме** (неподходящие узлы
  приглушаются, счётчик «Найдено: N»), переключатель **«Черновик / Живой»** и
  **эффектов выполнения** (Этап 2, подэтап B; состояние хранится в UI-store),
  статус autosave («Сохранено …»), статус выполнения, **Запустить/Стоп**, кнопка Debug-панели.
  Примечание: семантика «Живого» режима будет дополнена вместе с публикацией
  (зафиксированная идея) — сейчас переключатель хранит режим и отображает его.
- **Библиотека деталей** (`BlockLibrary`, слева; до Этапа 2 — палитра `NodePalette`):
  - вкладки **Основные** (детали сложности `basic`), **Все** (все доступные), **Избранное**, **Недавние**, **Мои детали**, **Мои модели**;
  - поиск по названию, описанию, техническому идентификатору и ключевым словам блока (`keywords`);
  - звёздочка «Избранное» у каждой детали; последние 10 вставленных деталей — в «Недавних»;
  - укрупнённые группы Telegram / Веб-страница / Данные и преобразования; исходные категории реестра не меняются. При первом открытии группы закрыты; поиск временно раскрывает найденное даже среди расширенных деталей. В уроке библиотека раскрыта временно; обычная настройка не перезаписывается;
  - «Мои модели»: модели проекта вставляются блоком «Вызов модели» с предзаполненным `modelId`;
  - «Мои детали»: раздел в подготовке — пользовательские детали появятся после «Сохранить как деталь» (Этап 2, раздел G);
  - drag & drop на Canvas или клик — вставка на свободное место (0.5.34). Метка у триггеров. Зарезервированные блоки скрыты;
  - настройки библиотеки (вкладка, избранное, недавние, свёрнутые категории) сохраняются в LocalStorage — UI-store `src/store/ui-store.ts` (persist, ключ `nodezzle-ui-v1`).
- **Узлы** (NodezzleNode): рендерятся из Block Definition; порты INPUT (слева) / OUTPUT (справа) с типами и цветами; бейдж «триггер»; строка статуса/ошибки выполнения.
  Визуальный язык портов (Этап 2, подэтап C): **форма маркера = вид порта**
  (данные — круг, событие — ромб, ошибка — квадрат), **глиф + цвет = тип данных**
  (`Т`, `#`, `✓`, `{}`, `◇`, `[]`, … — `PORT_TYPE_GLYPHS` / `PORT_TYPE_COLORS`);
  живые состояния детали: пульс при выполнении, зелёное свечение успеха,
  красное — ошибки, приглушение пропущенных, лёгкая подсветка при наведении.
- **Умные соединения**: во время перетаскивания совместимые порты подсвечиваются (`.port-compatible`), несовместимые приглушаются (`.port-incompatible`); `isValidConnection` запрещает несовместимые соединения.
- **Minimap** (цвета категорий), Controls, zoom 0.15–2.2.
- **Инспектор** (`InspectorPanel`, справа; до Этапа 2 — `ConfigPanel` только для узла) — контекстный:
  - **Деталь**: переименование, параметры (из `defaults`), технический ID, результат последнего выполнения (входы/выходы, время, ошибка); для «Вызов модели» — контракт выбранной модели (входы/выходы/ошибки, версия);
  - **Соединение**: порты и типы с двух сторон, последнее значение по связи, удаление (входит в историю undo/redo);
  - **Холст** (ничего не выбрано): свойства проекта, формат, счётчики, переменные;
  - веб-элементы инспектируются инспектором детали (их свойства — конфигурация), без дублирования панели.
- **Спуск внутрь модели — Drill Down (Этап 2, подэтап H)**: двойной клик по детали
  «Вызов модели» открывает её внутренний холст; над схемой появляются хлебные
  крошки `Проект › Модели › Название` (клик «Проект» — возврат). Правки
  внутренней схемы сохраняются в модель (автосохранение учитывает активный
  уровень); история правок при переходе между уровнями очищается.
- **Контекстное меню (Этап 2, подэтап F)**: правый клик по детали — дублировать,
  копировать, отключить связи, удалить, «следовать по связи» вперёд/назад,
  добавить заметку; правый клик по холсту — добавить заметку.
- **Режим фокуса** (кнопка 🎯 в тулбаре): приглушает всё, кроме выбранной детали
  и её непосредственных связей.
- **Стикеры-заметки**: служебная деталь `note.sticky` — комментарий на схеме,
  не участвует в выполнении; текст редактируется прямо на стикере.
- **Быстрая вставка (Этап 2, подэтап D; обновлена в 11)**: пустая схема —
  компактное «С чего начнём?» с тремя действиями. Telegram добавляет начало,
  Web — текст; пустой старт только открывает библиотеку. После первой детали
  карточка исчезает. Когда соединение от порта
  отпущено на пустом месте — меню только совместимых деталей, выбор создаёт
  деталь и автоматически подключает её к исходному порту (`QuickInsert.tsx`,
  `quickInsertCandidates`).
- Клавиатура: `Ctrl+Z`/`Ctrl+Shift+Z` (undo/redo), `Ctrl+D` (дублировать), `Ctrl+C`/`Ctrl+V` (копировать/вставить), `Delete` (удалить).

### Debug-панель (низ Canvas)

Вкладки:
- **Симулятор** — payload запуска (Telegram: текст/команда/userId/chatId; Web: JSON).
- **Чат Telegram** — outbox: входящее эхо + отправленные схемы-сообщения.
- **Телефон** — предпросмотр телефона с Telegram (Этап 2, подэтап I ч. 1): рамка телефона,
  шапка бота, пузыри сообщений (входящее пользователя + ответы бота, фото — плейсхолдер).
  Это превью симуляции; реальный транспорт — в следующих этапах дорожной карты.
- **Веб** — предпросмотр веб-страницы (Этап 2, подэтап I ч. 2): окно браузера,
  собранное из веб-деталей схемы; загрузка страницы, клики по кнопкам и отправка
  форм запускают схему веб-событиями (`source: 'web'`).
- **Порты** — значения входов/выходов каждой детали после последнего запуска
  (статус, длительность) — Этап 2, подэтап I ч. 2.
- **Журнал** — LOG (уровни info/warn/error, время, JSON-данные).
- **История** — execution history (статус, длительность, ошибка).

## Живое выполнение (визуальные состояния)

```
IDLE → WAITING → RUNNING → SUCCESS | ERROR | STOPPED
```

| Состояние | Визуал |
|---|---|
| RUNNING | неоновый пульс узла (`.status-running`) |
| SUCCESS | мягкая зелёная подсветка (`.status-success`) |
| ERROR | красная подсветка + строка ошибки (`.status-error`) |
| SKIPPED | приглушённый узел (триггер не сработал) |
| данные в движении | анимация рёбер (`.animated`) + цвет по типу порта |

## Компактная подача (0.5.29)

- **Деталь на холсте**: фиксированная ширина 240 px, заголовок с меньшими
  отступами, триггер отмечен ⚡ с подсказкой. INPUT и OUTPUT расположены
  двумя независимыми колонками: высота определяется большей из них,
  а не суммой числа портов. Строка — 24 px, маркер — прежние 13 px.
- Тип показывается цветным глифом без повторения длинного названия.
  Полное имя и тип доступны в `title` подписи/маркера и `aria-label` маркера.
  Длинная подпись сокращается многоточием; ни один порт не скрывается.
- Маркеры позиционируются относительно **своей строки**: раньше несколько
  абсолютных маркеров могли накладываться в центре узла.
- Начальное автовписывание ограничено 100%, чтобы первая деталь не
  увеличивалась до 220%. Ручное масштабирование 0.15–2.2 сохранено.
- **Академия**: разделы в двух колонках от 768 px, на узком экране — в одной;
  компактные карточки с кратким результатом урока. На странице урока
  запуск расположен перед планом, шаги раскрываются через `details/summary`.
- **Учебная карточка**: 304 px, ограничена высотой окна и прокручивается.
  Кнопка «−/+» сворачивает тело без остановки урока. На следующем шаге тело
  раскрывается, дополнительная теория снова закрыта. При цели `inspector`
  карточка сдвигается влево (проверено E2E на 1440 px), чтобы не закрывать
  нужные настройки. Это не полная мобильная адаптация редактора: отдельно
  проверены Академия и теоретический урок на 390×640.

### Практические шаги отладки (0.5.30)

В уроках конвертеров и эхо-бота просмотр результата ждёт конкретную вкладку
(«Порты» / «Чат Telegram»), а не любую открытую панель. Автопереключение
для этих шагов выключено. Подсветка указывает на соответствующую кнопку
вкладки, а при закрытой панели — на кнопку 🐞. Выбранная вкладка помечена
`aria-pressed`. Инструкции остаются короткими; компактная раскладка не менялась.


### Условия и команды в обучении (0.5.31)

Краткие инструкции совпадают с полями инспектора: выходы «Да»/«Нет»,
«Сравнивать с», «Команда». Условие требует нужную ветку и лог, команда —
/start и отправленный ответ, а не только успешный статус схемы. Для
команды просмотр результата ждёт вкладку «Чат Telegram» без автоперехода.
Готовая настройка /start принимается без искусственного редактирования.
Поле команды в симуляторе отделено от текста сообщения; это явно сказано
в уроке. Габариты деталей и учебных карточек не увеличены.


### Практика веба, моделей и отладки (0.5.32)

Выделение нескольких деталей для модели объяснено через Ctrl (Mac — Cmd),
а не Shift. В уроке показаны пустой контракт и ожидаемый результат `{}`.
Веб-инструкция предлагает JSON события или клик в превью. В отладке
журнал, порты и история проверяются как три отдельных действия, без
автопереключения и кнопки подтверждения вместо просмотра. Локальная
история не сохраняется после F5 — инструкция отделяет её от серверной.
Компактные размеры деталей, карточек и панелей не менялись.


### Первая цепочка и вводные уроки (0.5.33)

Первая цепочка требует реальную передачу текста в лог и отдельно ждёт
вкладку «Журнал», не завершаясь при любой открытой панели. Подсказка
объясняет, где задать текст симулятора и какую связь проверить. В уроке
портов используется название «ID чата», совпадающее с интерфейсом.
Знакомство и публикация проходят без редактора и не изменяют рабочие
проекты. Компактная раскладка и способы взаимодействия сохранены.


## Вставка без наложений (0.5.34, 07C)

Клик в библиотеке и стартовая вставка ищут место ближе к центру области
между библиотекой и инспектором. Перетаскивание и меню от порта ищут его
рядом с заданной точкой. Координаты передаются в `screenToFlowPosition`
как абсолютные экранные, без повторного вычитания смещения Canvas.

- Геометрия: `src/lib/node-placement.ts`. Прямоугольники
  старых узлов берутся из React Flow; до измерения используются ширина
  240 и консервативная высота `56 + 24 × max(INPUT, OUTPUT, 1)`.
  Стикеры учитываются как препятствия с отдельной оценкой 210×90.
- Зазор — 24 единицы холста. Проверяются свободные горизонтальные полосы
  у границ препятствий и проекция желаемой точки; в полосах объединяются
  занятые интервалы X. Возвращается ближайшая допустимая целая позиция.
  Целочисленность соответствует существующему округлению сохранения v1.
- Видимая область вычисляется по актуальному DOM панелей и масштабу;
  снизу отладка уже исключена размером Canvas. Есть экранный отступ 16 px.
- Если в области нет места, деталь размещается справа от всей схемы.
  Камера показывает новую деталь; для слишком большой детали может
  уменьшить масштаб, но не ниже 0.15. Координаты старых узлов неизменны.
- Общий путь вставки сохраняет конфигурацию, обычный undo/redo и autosave.
  Быстрая вставка сохраняет выбранные порты автоматического соединения.

**Границы:** это не автоматическая раскладка всей схемы. Ручной drag,
отдельная команда создания заметки не изменены. Дублирование и буфер
добавлены в 08A (см. ниже). Уже имеющиеся наложения не исправляются. Если узел впоследствии
вырастет из-за ошибки/контента, старые детали не раздвигаются автоматически.
На узком экране, целиком перекрытом панелями, гарантировать видимость между
ними нельзя — это отдельная задача мобильной адаптации. Всплывающие
карточки/диалоги и прозрачные рамки групп не считаются препятствиями.


## Копирование и дублирование фрагментов (0.5.35, 08A)

`Ctrl/Cmd+D` ищет свободное место рядом с исходным фрагментом,
`Ctrl/Cmd+V` — ближе к центру доступного Canvas. Поиск и показ камерой
используют ту же область между панелями, что и одиночная вставка.
Весь фрагмент рассматривается как один прямоугольник: одинаковое смещение
для всех узлов сохраняет взаимную раскладку. Пустоты внутри прямоугольника
тоже резервируются — намеренно консервативно, без уплотнения схемы.

Копируются настройки, подписи и только внутренние связи с исходными
портами; все ID новые. Буфер — независимый снимок в памяти вкладки, не
системный буфер и не постоянное хранилище. После F5 вставленная схема
сохраняется, сам буфер — нет. Пустое выделение не стирает предыдущую копию.
Одна вставка — один шаг undo/redo и автосохранение; выделены новые узлы.
Правый клик по участнику выделения сохраняет фрагмент, по другому узлу —
выбирает его одного. Ctrl/Cmd в полях ввода обрабатывает браузер, не Canvas.

**Границы:** рамки групп и определения моделей не клонируются; `modelId`
остаётся ссылкой, поэтому перенос вызова модели в другой проект не
импортирует её определение. Старые наложения внутри фрагмента сохраняются.
Фрагмент не растягивается и не округляется поузлово при вставке: формат v1
по-прежнему округляет дробные позиции при сохранении (погрешность до 0.5
единицы на координату). Огромный фрагмент может не поместиться даже при
минимальном масштабе 0.15; камера центрирует его. Панели, полностью
перекрывающие узкий экран, — отдельный подэтап 08B, пока не реализованный.


## Перемещаемое окно урока (0.5.36, поправки перед 08B)

Заголовок с ⠿ — ручка перемещения мышью/указателем; в фокусе работают
стрелки (16 px), Shift+стрелки (48 px), Home и кнопка ↺ (исходная позиция).
Окно и экран завершения ограничиваются границами браузера, изменение
высоты текста/сворачивание и resize пересчитывают границы. Положение
сохраняется в sessionStorage текущей вкладки, не в проекте/прогрессе.
До ручного перемещения прежнее позиционирование по цели шага сохранено.

При активном протягивании соединения карточка временно пропускает события:
можно попасть во вход под ней, но не начать новый жест из-под карточки —
сначала передвиньте или сверните её. Обычные клики по тексту/кнопкам окна
остаются интерактивными; содержимое не служит ручкой перемещения.
Подсветка не блокирует редактор, внешнее затемнение теперь 35% вместо 70%.

Ручная проверка сообщает, что условие ещё не выполнено; для connect
называет точные выход/вход и обе детали. Правила автоматического зачёта
сохранены: неверный порт не засчитывается, правильный переводит дальше.
Escape у быстрой вставки и контекстного меню закрывает только меню;
повторное нажатие без меню вызывает обычное подтверждение прерывания урока.
Это исправление окон обучения, не полная адаптация Canvas к мобильным
экранам — задача панелей 08B остаётся следующей.


## Адаптивные панели Canvas (0.5.37, 08B)

При ширине окна <1024 px библиотека и инспектор становятся переключаемыми
немодальными панелями. «Детали» / «Свойства» открывают одну панель,
«Холст» закрывает обе; повторное нажатие текущей кнопки тоже закрывает её.
Поля скрытой панели исключены из Tab через `hidden`. Открытие фокусирует
поле, Escape/крестик инспектора возвращают фокус на кнопку; меню/модальный
диалог имеют приоритет Escape. Отладка при входе на узкий экран закрыта,
открывается кнопкой 🐞, содержимое ограничено `min(190px, 28dvh)`, вкладки
доступны горизонтальной прокруткой. Миникарта скрыта, Controls сохранены.

Вставка закрывает панель, фокусирует «Холст» и считает свободную область
без перекрывающей панели. Это касается библиотеки, drop/Quick Insert и
фрагментов 08A. При расширении до >=1024 px возвращаются обе постоянные
панели, координаты узлов не меняются. Состояние панели временное, не входит
в persist или документ; поиск и настройки остаются в существующем UI-store.

Тулбар ниже 1280 px переносит кнопки на строки, дополнительные инструменты
доступны через «Инструменты». Поиск, масштаб, режим и эффекты не удалены.
Карточка урока по умолчанию снизу (максимум 38dvh), не закрывает верхние
переключатели; ручное перемещение имеет приоритет. Для скрытой панели
подсвечивается кнопка её открытия — ученик сам открывает нужную панель.

**Проверено:** 390×800, 768×800, переход к 1440×900, поля/клавиатура/F5/
запуск, один полный урок на 390 px и регрессия всех 12 уроков на настольном
размере. Это закрывает подэтап панелей 08B, но не доказывает сенсорные
соединения, весь курс на телефоне, экранную клавиатуру и все ориентации.
Маленькое окно с открытой панелью всё ещё частично перекрывает схему —
кнопка «Холст» освобождает её полностью.


## Web-превью: отдельные события кнопок и форм (09A, 0.5.38)

Клик/submit адресуется ID выбранного элемента, а не всем узлам того же
типа. Одинаковые подписи разрешены. Превью показывает первую страницу,
её загрузка/перезагрузка тоже адресные. Черновики форм независимы внутри
превью, сбрасываются при смене проекта/модели и после закрытия вкладки
превью/F5. Неверный JSON или не-объект показывают ошибку и блокируют submit;
поля получили доступные подписи. Данные корректного объекта не меняются.
Рамка браузера — локальная симуляция, не публикация реального сайта.


## Web-текст и заголовок (09B1)

Инспектор показывает настройки «Текст» и «Уровень заголовка (1–6)».
В превью отображаются p/h1–h6 с переносами строк, без исполнения HTML.
Без связей настройка видна сразу; с проводом нужен актуальный успешный
результат узла. Ожидание/неверная настройка обозначены текстовой подсказкой
role=status. Существующие кнопки/формы и адресация 09A не изменены.
Это плоский слой, не контейнерная вёрстка. Подробнее — WEB.md.


## Контейнеры/секции/сетки Web (09B2)

В режиме библиотеки «Все» доступны три структурные детали. Инспектор
показывает заголовок секции и колонки сетки (1–6); children подключается
массивом, не редактируется как строка в инспекторе. Превью рендерит вложенные
div/section/Grid только после проверки дерева; пустая структура объяснена
подсказкой. Корни выбираются по зависимостям children, чтобы не дублировать
дочерний текст снаружи. Ошибка дерева/цикл имеют текстовую обратную связь.
Кнопки/формы/страница пока остаются отдельным слоем. WEB.md содержит практику.


## Изображения/ссылки в Web-превью (09B3)

Инспектор даёт адрес и подпись. Некорректный URL показывает подсказку вместо
img/a. Картинка требует нажатия «Загрузить изображение», показывает адрес,
предупреждение о внешнем запросе, текстовую подпись/alt, загрузку и повтор
после ошибки. Запрос не отправляет referrer; IP внешнему источнику виден.
Ссылка открывает новую вкладку, в title виден полный адрес; скринридер
получает уведомление о новой вкладке. Свежесть и корни — правила 09B1/B2.
Подробные ограничения, в том числе DNS/редиректы, — WEB.md/SECURITY.md.


## Поля и формы Web (09B4)

Инспектор формы показывает явный переключатель JSON/Поля. У input/textarea
есть имя данных, список экземпляров формы, подпись/подсказка и начальное
значение. Список имеет локализованное доступное имя; одинаковые формы
различаются номером. Подпись поля не использует старую подпись «в журнале».

Контролы могут находиться вне DOM формы, связываясь стандартным form-атрибутом.
Нет подходящей формы в режиме fields — контрол отключён с пояснением.
Дубли/лимиты/неполная готовность запрещают submit с видимой ошибкой.
JSON UI 09A сохранён. Черновики не сохраняются при F5/размонтировании;
пошаговая практика и точные границы — WEB.md.


## Информационное окно Web (09B5)

Компактная кнопка открытия, в инспекторе «Заголовок окна». Нативный dialog
поверх рамки превью; заголовок даёт доступное имя, пробельный заменяется
названием блока. Фокус сначала на закрытии, Tab/Shift+Tab внутри, Escape
закрывает только окно, а не панели Canvas. Изоляция клавиш защищает фоновые
узлы. При удалении активной кнопки загрузки фокус возвращается к закрытию.
Фон не закрывает окно, после закрытия фокус возвращается к живой кнопке
открытия. На 390 px окно помещается в экран, содержимое прокручивается.
Дети только при открытии, согласие на картинки сбрасывается. Подпись прямо
говорит, что открытие/закрытие не запускает схему. Практика — WEB.md.


## Telegram callback в симуляторе (09C1)

Компактный выбор «Событие Telegram»: сообщение/команда либо нажатие
inline-кнопки. Callback показывает ID запроса, данные и ID сообщения;
прежние ID чата/пользователя общие. Неверные данные сопровождаются подсказкой,
callback не исполняется. В настройках триггера — точный фильтр данных;
в ответе — текст и настоящий checkbox «Показать окно Telegram».
Чат и Телефон показывают отдельное уведомление, не пузырь сообщения и
не реальное окно Telegram. Пустой ответ виден как подтверждение без текста.
F5 сбрасывает режим/поля симулятора; текущие уроки при входе восстанавливают
режим сообщения. Пошаговая практика — TELEGRAM.md. Кнопок клавиатуры ещё нет.


## Inline-клавиатура Telegram (09C2)

В инспекторе конструктора — компактное многострочное поле «Ряды кнопок (JSON)»
с явным доступным именем. В Чате/Телефоне под текстовым сообщением выводятся
одинаковые контролы рядов/кнопок: настоящий button, перенос длинной подписи,
клавиатурный Enter и пометка симуляции. Подпись не исполняется как HTML.
Кнопки неактуальной/неуспешной схемы или с неверным userId отключены с
пояснением. Нажатие заменяет результаты, а не сохраняет переписку; для
следующей пробы снова отправьте сообщение. Урок «Порты» объясняет третий
необязательный вход отправки, не требует клавиатуры для старой практики.

### Серверные копии в Dashboard (10A, 0.5.46)

Компактный отдельный раздел после локальных проектов/песочниц: аккаунт,
выбор пространства, локального источника, список серверных документов.
Успешное восстановление предлагает явную ссылку в локальный Canvas. Все
строки русские через serverProjects.*, длинные имена переносятся; форма
и кнопки проверены при 390 px. Действия заблокированы во время запроса.

Рядом постоянно написано: ручные копии — не синхронизация/публикация;
локальные данные общие для браузера и выход их не удаляет. Ошибка не
заменяется успехом, серверный технический message не показывается. При
неподтверждённом POST новый запрещён до обновления списка. Подробности
переноса — раскрываемая практика, без модального окна поверх Canvas.

Учебные карточки/прогресс и локальное создание работают без API/аккаунта.
Для переноса песочницу сначала явно преобразуют в обычный проект. После
смены аккаунта панели подключения бота и аудита загружаются заново;
10A не добавляет выбор LIVE или перепривязку бота к серверной копии.

### Серверный Canvas (10B2/C, 0.5.48)

В серверной карточке Dashboard добавлена отдельная кнопка **«Открыть на
сервере»**. Она ведёт на `/server-projects/:id`, не создаёт локальную копию.
Сверху Canvas — компактная полоса с явным режимом и состоянием сохранения.
Локальная подпись Toolbar скрыта только в этом режиме. «Запустить» остаётся
симулятором; сохранение не публикует LIVE.

Состояния: есть правки / сохраняем на сервер / сохранено на сервере /
автосохранение приостановлено. При паузе — понятная причина, «Проверить
сервер» (чтение) и «Сохранить локальную копию». После чтения показана сводка
просмотренного документа (имя/дата/число деталей/моделей) и явный выбор:
принять его либо заменить своими правками с подтверждением. Автомерджа нет.

При повторном открытии несовпадающие резервные черновики предлагаются
отдельным экраном. Восстановление не отправляет данные само; старый резерв
можно удалить явно. Недоступный проект не мешает экспортировать резерв
подтверждённого аккаунта в обычную локальную копию. Квота отображается
отдельным предупреждением; уход с неподтверждёнными данными можно отменить.

Полоса имеет ограничение высоты и прокрутку, перенос кнопок; проверена при
390 px. Встроенная помощь объясняет режим/сбой/закрытие, полная практика —
SERVER_PROJECTS_GUIDE.md. Уроки продолжают работать без аккаунта и API.


### Первый путь без документации (11, 0.5.49)

- «Детали / Свойства / Только схема» доступны на всех размерах. На широком
  экране панели сворачиваются независимо; на узком сохранены немодальные
  панели, Escape и возврат фокуса. Свёрнутая панель не занимает место при
  расчёте вставки. Выделение/координаты от переключения не теряются.
- Компактный старт в режиме новичка освобождает схему от боковых панелей.
  Путь Telegram: «Получено сообщение» → добавить ответ → передать текст и
  номер получателя → «Запустить» → тестовый чат. Web: текст → показать на
  странице → связь → запуск → настоящее веб-превью. Новая деталь ставится
  справа от начала, насколько позволяет свободное место. При раскрытии
  результата в свободной рабочей области первые детали вписываются в экран.
- Полоса «Начало / Действие / Проверка / Готово» выводится из текущих деталей,
  связей и результата существующего выполнения, без отдельного сохранённого
  «достижения». «Готово! Схема работает» требует успешного результата действия
  и совпадения executionGraphKey. Правка схемы/undo/ошибка снимают успех;
  обычное перемещение детали не делает результат устаревшим. Подсказка
  ограничена первым простым сценарием; сложные схемы и модели ей не блокируются.
- Нижняя панель изначально закрыта. Первый запуск раскрывает чат / Web /
  симулятор по деталям схемы; открытая пользователем вкладка сохраняется.
  Порты, журнал, история, телефон остаются доступны. Урок управляет своими
  целями; на шаге запуска раскрывается панель без замены выбранной вкладки.
- Технические инструменты Toolbar раскрываются кнопкой; «Расширенный вид»
  отключает новичковые подсказки. Русские названия/tooltip, одинаковая минимальная
  область 36×36, состояния нажатия/фокуса/недоступности; badge не переносится.
  Технический ID детали — в раскрываемых сведениях, пустой нулевой сводки нет.
- Использованы прежние эффекты full/reduced/off и короткая обратная связь
  соединений. Нет конфетти, нового FX-движка или повторяющихся popup.
- UI-store v3 мигрирует свёрнутые категории в группы: если хотя бы одна старая
  категория группы была открыта, группа остаётся открытой. Избранное, недавние,
  модели, настройки эффектов и формат проекта v1 сохранены.

**Граница проверки:** кнопка «Запустить» в редакторе проверяет настоящую схему
на тестовом сообщении через существующий движок, не отправляет сообщения
в боевой Telegram. Интерфейс сообщает об этом явно. Подключение бота и
публикация страницы — отдельные действия; этот проход их не имитирует.

### Запрос владельца: заполненная верхняя часть сайта (перед 12A)

Добавить целостную шапку с логотипом, основной навигацией, быстрыми переходами
к уже работающим панелям и видимыми точками входа в запланированные разделы.
Работающие функции не дублировать. Подготовленные экраны/кнопки обозначать
«В разработке»; они не выполняют фиктивные операции и не создают реальные данные.
На узком экране — доступное меню, без горизонтального переполнения. В редакторе
навигация компактна и не вытесняет схему. После дизайна — продолжить 12A.
