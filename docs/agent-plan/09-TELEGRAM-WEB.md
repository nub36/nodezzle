# 09 — Развитие Telegram и Web

После закрытия 08 владелец выбрал Telegram/Web, а не серверное сохранение
или продолжение мобильного Canvas. Работа продолжается в существующем
проекте, без новых зависимостей, деплоя и смены формата проекта.

## A. Адресные события Web-превью — завершён (0.5.38)

- [x] Кнопка/форма запускает только свой экземпляр и его цепочку, даже
  при одинаковых подписях. Тип события и источник по-прежнему проверяются.
- [x] Загрузка/перезагрузка превью адресует показанную страницу; контекст
  проекта/модели не разделяет черновики форм или маркер загрузки.
- [x] Неверный JSON, массив и примитив формы не отправляются; ошибка видна.
- [x] Старый запуск без адресата сохраняет прежнее поведение симулятора.
- [x] Два экземпляра, реальные значения, F5, отрицательные случаи — в E2E;
  маршрутизация и независимость цепочек — в unit/integration.

Проверено: **493/493 unit/integration (63 файла), 55/55 E2E**, типы и
сборка успешны. Новые 19 unit/integration и 3 браузерных сценария.
Все 12 уроков и панели 08B повторно пройдены. Решение — ADR-019.

## B1. Текст и заголовок — завершён (0.5.39)

- [x] Реализованы существующие web.text/web.heading, не новые дубли блоков.
- Плоский порядок в превью — порядок узлов, после названия страницы.
- Контракт выхода element: инертные данные kind/text/level; никаких HTML,
  DOM-атрибутов или исполняемого содержимого. Входы приоритетнее настроек.
- Несоединённые элементы показываются по настройкам сразу; соединённые —
  только по успешному результату актуальной схемы. Правка данных/связей
  требует нового запуска, перемещение узлов — нет.
- [x] Unit, реальное соединение/запуск, безопасный вывод и F5 в браузере.

Проверено: **508/508 unit/integration (65 файлов), 58/58 E2E**, типы
приложения/сервера/E2E и сборка успешны. Новые 15 unit/integration + 3 E2E.
Все 12 уроков и панели 08B сохранены. Контракт и ограничения — WEB.md,
решение — ADR-020. Остальные 8 web_ui остаются planned/скрыты.

## Далее — отдельные ограниченные подэтапы

- B2: структура контейнеров/секции/сетки; контракт children и границы
  рендеринга уточнить до реализации. Изображения/ссылки/поля — отдельно.
- C: сверить Telegram callback/inline keyboard с существующим транспортом
  и определить сквозной сценарий симулятор → runtime → адаптер.

B2/C пока не реализованы; A/B1 закрыты. Полный Web-рендерер, опубликованный сайт, реальный
бот, токены и серверное хранилище не входят в A/B1. В превью по-прежнему
показывается первая страница, адрес в рамке не означает публикацию сайта.
