# 10 — Серверное сохранение проектов

После завершения 09 владелец принял рекомендованный приоритет — серверное
сохранение. Этапы 1–5 и планы 07/08/09 не переоткрываются. Серверный CRUD,
аккаунты/HttpOnly-сессии и SQLite уже существуют; новый сервер не создаётся.

## Аудит и последовательность

Редактор использует LocalStorageAdapter и синхронный flush при закрытии.
На старте плана серверный PUT перезаписывал документ без сравнения ревизий. Нельзя просто
подменить адаптер: это создало бы потерю правок, гонки запросов и ложные
«Сохранено» при обрыве сети. Поэтому работа идёт ограниченными подэтапами.

### A. Явные серверные копии — завершён (0.5.46)

- Отдельный раздел Dashboard: состояние аккаунта, вход/регистрация/выход,
  явный выбор рабочего пространства, список серверных проектов.
- Сохранение только новой копии локального проекта через существующий POST:
  новый project.id, прежние внутренние ID/провода/модели/поля/группы. Никаких
  PUT, DELETE или автоматической публикации. Локальный оригинал неизменён.
- Восстановление только отдельной локальной копией с новым project.id;
  серверный проект и существующие локальные не изменяются. Открытие в Canvas
  означает локальное редактирование, а не автосохранение на сервер.
- Песочницы Академии исключены из переноса (сначала явно преобразовать
  в обычный проект). Проверяется сам документ, а не только список карточек.
- Серверные ответы валидируются; ошибка, timeout, 401/403/404/409/413 не
  превращаются в успех. Нет автоматических повторных записей. После
  неопределённого исхода POST нужно обновить список перед повтором.
- Пароли только в форме/POST, сессия HttpOnly; не хранить credentials в
  LocalStorage/Project JSON. Локальные проекты остаются данными браузера,
  не изолируются между аккаунтами: это явно написано в UI.
- Блокировка повторных действий и устаревших ответов; смена аккаунта/раздела
  не применяет поздний ответ к новому контексту. Учебные проекты/прогресс,
  существующие автономные функции и формат v1 сохраняются.
- Unit/integration + настоящие E2E: регистрация/вход, копия → F5 → другая
  локальная копия → Canvas, разделение аккаунтов, ошибки сети/ответа/хранилища.

### B. Серверный редактор и конфликты — B1 завершён, B2 далее

Сначала контракт ревизий/условной записи на сервере (включая restore),
затем отдельный серверный режим редактора, сериализация сохранений,
несохранённые правки/потеря доступа/восстановление после сети. Не менять
глобальный адаптер локальных уроков и не притворяться, что beforeunload
гарантирует доставку HTTP-запроса. Продумать независимые маршруты local/server.

#### B1. Контракт ревизий — завершён (0.5.47)

Миграция 012, непрозрачная revision отдельно от формата v1. Условные
PUT/restore/DELETE в SQLite, отсутствие expectedRevision → 428, устаревшая
→ 409. Случайная новая метка защищает и от повторного создания того же ID.
Сессия/доступ перепроверяются после чтения тела. Строгий отдельный клиент
ServerProjectApi не повторяет записи и не подставляет свежую базу сам.
Обновлены прежние тесты вызовов API под обязательное условие.

43 новых unit/integration: миграция старой заполненной БД, два SQLite-
подключения, конкурирующие HTTP-записи, PUT против restore, невалидные
условия, квитанция/повтор, удаление/ABA, отзыв сессии/membership во время
чтения тела, LIVE/снапшот и строгий клиент. Всего **738/738 (78 файлов)**;
**89/89 E2E**, все 12 уроков, typecheck/build. Контракт и учебная API-практика:
[PROJECT_API.md](../PROJECT_API.md), ADR-028. Деплоя нет.

#### B2. Отдельный серверный Canvas — следующий, не начат

Отдельный маршрут/контекст, явное открытие серверного документа; не менять
глобальный ProjectStorage. Сериализованное автосохранение только после
подтверждения предыдущего; правки во время запроса должны оставаться dirty.
На 409/401/404/сети — остановить автоотправку, не терять локальные правки,
не брать свежую ревизию для слепой перезаписи. Нужны восстановление черновика,
действия пользователя при конфликте и защита смены аккаунта/маршрута/unload.
Состояние «Сохранено на сервере» — только после проверенного ответа.
Фиксировать ограниченную реализацию/приёмку отдельно, не объявлять B1
реализованным серверным редактором или всей синхронизацией.

### C. Приёмка хранения — далее

Несколько вкладок/устройств, смена аккаунта, восстановление черновика,
практика для новичка и полная регрессия. Публикация LIVE и выбор её в Canvas
потребуют явного контракта, не включаются автоматически в перенос копии.

Нет новых зависимостей, боевых секретов, деплоя или доступа к VPS.

## Результат 10A — 2026-09-15

ProjectApi использует общий same-origin JSON-клиент и проверяет ответы Zod.
Срок ожидания 15 секунд; auth подтверждается через me. У панели нет PUT/
DELETE/публикации. Сессия перепроверяется при фокусе и событии BroadcastChannel
(передаётся только уведомление); связанные панели ботов/аудита перемонтируются
при смене аккаунта. Счётчик запросов блокирует позднее применение ответа,
включая восстановление после ухода/выхода в другой вкладке.

26 новых unit/integration и 7 E2E. Итого **695/695 (75 файлов), 89/89 E2E**,
все 12 уроков и предыдущие Web/Telegram/Canvas сценарии; типы и сборка
успешны. В typecheck включена отдельная конфигурация E2E с общими aliases.
Подтверждены реальный API → отдельный браузер → Canvas/F5, разделение
аккаунтов, песочницы, неподдерживаемый ответ, 413, квота, offline/401,
поздние ответы и межвкладочный выход. Никакого VPS-деплоя/реального бота.

Практика для новичка встроена в раскрываемую подсказку Dashboard и
[PROJECT_FORMAT.md](../PROJECT_FORMAT.md). Далее **10B**, не автосинхронизация
на основе безусловного PUT. Ссылки secret_id копируются как данные схемы,
но сами секреты/боты/LIVE/версии не переносятся и не перепривязываются.
