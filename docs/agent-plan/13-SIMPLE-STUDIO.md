## Решение и границы среза

Название «Простой режим». Карточки отображают реальные nodes, связи — реальные
edges с исходными портами. Это не линейная копия графа: связи явно показываются,
порядок карточек не выдаётся за порядок исполнения. Никакой перезаписи координат
при просмотре. Метаданные, модели и группы не удаляются.

Начальный набор намеренно мал: Telegram — событие сообщения, команда, отправка
ответа; core.text доступен дополнительно для уже составленных цепочек. Web —
web.text и core.text. Пустая схема — core.text, далее переход в PRO для сложной
композиции. Presentation задаёт только ID/подписи/группировку, не definitions.

Контекстное «Что сделать дальше?» у события добавляет обычный ответ и выбирает
событие в форме. Пользователь подтверждает реальный провод chat_id → chat_id
кнопкой «Связать с событием». Текст вводится прямо в карточке. Уже подключённый
текст явно подписан и не заменяется настройкой. Возможность выбрать событие
для несвязанного ответа нужна для исправления/старых проектов.

Неподдержанные блоки, связи, поля конфигурации, модели, группы и смешанная схема:
безопасное представление только для чтения, полный список деталей и связей,
раскрываемые данные; редактирование и выполнение — PRO. Не интерпретировать
неизвестные конструкции как простой линейный сценарий. Поддержанные старые
схемы остаются редактируемыми. F5 и переключение сохраняют тот же projectId,
никакой миграции/конвертации. При ошибке сохранения переход режима не выполнять.

Новый код нужен только для композиции простого экрана, отбора/проверки
представимости, доступных форм, выбора следующего действия и переключения режима.
Один Project Format v1, BlockRegistry, Runtime, project-store, ProjectStorage.
Тарифы, paywall, новые рецепты/блоки и VPS не входят в работу.

## Приёмка

Unit: реальный runtime с фиксированным текстом/приоритетом провода/пустым входом;
curation и строгие границы редактирования. E2E через UI без подготовки JSON:
создание → событие → ответ → текст → проверка → телефон → PRO → Simple;
F5, undo/redo, неподдержанный блок без потери данных, старый проект, 390 px,
ошибка обязательной настройки/исправление. Полный прежний набор, types/build.


## Реализованный срез (0.5.52)

- /build — выбор цели; /build/:projectId — карточное представление локального
  документа. Dashboard имеет отдельную точку входа, прежняя кнопка создания
  и /projects/:projectId продолжают открывать PRO. Его каталог, Canvas,
  библиотека, порты, Quick Insert и профессиональные инструменты сохранены.
- Simple → PRO: кнопка в шапке. PRO → Simple: «Инструменты → Простой режим».
  Переключение сохраняет документ; квота не приводит к смене режима/потере
  правок. Уход из Simple при ещё идущем сохранении ждёт результата; ошибка
  блокирует переход и позволяет повторить сохранение. Модель при переходе
  закрывается штатным closeModel с сохранением её содержимого.
- Вынесен только useLocalProjectLifecycle из CanvasPage. Новые компоненты:
  выбор цели/карточное представление, EditorModeSwitch, чистые правила
  simple-presentation. Стор, хранилище и runtime не копировались.
- Telegram: 3 основных предложения (сообщение, команда, ответ), ещё core.text
  под «Дополнительно». Web: web.text/core.text; пустая схема: core.text как
  заготовка, остальные действия — PRO. Новых BlockDefinition нет, PRO по-прежнему
  содержит 97 доступных, базовая фильтрация 57; всего definitions 166.
- Русские названия отличаются только в Simple presentation. PRO/Academy label
  не переименованы. Широкий набор логики/фото/кнопок не обещан в этом срезе.
- После события — «Что сделать дальше?» и добавление ответа с формой текста
  и понятным получателем. Соединение отдельным подтверждением: добавление и
  связь независимо отменяются. История — штатные past/future; F5 и смена
  представления заново загружают документ и сбрасывают историю, но не схему.
- send_message: optional config.replyText; подключённый text всегда приоритетен,
  отсутствие текста по-прежнему ошибка. PRO Inspector показывает этот же параметр
  с пояснением приоритета. Приходящий текст в Simple явно подписан; переключение
  на свой текст удаляет только выбранное ребро по явному действию, не источник.
- /start распознаётся из сообщения теста общей messageCommand: вынесено точное
  прежнее правило ingress без изменения его семантики. PRO сохраняет свои
  поля симулятора. Проверка Simple вызывает прежний execution-store.run;
  PhonePreview/WebPreview показывают реальные результаты. После правки старый
  результат не выдаётся за новый. Никаких сообщений настоящему боту.
- Прочие blocks/config/edges, дублированные входы, разные события для текста и
  получателя, модели/группы/переменные/смешанные схемы — только чтение. Структура
  сохраняется полностью, в том числе конфигурация и координаты. Выполнение
  неподдержанных схем в Simple не маскируется успешным тестом; доступно в PRO.
- Пустой проект не выдаётся за бота. Web умеет только текстовую страницу через
  существующий WebPreview; формы/деревья/модальные окна остаются в PRO.

### Первый результат

8 действий от Dashboard (ввод каждого поля считается действием):
«Собрать в простом режиме» → Telegram → событие → «Ответить сообщением» →
ввести «Привет!» → «Связать с событием» → ввести тестовое сообщение →
«Проверить бота». Дополнительные настройка получателя/JSON/Debug не нужны.

Данные: telegram.message_received.chat_id → telegram.send_message.chat_id,
у ответа config.replyText="Привет!". Два узла, одно ребро, formatVersion=1.
Других источников текста, скрытых узлов и автоматических конвертеров нет.

### Оставшиеся границы

1. Ветвления, кнопки, фото и произвольные типизированные соединения редактируются
   в PRO; универсального Simple-представления сложного графа пока нет.
2. Web ограничен текстом; пустая схема — заготовкой. Это не полноценный Web Builder.
3. Simple пока для локальных проектов. Серверный Simple с CAS/резервом требует
   отдельного расширения поверх существующей ServerSession, не копии хранения.
