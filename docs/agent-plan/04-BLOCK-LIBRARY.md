# 04 — Этап 4: Библиотека блоков (Промпт №4)

**Статус: план зафиксирован.** Выполняется после этапов 1–3
(фактическое продвижение — в [STATUS.md](STATUS.md)).

## Цель этапа

Полная библиотека деталей. **Каждая основная категория содержит минимум
10 определений блоков**:

```
16 категорий × 10 блоков = минимум 160 определений
```

Точка старта (фундамент): 24 блока (18 в палитре + 6 зарезервированных)
в 8 категориях — см. `docs/BLOCKS.md`.

## Категории (16)

1. **Ядро** — константы, входы/выходы моделей, базовые примитивы.
2. **Логика** — условия, переключатели, сравнения, комбинаторы.
3. **Данные** — объекты, массивы, работа со структурами.
4. **Поток** — задержки, циклы, ожидание, параллельность.
5. **Телеграм-события** — входящие сообщения, команды, коллбэки и др.
6. **Телеграм-действия** — отправка сообщений, фото, документов, редактирование и др.
7. **Веб-интерфейс** — страницы, секции, текст, кнопки, формы, изображения и др.
8. **Веб-события** — клики, отправки форм, загрузка страницы и др.
9. **Модели** — вызов моделей, входы/выходы, контракты.
10. **Память** — переменные, общее хранилище, состояние.
11. **Интернет-запросы** — внешние API, загрузка данных.
12. **Дата/Время** — текущее время, форматирование, таймеры, расписания.
13. **Файлы и медиа** — файлы, изображения, документы.
14. **Безопасность** — секреты, доступы, проверки.
15. **Отладка** — логи, трассировка, инспекция значений.
16. **Преобразователи** — конвертация типов (развитие текущей категории «Данные»).

## Дополнительно (обязательные разделы библиотеки)

- **Мои детали** — пользовательские детали.
- **Мои модели** — модели пользователя как детали.
- **Избранное** — закреплённые детали.
- **Недавние** — последние использованные.

## Структура определения блока

Каждое определение содержит:

| Поле | Назначение |
|---|---|
| Идентификатор | устойчивый технический идентификатор `<категория>.<имя>` (англ.) |
| Версия | версия определения (совместимость/миграции) |
| Название | русское название (i18n-ключ) |
| Описание | русское описание: что делает блок (i18n-ключ) |
| Категория | одна из 16 категорий |
| Подкатегория | уточняющая группировка внутри категории |
| Значок | визуальная иконка детали |
| Входы | порты входов (тип, обязательность) |
| Выходы | порты выходов (тип), включая ошибки/события |
| Конфигурация | параметры экземпляра со значениями по умолчанию |
| Выполнение | обработчик выполнения в рамках runtime |
| Возможности | флаги/особенности (триггер, вход модели, асинхронность и т. п.) |
| Сложность | уровень сложности для пользователя |
| Ключевые слова | слова для поиска (рус/англ) |
| Статус | зрелость определения (см. ниже) |

### Статус определения

| Статус | Значение |
|---|---|
| Запланировано | только определение, реализации нет (скрыт из палитры или помечен) |
| Прототип | черновая реализация, может меняться |
| Реализовано | стабильная реализация с тестами |
| Экспериментально | доступно, но поведение может существенно меняться |
| Устарело | не рекомендуется; поддерживается совместимость |

### Сложность

- **Базовый** — простые детали для новичков.
- **Продвинутый** — детали для опытных пользователей.

## Масштабируемость архитектуры

Архитектура библиотеки должна без переписывания поддерживать:

- 200+ блоков;
- 500+ блоков;
- 1000+ блоков.

Практические следствия: ленивая регистрация/подгрузка категорий, поиск по каталогу,
версионирование определений, раздельные файлы категорий (уже частично есть в
`src/blocks/`), каталог в `docs/BLOCK_CATALOG.md` (этап 3).

## Жёсткое требование честности

**Запрещено выдавать запланированное за реализованное.** Статус каждого блока
должен отражать факт: есть исполняемый код и тесты — «Реализовано»;
только определение — «Запланировано». Матрица фактических статусов —
`docs/IMPLEMENTATION_MATRIX.md` (этап 3). См. [RULES.md](RULES.md), правило 7.
