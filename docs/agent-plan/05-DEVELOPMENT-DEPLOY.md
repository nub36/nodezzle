## Порядок разработки

После завершения предыдущих этапов агент продолжает разработку по `docs/ROADMAP.md`.

**Каждый этап/подэтап выполняется строго по циклу:**

```
Разработка
  → Тесты
  → Проверка типов
  → Сборка
  → Документация
  → Обновить статус
  → Обновить историю изменений
  → Коммит
  → Отправка в репозиторий
```

Команды:

```bash
npm test              # тесты (все должны быть зелёными)
npm run typecheck     # проверка типов без ошибок
npm run build         # сборка без ошибок
```

Затем обновляются: затронутые документы в `docs/`, [STATUS.md](STATUS.md),
`CHANGELOG.md`. Только после этого — `git commit` + `git push`.

## Дисциплина коммитов

- **Не оставлять огромные незакоммиченные изменения.**
- После **каждого стабильного подэтапа** — обязательно **КОММИТ + ПУШ**.
- Не копить «тысячи незакоммиченных строк» (см. [RULES.md](RULES.md), правило 11).
- Сессия может оборваться в любой момент — если работа не отправлена в
  репозиторий, она потеряна для следующих агентов.

- **HTTPS через Let's Encrypt** (сертификаты).
- Порты **3000 и 3001 запрещены** для NODEZZLE при любых обстоятельствах

## Безопасность секретов

**Репозиторий на GitHub публичный.**

Никогда не коммитить:

- файлы окружения;
- учётные данные SSH;
- токен DuckDNS;
- токены Telegram;
- ключи API;
- пароли баз данных;
- закрытые ключи.

Проверка перед коммитом: `git status`, просмотр диффа; файл `.gitignore`
должен закрывать секреты (в репозитории есть безопасный `.env.example`).

### Будущее хранение секретов

Секреты Telegram/API в продукте хранятся через **Secrets Vault**,
а в схемах используется только **`secret_id`**. Никаких реальных
значений секретов в коде, на холсте или в документации. Токены Telegram —
только на сервере (см. `docs/TELEGRAM.md`, `docs/DECISIONS.md`).
