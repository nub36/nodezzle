# 03 — Этап 3: Мастер-спецификация (Промпт №3)

**Статус: ЭТАП ВЫПОЛНЕН (2026-09-14, версия 0.3.0).** Созданы все документы
обязательного состава (см. ниже); фактическое состояние — в
[STATUS.md](STATUS.md) и [../IMPLEMENTATION_MATRIX.md](../IMPLEMENTATION_MATRIX.md).

## Цель этапа

Этап создаёт **полную проектную память**: единую систему спецификаций, в которой
описано ВСЁ — каждая страница, каждая система, каждое правило безопасности.
Любой будущий агент (или человек) должен уметь восстановить полное понимание
продукта только по документации репозитория.

## Обязательный состав документации

Этап поддерживает и развивает следующие документы (создаются по мере выполнения
этапа; существующие — не терять и не дублировать):

| Документ | Содержание |
|---|---|
| `docs/MASTER_SPEC.md` | Главная спецификация продукта: сущности, состояния, правила, сценарии. |
| `docs/DESIGN_SYSTEM.md` | Дизайн-система: цвета, типографика, компоненты, состояния, анимации, тёмная тема. |
| `docs/SECURITY.md` | Безопасность: секреты, доступы, изоляция исполнения, лимиты, угрозы и контрмеры. |
| `docs/DATABASE.md` | База данных: сущности, схемы, миграции, хранилище проектов и переменных. |
| `docs/BLOCK_CATALOG.md` | Полный каталог блоков (развитие `docs/BLOCKS.md` под 160+ блоков этапа 4). |
| `docs/STATUS.md` | Технический статус проекта (синхронизирован с `docs/agent-plan/STATUS.md`). |
| `docs/IMPLEMENTATION_MATRIX.md` | Матрица реализации: что запланировано / прототип / реализовано / покрыто тестами. |
| Документация страниц | Отдельные описания страниц (раздел ниже). |

Важно: `docs/agent-plan/STATUS.md` остаётся главным «местом остановки» для агентов;
`docs/STATUS.md` — общий статус продукта для документации.

## Страницы продукта

Каждая страница описывается в документации (назначение, состояния, данные, действия):

1. **Лендинг (Главная)** — уже есть в фундаменте: Hero, Playground, возможности.
2. **Авторизация (Аутентификация)** — вход, регистрация, восстановление пароля (русские страницы).
3. **Дашборд (Проекты)** — уже есть в фундаменте: список, создание, удаление, демо.
4. **Холст (Редактор)** — основной экран сборки; спецификация — этап 2.
5. **Проект** — настройки конкретного проекта: имя, тип, переменные, версии.
6. **Настройки** — аккаунт, рабочее пространство, предпочтения.
7. **Предпросмотр телефона с Telegram (Telegram Preview)** — живой предпросмотр бота.
8. **Предпросмотр веба (Web Preview)** — живой предпросмотр веб-интерфейса.

## Системы, которые охватывает мастер-спецификация

- **Выполнение** — модель исполнения схем: состояния, телеметрия,
  отмена, защита от циклов, трассировка.
- **Модели** — контракты, версии, вложенность, библиотека «Мои модели».
- **Телеграм** — события, действия, симулятор → реальный транспорт, безопасность токенов.
- **Веб** — веб-элементы, рендеринг, события, предпросмотр, изоляция пользовательского JS.
- **Черновик / Живой** — черновик схемы и «живая» версия.
- **Публикация** — публикация версий проекта.
- **История версий** — снапшоты, сравнение, откат.
- **Безопасность** — см. `docs/SECURITY.md`: секреты, доступы, лимиты, изоляция.
- **База данных** — см. `docs/DATABASE.md`: проекты, переменные, история, пользователи.
- **Секреты** — тип `secret`, серверное хранение, маскирование в UI
  (будущее: хранилище секретов + `secret_id` в схемах; см. [05-DEVELOPMENT-DEPLOY.md](05-DEVELOPMENT-DEPLOY.md)).
- **Трассировка выполнения** — пошаговый след выполнения.
- **Повтор** — воспроизведение прошедшего выполнения.
- **Дорожная карта** — развитие `docs/ROADMAP.md` по итогам этапов.

## Принципы

- Спецификации пишутся **на русском**.
- Фактическое состояние реализации отражается честно: статусы
  `запланировано / прототип / реализовано` (см. [RULES.md](RULES.md), правило 7).
- Документация обновляется вместе с кодом, а не «когда-нибудь потом»
  (см. [RULES.md](RULES.md), правило 9).
