## Концепция

**NODEZZLE = NODE + PUZZLE.**

Визуальный puzzle/LEGO-конструктор, в котором пользователь собирает работающие
системы из соединяемых деталей:

```
Telegram + Web/HTML + логика + модели
```

- **Деталь (блок)** — минимальная единица: источник данных, действие, логика, элемент UI.
- **Соединение** — типизированная связь между портами деталей.
- **Логика** — поведение схемы, выполняемое runtime.
- **Модель** — переиспользуемая под-схема с контрактом (INPUT/OUTPUT/ERROR),
  вызывается как одна деталь; поддерживается «модель внутри модели».

### Философия

> **«Не программируй. Собери.»**
> Для Telegram: *«Не программируй бота. Собери его.»*

Интерфейс — не «скучный Node Editor», а цифровое ощущение Puzzle/LEGO: детали
светятся, соединения «притягиваются», данные текут как частицы. При этом
читаемость Canvas важнее декоративных эффектов.

Полная концепция — `docs/CONCEPT.md`. MVP — только два направления: **Telegram**
и **Web/HTML** (другие платформы пока не добавляются; архитектура расширяема).

## Зафиксированный фундамент (что уже есть)

- **Block Registry** — расширяемый реестр деталей (`src/core/registry/block-registry.ts`);
  ядро не знает о конкретных блоках и платформах.
- **Неограниченные INPUT/OUTPUT** — порты данных, событий (EVENT) и ошибок (ERROR);
  количество портов у детали архитектурно не ограничено.
- **Типизация портов (система типов)** — 16 базовых типов + `TypeRegistry` для
  пользовательских типов; умные соединения: совместимость портов
  (`src/core/type-system/compatibility.ts`), несовместимые соединения запрещены,
  «тихие» преобразования запрещены — только Converter-блоки.
- **Runtime** — живое выполнение схем `executeCanvas`: состояния
  IDLE/WAITING/RUNNING/SUCCESS/ERROR/STOPPED, pull-источники, защита от циклов,
  отмена (Stop), телеметрия, модели внутри моделей (`src/core/runtime/execute.ts`).
- **Формат проекта (Project Format) v1** — Zod-схема: canvas, узлы, соединения,
  модели, контракты, переменные, meta (`src/core/project/schema.ts`).
- **Сериализация** — сериализация/десериализация проекта (`src/core/project/serialize.ts`).
- **Автосохранение** — autosave (debounce) + flush при закрытии вкладки,
  адаптер `ProjectStorage` (LocalStorage) (`src/core/project/storage.ts`).
- **Undo/Redo** — Ctrl+Z / Ctrl+Shift+Z, копировать/вставить/дублировать.
- **Canvas** — палитра деталей по категориям, поиск, drag & drop, умные соединения
  с подсветкой совместимых портов, кастомные узлы из Block Definition,
  minimap, инспектор детали (конфигурация + последний результат).
- **Симулятор Telegram / Debug-панель** — симулятор (Telegram/Web payload),
  «Чат Telegram» (outbox), журнал выполнения (LOG), история выполнений,
  анимация частиц по соединениям во время выполнения.
- **Дашборд (Панель проектов)** — проекты, создание по типам
  (Telegram-бот / Web / HTML / Telegram + Web / Пустой), загрузка демо-примера, удаление.
- **Лендинг (Главная)** — Hero-анимация «детали собираются в систему»,
  Playground (интерактивная демонстрация с демо-чатом), возможности,
  Premium Dark UI (glassmorphism, aurora, glow).
- **ru-RU** — весь интерфейс и документация на русском; технические идентификаторы
  на английском; `src/i18n/locales/ru.json`.
- **Блоки (24)** — 18 в палитре + 6 зарезервированных (`available: false`, скрыты):
  ядро, данные/конвертеры, логика, поток, Telegram, Web, модели, отладка, дата/время.
  Подробности — `docs/BLOCKS.md`.
- **Тесты** — 34 unit-теста ядра (совместимость, реестр, формат, хранилище,
  runtime: ветвление, ошибки, циклы, задержка, отмена, модель внутри модели).
- **Документация** — `AGENTS.md`, `README.md`, `CHANGELOG.md`,
  `docs/`: CONCEPT, ARCHITECTURE, BLOCKS, MODELS, TELEGRAM, WEB, UI,
  PROJECT_FORMAT, ROADMAP, IDEAS, DECISIONS.
- **Демо-проект** — «Пример: Telegram-приветствие»:
  `Получено сообщение → В объект → Вызов модели «Приветствие» → Из объекта → Отправить сообщение`.
