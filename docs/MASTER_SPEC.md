## 2. Продукт

**NODEZZLE (NODE + PUZZLE)** — визуальная среда сборки Telegram-ботов,
веб-интерфейсов и систем из соединяемых деталей. Философия: **«Не программируй. Собери.»**

- Целевые направления MVP: **Telegram-боты** и **Веб-интерфейсы** (один проект
  может совмещать оба — тип `telegram-web`).
- Пользователь собирает схему из деталей (блоков) на бесконечном холсте;
  схема выполняется живьём с визуальной телеметрией.
- Расширяемость: новая платформа = новый набор Block Definitions поверх общего
  ядра, без переписывания (см. [ARCHITECTURE.md](ARCHITECTURE.md)).

## 3. Сущности

### 3.1 Деталь (блок) — SPEC/IMPLEMENTED
Описание: `BlockDefinition` (`src/core/types/blocks.ts`), регистрация —
`BlockRegistry`. Деталь имеет: устойчивый `id` вида `<категория>.<имя>`,
русские название/описание (i18n), категорию, порты, конфигурацию по умолчанию,
обработчик выполнения `runtime`, опционально `trigger`/`entry`/`matches`.
Полный каталог — [BLOCK_CATALOG.md](BLOCK_CATALOG.md).

### 3.2 Порт — SPEC/IMPLEMENTED
`PortDefinition`: направление (вход/выход), вид (`data | event | error`),
тип (`text, number, boolean, json, object, array, file, image, user, date,
url, secret, telegram_message, event, error, any`), русская подпись.
Форма маркера кодирует вид: круг — данные, ромб — событие, квадрат — ошибка
(покрыто тестами совместимости).

### 3.3 Соединение — SPEC/IMPLEMENTED
Ребро `source → target` между портами. Правила «умных соединений»
(`src/core/type-system/compatibility.ts`): `error↔error`, `event↔event`,
данные — `any` совместим со всем, иначе типы равны. **Тихие преобразования
запрещены** — только конвертер-блоки. Цвет ребра = цвет типа порта-источника.

### 3.4 Холст (CanvasDocument) — SPEC/IMPLEMENTED
`{ id, name, nodes[], edges[], viewport?, groups? }` — формат описан в
[PROJECT_FORMAT.md](PROJECT_FORMAT.md), валидируется Zod (формат `formatVersion: 1`).
Группы (`groups`) — визуальные рамки: `{ id, label?, nodeIds[] }`
(опциональное поле, старые проекты валидны без миграции).

### 3.5 Модель — SPEC/IMPLEMENTED
`StoredModel`: `{ id, name, version, contract, canvas, updatedAt }`.
Контракт — именованные типизированные порты `inputs/outputs/error`.
Внутри модели: `Вход модели` (`core.input`, `config.portId`) и `Выход модели`
(`core.output`). Вызов снаружи — `Вызов модели` (`models.call`, объектные порты
`вход/результат`, ключи — через конвертеры «В объект»/«Из объекта»).
Рекурсия (модель в модели) поддерживается рантаймом. Создание из выделения —
`extractModel()` (TESTED). Подробности — [MODELS.md](MODELS.md).

### 3.6 Проект — SPEC/IMPLEMENTED
`NodezzleProject`: `{ formatVersion: 1, id, name, kind: telegram | web |
telegram-web | empty, canvas, models[], variables[], meta }`. Хранение —
`ProjectStorage` (сейчас LocalStorageAdapter; API-адаптер — PLANNED, см.
[DATABASE.md](DATABASE.md)).

### 3.7 Переменные проекта — SPEC (формат)/ЗАПЛАНИРОВАНО (механика)
Поле `variables[]` существует в формате (`{ id, name, type, value, scope:
'project' }`); блоки `Переменная`/`Общее хранилище` зарезервированы
(`available: false`). UI и исполнение переменных — будущие этапы.

### 3.8 Триггер и событие запуска — SPEC/IMPLEMENTED
`TriggerPayload`: `{ source: telegram | web | model | generic, telegram?, web?,
model? }`. Триггеры — детали с `trigger: true` и функцией `matches()`.
Источники событий сейчас: Симулятор и превью (телефон/веб). Реальный транспорт
Telegram — ЗАПЛАНИРОВАНО ([TELEGRAM.md](TELEGRAM.md)).

### 3.9 Выполнение — SPEC/IMPLEMENTED
Движок `executeCanvas()` (чистый TypeScript, TESTED): обход от триггеров,
состояния узлов `idle | running | success | error | skipped`, журнал,
телеметрия портов (`NodeRunInfo: inputs/outputs/durationMs`), отмена, защита от
циклов, модели внутри моделей. Состояния схемы: `IDLE → WAITING → RUNNING →
SUCCESS | ERROR | STOPPED`.

### 3.10 Пользователь, рабочее пространство, версия, публикация — ЗАПЛАНИРОВАНО
Аутентификация, аккаунты, история версий проекта, публикация, черновик/живое
как раздельные документы, трассировка и повтор выполнений — будущие этапы
([ROADMAP.md](ROADMAP.md), [IDEAS.md](IDEAS.md)). Переключатель «Черновик/Живой»
в тулбаре сейчас — визуальный режим, не раздельное хранение.

## 5. Ключевые сценарии (фактическое поведение)

1. **Первый запуск.** Лендинг: hero-анимация «детали собираются в систему»,
   живой Playground (мини-схема запускается без регистрации), переход на Дашборд.
2. **Создание проекта.** Дашборд → выбор типа (Телеграм / Веб / Телеграм+Веб /
   Пустой) → проект сохраняется в LocalStorage, открывается Холст. Доступно
   «Загрузить пример: Telegram-бот» (демо-проект `demo_telegram_bot`).
3. **Сборка схемы.** Детали из библиотеки (вкладки, поиск, избранное, недавние,
   «Мои модели»), drag&drop, умные соединения, быстрая вставка, контекстное
   меню, группы-рамки, стикеры-заметки, инспектор, undo/redo, автосохранение
   (900 мс + сброс при закрытии вкладки).
4. **Создание модели из выделения.** Контекстное меню «Создать модель из
   выделенного» → диалог (имя + автоконтракт) → выделение заменяется «Вызовом
   модели»; граничные значения — через конвертеры. Ограничения версии: один
   внешний вход, без событий и триггеров в выделении.
5. **Спуск внутрь модели.** Двойной клик по «Вызов модели» → внутренний холст,
   хлебные крошки `Проект › Модели › Имя`; правки сохраняются в модель.
6. **Запуск.** Кнопка «Запустить» или Симулятор (источник Телеграм/Веб +
   данные). Узлы подсвечиваются состояниями, рёбра анимируются, журнал и
   значения портов — в Debug-панели (вкладки «Порты», «Журнал», «История»).
7. **Предпросмотр телефона.** Вкладка «Телефон»: рамка телефона, шапка бота,
   пузыри сообщений из того же запуска, что и «Чат».
8. **Предпросмотр веба.** Вкладка «Веб»: окно браузера из веб-деталей схемы;
   загрузка страницы/клик/отправка формы запускают схему веб-событиями.

## 6. Системные правила (сводка)

- Ядро не знает о платформах; данные описаны Zod-схемой; рантайм — чистый TS.
- Все пользовательские строки — через i18n; основная локаль `ru-RU`.
- Формат проекта меняется только через опциональные поля либо новую версию
  формата + миграцию ([PROJECT_FORMAT.md](PROJECT_FORMAT.md)).
- Секреты никогда не попадают в репозиторий, формат проекта и frontend
  ([SECURITY.md](SECURITY.md)).
- После каждого смыслового изменения: тесты, документация, коммит
  ([05-DEVELOPMENT-DEPLOY.md](agent-plan/05-DEVELOPMENT-DEPLOY.md)).
