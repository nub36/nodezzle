# NODEZZLE — Архитектурные решения (ADR)

Обоснованные технические решения проекта. Каждое решение: контекст → решение → альтернативы → последствия.

---

## ADR-001 — Стек фронтенда: Vite + React 19 + TypeScript

**Контекст.** NODEZZLE — heavyweight-SPA (Canvas с тысячам узлов, live-выполнение, i18n). Нужны: быстрая разработка, строгая типизация, зрелая экосистема для node-graph UI, лёгкий dev/build.

**Решение.** **Vite** (dev/build, HMR, alias `@` → `src/`) + **React 19** + **TypeScript (strict)** + `moduleResolution: bundler`.

**Альтернативы.**
- *Next.js* — SSR/SSG избыточны: продукт — десктоп-SPA; усложняет превью/статическую раздачу. Отклонено.
- *Svelte/Solid* — меньше экосистемы именно для graph-редакторов. Отклонено.
- *Без TS* — формат проекта, контракты блоков и runtime требуют строгих типов. Отклонено.

**Последствия.** `tsc --noEmit` в CI-процедуре (npm run build/typecheck); TS-типы выведены из Zod-схемы формата.

## ADR-002 — Canvas: @xyflow/react (React Flow 12)

**Контекст.** Нужен бесконечный Canvas: drag&drop, зум/пан, соединения, миникарта, производительность на больших схемах, кастомные узлы, API для интеграции (screenToFlowPosition, applyNodeChanges…).

**Решение.** **@xyflow/react 12** — зрелая библиотека node-graph: встроено всё необходимое, кастомные узлы/рёбра, controls, minimap, виртуализация рендера.

**Альтернативы.**
- *Собственный Canvas (SVG/Canvas2D/WebGL)* — месяцы работы, риск деградации качества; переписывание при росте. Отклонено.
- *jointjs / litegraph.js / react-flow-diagram* — слабее экосистема, устаревание, меньше контроля типов. Отклонено.
- *LogicFlow / X6* — API и экосистема слабее для React-стека. Отклонено.

**Последствия.** Кастомный узел `NodezzleNode` рендерится из Block Definition; UI-состояние хранилища отделено от формата (serialize.ts).

## ADR-003 — Состояние: Zustand

**Контекст.** Состояние: проект/canvas (nodes/edges), undo/redo, autosave, execution (статусы узлов, логи, outbox). Нужно: предсказуемость, минимум бойлерплейта, селекторы (узлы перерисовываются по своим слайсам), доступ вне React (runtime-колбэки).

**Решение.** **Zustand 5**: два стора — `project-store` (документ, undo/redo, autosave) и `execution-store` (выполнение).

**Альтернативы.**
- *Redux Toolkit* — больше ритуала, не критично для SPA такого масштаба. Отклонено.
- *Context+reducer* — перерисовки всего дерева, неудобные селекторы. Отклонено.
- *Jotai/Recoil* — атомарность избыточна. Отклонено.

**Последствия.** Undo/redo — явная история снапшотов (100), не «магия» middleware; autosave — debounce 900 мс + flush on beforeunload.

## ADR-004 — i18n: i18next + react-i18next, основная локаль ru-RU

**Контекст.** Весь UI и документация — на русском; технические id — английские; архитектура должна позволить добавить языки позже.

**Решение.** **i18next** с одним словарём `ru.json` (неймспейсы внутри: app/common/landing/dashboard/canvas/execution/errors/portTypes/categories/blocks). Все пользовательские строки — ключи; новые блоки несут свои `labelKey/descriptionKey`.

**Альтернативы.**
- *Harдкод строк* — нарушение требований продукта. Отклонено.
- *messageformat/полиморфные словари* — избыточно на MVP. Отклонено.

**Последствия.** Правила: русские тексты только в `ru.json`; `errors.*` — код=англ., текст=рус.

## ADR-005 — Tailwind CSS 4 (утилиты) + собственные токены/декор

**Контекст.** Premium Dark UI (glassmorphism, aurora, glow) требует: дизайн-токены, быстрые утилиты, кастомные декоративные классы без тяжёлых библиотек анимации.

**Решение.** **Tailwind CSS 4** (через `@tailwindcss/vite`): токены в `@theme` (abyss/navy/panel/line/ink/muted), декоративные классы (aurora, glass, noise, hero-*, play-*, status-*) — вручную в `globals.css` (чистый CSS + SMIL, **без framer-motion** на этом этапе).

**Альтернативы.**
- *styled-components/CSS Modules* — дублирование утилит, медленнее итерации. Отклонено.
- *framer-motion* — лишняя зависимость; анимации покрывает CSS/SMIL. Пересмотреть при появлении сложных переходов. Отложено.

**Последствия.** Один CSS-файл стилей; токены — единая точка правды цвета.

## ADR-006 — Формат проекта: Zod (schema-first)

**Контекст.** Формат проекта — контракты между UI, runtime и будущим backend. Нужны: валидация при загрузке, вывод типов, версионирование.

**Решение.** **Zod 4**: `nodezzleProjectSchema` — единственный источник правды (`z.infer` → TS). Проверка: `tryParseProject` при чтении из хранилища; runtime дополнительно валидирует документ (существование блоков/узлов соединений).

**Альтернативы.**
- *TypeBox/EJSON* — меньше интеграции с TS-выводом и экосистемой. Отклонено.
- *Чистые TS-интерфейсы без валидации* — мусорные данные ломают runtime. Отклонено.

**Последствия.** Блоки/категории не перечислены в схеме формата (ссылка `blockId` строкой) — формат не меняется при добавлении блоков.

## ADR-007 — Хранилище: интерфейс ProjectStorage + LocalStorageAdapter

**Контекст.** MVP без backend; впереди — серверное хранилище, версии, пользователи.

**Решение.** Интерфейс `ProjectStorage` (list/get/save/remove) + `LocalStorageAdapter` (ключ `nodezzle.project.<id>`). Flush на `beforeunload`. Замена на `ApiStorageAdapter` — без изменения UI (ROADMAP этап 2–3).

**Альтернативы.** *IndexedDB* — асинхронная сложность без пользы для MVP (размеры проектов малы). Отклонено до этапа «большие проекты». *SQLit/WASM* — избыточно. Отклонено.

## ADR-008 — Runtime: чистый TypeScript, `executeCanvas`

**Контекст.** Выполнение схем: данные по соединениям, триггеры, модели, ошибки, отмена, циклы. Должно тестироваться без DOM и в будущем работать на сервере (Telegram webhook → execution).

**Решение.** `executeCanvas(doc, options) → ExecutionResult` — чистая асинхронная функция без React: очередь готовности (push), pull «холодных» источников (on-demand исполнение констант), бюджет шагов (циклы), cancel-флаг, телеметрия (nodeRuns/logs/outbox). Telegram-транспорт — инъекция `runtime.telegram` (MVP: outbox-симуляция).

**Альтернативы.**
- *Выполнение внутри React-стека (стор как движок)* — не тестируемо, не переиспользуемо на сервере. Отклонено.
- *WASM/worker на этапе 0* — преждевременно (см. ROADMAP этап 7). Отложено.

**Последствия.** 10+ unit-тестов runtime; тот же код ляжет в будущий backend.

## ADR-009 — Умные соединения: правила в ядре, UI — подсветка

**Контекст.** Совместимость INPUT/OUTPUT должна быть единой для UI (подсветка/запрет) и для будущего (валидации, AI-проверки).

**Решение.** `checkCompatibility(source, target)` в `src/core/type-system` (чистая функция, тестируется): error↔error, event↔event, data: `any` со всем / равенство типов / TypeRegistry для кастомных. Canvas: `isValidConnection` запрещает несовместимые; во время drag — подсветка портов.

**Последствия.** Новые типы/правил добавляются в одно место.

## ADR-010 — Роутинг: react-router-dom (HashRouter)

**Контекст.** Три экрана (/, /dashboard, /projects/:id). Статическая раздача превью/сборки без серверных rewrite.

**Решение.** **react-router-dom 7** + **HashRouter** (`/#/dashboard`): работает из любого статического хостинга/превью без настройки. При появлении backend-хостинга — переход на BrowserRouter без изменения кода экранов.

## ADR-011 — Тесты: Vitest (node, без jsdom)

**Контекст.** Ядро (типы, реестр, формат, storage, runtime) — чистый TS. UI-тесты не требуются на этапе 0 (ручная проверка превью).

**Решение.** **Vitest** (node-среда): 34 unit-теста; `*.test.ts` рядом с кодом; storage — in-memory fake (без mock-библиотек).

## ADR-012 — Безопасность секретов

**Контекст.** Публичный репозиторий; продукт будет использовать Telegram Bot Token и API-ключи.

**Решение.**
1. В Git — только `.env.example` (названия + фиктивные значения, помеченные `EXAMPLE-FIXTURE-DO-NOT-USE`).
2. `.env`/`.env.*` в `.gitignore` (исключение `.env.example`).
3. Telegram Bot Token — **только на backend** (в будущем); frontend-адаптер — симуляция (outbox).
4. Тип порта `secret` существует; значения секретов в формате проекта не хранятся (в будущем — ссылки на серверные секреты).
5. Перед каждым commit — проверка отсутствия секретов (AGENTS.md §6).

## ADR-013 — MVP-направления: только Telegram и Web

**Контекст.** Заявка продукта: два направления; другие платформы — при расширении.

**Решение.** Реализуются категории `telegram` и `web` (+ общие: core/logic/data/flow/models/debug/datetime). Категории `http`, `ai`, `memory` зарезервированы (блоки `available: false` — документация архитектуры без ложных обещаний UI).

**Последствия.** Архитектура проверена «на совместимость с будущим»: новый канал = модуль блоков + регистрация (проверено двумя платформами).

## ADR-014 — Именование: `nodezzle`, branch-политика

**Контекст.** Долговременная память проекта — один репозиторий `nub36/nodezzle`.

**Решение.** Все изменения — в этом репозитории; коммиты с русским описанием; документация синхронизируется (AGENTS.md §5). PR-процесс: ветка → PR в `main` (по решению владельца).

## ADR-015 — Свободное место при вставке, без перераскладки схемы (0.5.34)

**Контекст.** Компактные детали всё равно накладывались при повторном клике
в библиотеке. Существующие вручную заданные позиции должны сохраняться.

**Решение.** Геометрия — чистая функция UI-слоя; Canvas передаёт актуальные
размеры, препятствия и видимую область в координатах холста. Поиск по
полосам/интервалам выбирает целую свободную позицию с зазором 24.
При заполнении viewport используется свободная точка справа от схемы,
камера показывает её. `project-store.addNode` и сериализатор не меняются.

**Последствия.** Единое поведение для клика, drop, стартовой вставки и
меню от порта; без новых зависимостей и формата проекта. Измерения и
viewport остаются временными UI-данными. Старые позиции не изменяются;
не выполняются глобальная раскладка, устранение старых наложений или
переразмещение при позднем росте узлов. Буфер/дублирование вне этого изменения.


## ADR-016 — Фрагмент как единица размещения (0.5.35, 08A)

**Контекст.** Владелец выбрал Canvas UX после плана 07. Смещение дубликатов
на +36/+36 и случайная точка paste создавали наложения; поузловой поиск
разрушил бы взаимную раскладку копии.

**Решение.** Геометрия ADR-015 переносится из `features/canvas` в `lib`,
чтобы стор не зависел от feature-слоя. Добавлены общие границы фрагмента.
Приватный `insertFragment` в сторе находит свободное место для всего
прямоугольника, переносит узлы одним смещением, копирует лишь внутренние
связи и создаёт один снимок истории. Буфер глубоко копирует узлы и рёбра.
UI передаёт доступную область, получает только новые ID и показывает
фрагмент существующей камерой; mutable-содержимое буфера не раскрывается.

**Последствия.** Внутренняя раскладка, порты, старые позиции и формат v1
сохранены; зазор 24, без глобальной раскладки и новых зависимостей.
Пустоты внутри границ не используются, старые наложения не исправляются.
Сериализатор продолжает округлять дробные координаты: точное взаимное
смещение гарантируется в операции вставки, а не после округления v1.
Рамки групп и определения моделей не дублируются; ограничения минимального
масштаба и узких экранов остаются явными (UI.md, план 08B).


## ADR-017 — Перемещаемая подсказка без блокировки соединений (0.5.36)

**Контекст.** Владелец показал зависание «Первой цепочки»: окно поверх
редактора, неверный выход user_id вместо text, быстрая вставка. Отсутствие
обратной связи делало корректный отказ зачёта похожим на поломку.

**Решение.** Не ослаблять completion. Окно перемещается через Pointer
Capture и стрелки за отдельный заголовок; координаты только в sessionStorage,
ограничение экраном — чистая функция и ResizeObserver. Во время соединения
pointer-events карточки выключены. Ручная проверка сообщает оставшееся
условие, connect — конкретные порты. Escape меню обрабатывается раньше
глобального обработчика урока. Затемнение снижено до 35%.

**Последствия.** Схемы, прогресс и правила уроков не мигрируются. Начать
жест из-под окна нельзя — его нужно переместить/свернуть, но завершить
провод над закрытым портом теперь можно. Серверный сайт не развёртывается
автоматически этим изменением; 08B остаётся следующим подэтапом.


## ADR-018 — Одна панель на узком Canvas (0.5.37, 08B)

**Контекст.** Две постоянные панели по 280 px перекрывали узкий холст.
Скрывать функции или менять позиции схемы при resize нельзя.

**Решение.** Ниже 1024 px одна немодальная панель либо свободный холст;
временный `canvasPanel` в UI-store, DOM `hidden`, явные переключатели,
фокус/возврат и приоритет Escape. Вставка закрывает панель и использует
весь будущий холст. Дополнительные инструменты тулбара раскрываются ниже
1280 px, отладка прокручивается и ограничена по высоте. Учебная подсветка
показывает переключатель скрытой панели, не открывает её за пользователя.

**Последствия.** Нет миграции проекта/прогресса, новых зависимостей или
автоперераскладки. Настольный режим сохраняется. Порог одинаков в hook и
CSS. Это адаптация панелей; сенсорные жесты и полный мобильный курс не
объявляются проверенными на основании трёх E2E.
