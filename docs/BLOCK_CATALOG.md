## 1. Статусы определений

Каждое определение несёт статус (поле `status`, назад совместимое; вывод —
`effectiveStatus()` реестра):

| Статус | Значение |
|---|---|
| `implemented` (РЕАЛИЗОВАНО) | есть исполняемый код (`runtime`), деталь доступна в палитре |
| ПОКРЫТО ТЕСТАМИ | реализовано и непосредственно исполняется автотестами (уточнение к РЕАЛИЗОВАНО) |
| `planned` (ЗАПЛАНИРОВАНО) | определение и контракт портов зафиксированы, исполнение не реализовано; скрыто из палитры (`available: false`) |
| `prototype` | черновая реализация, поведение может меняться |
| `experimental` | работает, но контракт нестабилен |
| `deprecated` | устарело, будет убрано в следующих версиях |
| СЛУЖЕБНОЕ | не в палитре; вставляется особым действием (стикер) |

**Факт на дату (09B4, 0.5.42):** зарегистрировано
**165** определений — **93 в палитре** (все с исполняемым кодом; девять Web UI-элементов
дополнительно проверены runtime и E2E), **71 запланированное определение** (скрыты из
палитры) и **1 служебное** (стикер-заметка, тоже скрыт из палитры).
Целевая библиотека Этапа 4 — 16 категорий × 10+ блоков (160+ определений,
[04-BLOCK-LIBRARY.md](agent-plan/04-BLOCK-LIBRARY.md)) — **достигнута и
подтверждена автотестом** `src/blocks/library-catalog.test.ts`.
Запланированная деталь — это определение и место в каталоге; она **не** считается реализованной.

## 19. Механизмы библиотеки

- **Основные / Продвинутые**: у каждой детали поле `difficulty`
  (`basic`/`advanced`); вкладка «Основные» показывает только `basic`,
  «Все» — все доступные.
- **Поиск**: `matchesQuery()` ищет по русскому названию, описанию,
  идентификатору и `keywords`; новые детали участвуют автоматически.
- **Быстрая вставка**: кандидаты строятся функцией `quickInsertCandidates()`
  из общего реестра и системы типов портов — без отдельных каталогов.
- **Автотест каталога**: `src/blocks/library-catalog.test.ts` — уникальные
  ID, корректные порты и типы, статусы, сложность, русские названия,
  поиск и быстрая вставка. Полный порог «16 × 10+» добавляется в части H.

Правило добавления блока и контракт `BlockDefinition` — [BLOCKS.md](BLOCKS.md).
