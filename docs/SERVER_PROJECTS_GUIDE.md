# Серверные проекты — практика для пользователя (0.5.48)

## Три разных действия

| Действие | Где сохраняются последующие правки | Что меняется |
|---|---|---|
| Открыть обычную карточку проекта | В этом браузере | Локальный проект |
| «Сохранить новую серверную копию» | Пока нигде автоматически | Создаётся ещё один серверный проект |
| «Открыть на сервере» | В выбранном серверном проекте | Тот же черновик, с проверкой ревизии |

«Создать локальную копию» из серверного списка создаёт отдельный локальный
проект с новым ID. Он не связан автосинхронизацией с оригиналом. Учебные
песочницы нельзя открыть/перенести как серверный редактор: сначала явно
преобразуйте их в обычный проект, если это действительно нужно.

## Упражнение 1. Сохранение и другое устройство

1. В обычном Canvas дождитесь «Сохранено», вернитесь к проектам.
2. Войдите/зарегистрируйтесь, явно выберите рабочее пространство.
3. Выберите локальный проект → «Сохранить новую серверную копию».
4. У созданной серверной карточки нажмите **«Открыть на сервере»**.
   Над Canvas должна появиться полоса **«Серверный редактор»**.
5. Переименуйте проект или измените настройку детали. Пройдут состояния
   «Есть несохранённые правки» → «Сохраняем на сервер…» → **«Сохранено на сервере»**.
   Можно ускорить отправку кнопкой «Сохранить сейчас».
6. Нажмите F5. Проверьте имя/схему. В другом браузере войдите в тот же аккаунт,
   выберите пространство и откройте тот же серверный проект — правка доступна.

Сохранение работает и внутри модели: отправляется весь проект вместе с
обновлённой внутренней схемой, а не только открытый фрагмент.

## Упражнение 2. Две вкладки и конфликт

Используйте отдельный тестовый проект, не рабочий бот.

1. Откройте один серверный проект в двух вкладках.
2. В первой измените имя и дождитесь подтверждения.
3. Во второй сделайте свою правку. Её старая база будет отклонена:
   «Автосохранение приостановлено». При возвращении фокуса проверка контекста
   может приостановить отправку ещё раньше — это не потеря данных.
4. Нажмите «Проверить сервер». Это чтение, не автоматическая перезапись.
5. Выберите один вариант:
   - **«Сохранить локальную копию»** — оставить свои правки отдельным проектом;
   - **«Принять серверную версию»** — заменить редактор просмотренным документом;
   - **«Отправить мои правки вместо этой версии»** — осознанно заменить
     просмотренную версию целиком, после подтверждения.
6. Даже после подтверждения новые изменения другой вкладки защищены: если
   сервер успел измениться снова, получите новый конфликт, не молчаливую потерю.

Это не совместный редактор реального времени и не автоматическое слияние.
Перед заменой всей схемы рекомендуется сохранить отдельную копию.

## Упражнение 3. Сбой сети и резерв

1. В тестовом проекте временно отключите сеть браузера и внесите правку.
2. После ошибки не нажимайте бесконечно «Сохранить». Автоповтор остановлен.
3. Верните сеть и нажмите «Проверить сервер». Если сервер уже принял именно
   ваши данные, подтверждение восстановится без второго PUT. Иначе выберите
   действие после просмотра серверной версии.
4. При перезагрузке/повторном открытии найденный резерв предлагается явно:
   **«Восстановить черновик»** не отправляет его автоматически. После него
   снова нужно проверить сервер и выбрать действие.
5. Старые резервы не удаляются вместе с чужой вкладкой. Их можно удалить
   явно на экране выбора. Записи, совпадающие по содержимому с сервером,
   не предлагаются как несохранённые правки.

Каждый открытый редактор пишет отдельный резерв в LocalStorage. Он переживает
F5/обычное закрытие браузера, пока хранилище не очищено/не вытеснено. Это не
облачная резервная копия: он не переносится на другое устройство, не защищён
от очистки браузера и не шифруется. Список фильтруется по подтверждённому
аккаунту, но хранилище общего компьютера не является границей безопасности.

## Если проект удалён или доступ отозван

Пока редактор открыт, сохраните свои правки локальной копией. Если уже
перезагрузили страницу: войдите в исходный аккаунт и откройте прежний URL
проекта. При недоступности проекта найденные резервы этого аккаунта можно
экспортировать отдельной локальной копией — серверный проект не воскресает.
Без подтверждения аккаунта резерв не показывается; при недоступном API
открытие нового серверного редактора недоступно. Обычные локальные проекты
продолжают работать автономно.

## Безопасный выход

При несохранённых данных переход по ссылкам/кнопке Назад можно отменить.
При F5/закрытии браузер показывает стандартное предупреждение, если позволяет
его политика. HTTP-запрос на закрытии **не гарантируется**. Резерв пишется
при изменениях, а не в надежде успеть отправить данные в unload.

Если резервное хранилище заполнено/недоступно, появляется отдельное
предупреждение. Не уходите, пока правки не подтверждены сервером или не
сохранены локальной копией. В таком состоянии подтверждение ухода прямо
предупреждает о риске потери данных.

## Что это не делает

Сохранение черновика не публикует LIVE и не переносит Vault/ботов/версии.
Кнопка «Запустить» — прежний симулятор. Нет автоматического merge, совместных
курсоров, offline-first открытия без проверки аккаунта или гарантированной
доставки Telegram. Для боевого аккаунта нужны HTTPS и корректный backend;
версия в GitHub сама по себе не обновляет сайт на VPS.
