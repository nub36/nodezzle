# Академия — критический QA и исправление (2026-09-14, версия 0.5.27)

Документ фиксирует результаты полного аудита цепочки «действие
пользователя → React Flow/сторы → движок урока» и введённые механизмы
защиты от регрессий. Продакшн обновляется владельцем самостоятельно:
рабочий коммит указан в конце документа.

## Найденный и исправленный баг

**Симптом**: урок «Знакомство с Canvas», шаг 4/5 «Выберите деталь
„Текст"»: клик по детали выделял её и открывал Инспектор, но шаг не
засчитывался — урок зависал.

**Корневая причина** (`src/academy/completion.ts`): правило
`select-block` сравнивало `snapshot.selectedBlockId` (это ТИП детали,
например `core.text` — снимок заполняется из `project-store`)
с идентификатором экземпляра узла на холсте (`node.id` вида `n1`).
Сравнение типа с экземпляром не совпадает никогда; Инспектор при этом
работал, потому что читает другой источник данных, и маскировал баг.

**Исправление**: `select-block` сверяет тип детали
(`snapshot.selectedBlockId === step.blockId`). Это не точечный фикс
одного `if`: вся цепочка клик → выделение → снимок → правило аудирована
и покрыта регрессионными и интеграционными тестами.

### Побочные находки аудита (тоже исправлены)

| Находка | Исправление |
| --- | --- |
| `connect` засчитывал соединение без ручек портов или с неверным портом | требуемые порты обязаны совпадать точно |
| `run`/`send-simulator-message` засчитывали старый запуск, сделанный до появления шага | требуется НОВОЕ выполнение (`run.at >= stepStartedAt`) |
| события для диагностики нигде не фиксировались | введён журнал нормализованных событий моста |

## Единый Completion Bridge

Второго параллельного рантайма нет: единственный источник истины —
сторы приложения, из которых собирается снимок
(`src/features/academy/snapshot.ts` → `AcademySnapshot`), а движок
(`src/academy/completion.ts`) проверяет шаг по снимку.

Нормализованные события (`src/academy/events.ts`, выводятся дифом двух
снимков, пишутся в журнал урока — `recentEvents`, последнее —
`lastEvent`):

| Событие | Данные |
| --- | --- |
| `BLOCK_ADDED` | nodeId, blockType |
| `BLOCK_REMOVED` | nodeId, blockType |
| `BLOCK_SELECTED` | nodeId, blockType |
| `CONNECTION_CREATED` | nodeId-концы, блок-типы и порты обоих концов |
| `BLOCK_CONFIG_CHANGED` | nodeId, blockType, ключ настройки |
| `EXECUTION_FINISHED` | executionId, status, source |
| `SIMULATOR_MESSAGE_SENT` | executionId, текст |
| `MODEL_CREATED` | modelId, blockType `models.call` |
| `DEBUG_OPENED` / `DEBUG_CLOSED` | — |
| `PAGE_OPENED` | route |

## Источники истины по типам шагов

| Тип шага | Источник истины | Событие/условие завершения | Семантика «уже выполнено» |
| --- | --- | --- | --- |
| `information` | интерфейс (кнопка «Понятно») | `acknowledge()` | — |
| `open-page` | роутер (`location.pathname`) | маршрут совпал | засчитывается по состоянию |
| `add-block` | `project-store.nodes` | деталь типа `blockId` на холсте | засчитывается по состоянию |
| `select-block` | `project-store.selectedNodeId` → тип детали | тип выбранной детали == `blockId` | засчитывается по состоянию |
| `connect` | `project-store.edges` | ребро нужных типов И портов, направление учтено | засчитывается по состоянию |
| `configure` | `config` узла в `project-store` | ключ заполнен (`notEmpty`) или равен `equals` | засчитывается по состоянию |
| `run` | `execution-store.history` | последнее выполнение успешно/завершено | **только НОВОЕ** после начала шага |
| `send-simulator-message` | `execution-store.history` + текст симулятора | успешный запуск с нужным `source` (+ подстрока) | **только НОВОЕ** после начала шага |
| `create-model` | узлы `models.call` | модель добавлена на холст | засчитывается по состоянию |
| `open-debug` | `tutorial-store.debugOpen` | панель отладки открыта | засчитывается по состоянию |
| `quiz` | интерфейс (варианты ответа) | верный вариант через `answerQuiz()` | — |

Неверное действие не засчитывается: выбор другой детали, соединение не
теми портами/деталями, старый запуск — все проверены тестами.

## Оверлей и навигация

- Затемнение — `pointer-events: none`, клики по холсту и библиотеке
  не блокируются; карточка урока — единственный перехватывающий элемент.
- Каждый шаг несёт `target` (валидируется: только известные зоны).
- Кнопка «Проверить шаг» (`tutorial-recheck`) — фолбэк: просто
  перевыполняет автоматическую проверку, автопроверка работает всегда.
- После последнего шага — экран «Урок завершён» с кнопками
  «Следующий урок» / «В Академию» / «Остаться» и «Повторить».
- Прогресс сохраняется в `localStorage`; перезагрузка страницы посреди
  урока восстанавливает тот же шаг (проверено тестом).

## Диагностика (только для разработки)

Добавьте `?academyDebug=1` к адресу: панель `tutorial-debug` показывает
урок, шаг, его тип и последнее событие моста с данными. В продуктовой
сборке панель не нужна — включается только параметром адреса.

## Браузерный E2E: статус выполнения

**2026-09-14, версия 0.5.29: 11/11 браузерных тестов реально пройдены в
этой сессии**, Chromium 153.0.8010.0 + Playwright. Прямое скачивание с CDN
по-прежнему завершалось `ECONNRESET`. Для прогона использована внешняя
установка `@sparticuz/chromium` (не зависимость проекта, не входит в Git).
В конфиг добавлен необязательный `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

Обычный локальный запуск:

```bash
npm run test:e2e:install
npm run test:e2e
```

Для подготовленного системного Chromium:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/path/to/chromium npm run test:e2e
```

В этой среде дополнительно требовался `LD_LIBRARY_PATH=/tmp/al2023/lib`
для библиотек внешней сборки; эти временные пути не являются частью продукта.

### Что выявил фактический браузерный запуск

- Старые E2E пытались открыть заблокированный урок, очищали LocalStorage
  при F5, искали неверное имя конвертера и сворачивали уже раскрытые
  категории. Фикстуры исправлены: prerequisites заданы, F5 сохраняет
  прогресс, поиск по реальному ID, соединяемые детали раздвигаются
  пользовательским перетаскиванием.
- В продукте шаг выбора проскакивал из-за автовыделения вставленного узла.
  Подготовка учебного шага снимает это выделение один раз до автопроверки.
- Абсолютные маркеры портов накладывались; теперь каждый находится в
  своей строке, обе колонки независимы.

## 07B1 — конвертеры и эхо-бот (0.5.30)

**Реальный прогон 2026-09-14: 14/14 E2E, 402/402 unit/integration
(53 файла), typecheck и build успешны.** Окружение браузера — то же,
Chromium 153.0.8010.0, внешний путь через переменную конфигурации.

`e2e/practice-lessons.spec.ts` добавляет три сценария:

1. Конвертеры — каждый шаг, отклонение значения «41», текст «42» на входе,
   число 42 на выходе и в логе; закрытие панели/неверная вкладка не
   завершают просмотр; правильная вкладка завершает урок, прогресс переживает F5.
2. Эхо-бот — каждый шаг, неправильный совместимый `user_id` не принимается
   за `chat_id`; после переподключения ответ содержит точный текст и ID
   заданного чата; викторина отвергает хранение токена в проекте.
3. Конвертеры после F5 — схема с двумя связями и значение восстановлены;
   «не число» вызывает ошибку без завершения шага; исправление на «42»
   даёт успешный результат и позволяет завершить урок.

Все действия — клики, ввод и перетаскивания, без подмены снимков или
результатов выполнения. В фикстуре задаются только завершённые предпосылки,
но не целевой урок. Результаты читаются из отрисованных портов и outbox-чата.

**До исправления** первые два сценария падали на шаге просмотра:
конвертеры сразу показывали «Урок завершён», эхо-бот переходил к викторине.
Причина — `debugOpen === true` у уже открытого симулятора и автопереключение
вкладки наблюдателем. Исправление: необязательный `tab`, его проверка и
отключение автопоказа для такого шага. `debug-step.test.ts` покрывает
правило, старое поведение, валидатор, снимок, мост событий и перепроверку.

Подсветка проверена по геометрии: кнопка 🐞 при закрытой панели, вкладка
чата при открытой. Новые стабильные маркеры: `debug-tab-*`, `debug-toggle`,
`debug-node-<blockId>` с ID экземпляра, `input-<port>` / `output-<port>`,
`simulator-chat-user`, `simulator-chat-bot`, `tutorial-highlight`.

**Граница покрытия на 0.5.30:** весь 07B ещё не завершён. Продолжение
с условиями и командами Telegram описано ниже; затем веб, модели и отладка.
Доступная вкладка — проверяемое состояние, а не доказательство того, что
человек прочёл данные; нового клика при уже открытой нужной вкладке правило
не требует. Ошибочный запуск при этом проверяется отдельным шагом `run`.


## 07B2 — условия и команды Telegram (0.5.31)

**Реальный прогон 2026-09-14: 17/17 E2E (1 минута), 412/412 unit/integration
(54 файла), typecheck, проверка типов E2E и build успешны.** Браузер —
внешний Chromium, прежняя конфигурация; новых зависимостей нет.

`e2e/branches-commands.spec.ts` проходит через реальный UI:

1. Условие: неверные оператор/пустая цель не принимаются; подключение
   «Нет» вместо «Да» не завершает шаг. Ошибочная связь отменяется кнопкой
   undo. Сообщение «добрый день» даёт только `false`, лог не получает
   входа и задание остаётся. Простая правка текста не засчитывается;
   новый запуск с «привет, NODEZZLE» даёт `true` и тот же текст в логе.
   Проверены оба ответа викторины и сохранение завершения после F5.
2. Команда: готовая настройка /start принимается автоматически; `args`
   не заменяет требуемый `command`, неверная связь отменяется. /help не
   даёт ответа и не завершает шаг; /start даёт ровно один ответ /start
   в чат 13579. «Порты» не заменяют просмотр «Чата Telegram».
3. Подмена настройки: /help в самой детали вместе с /help в симуляторе
   действительно отправляет /help, но цель урока не выполнена. F5
   сохраняет две связи, настройку и шаг; исправление на /start и новый
   запуск позволяют завершить урок. Завершение тоже сохраняется после F5.

Общая подготовка вынесена в `e2e/lesson-helpers.ts`: задаются только
предпосылки, целевой урок не подменяется. Узлы раздвигаются мышью, связи
создаются через порты; результаты читаются из отрисованных портов/чата.

**Красные проверки до исправления:** условие переходило к викторине при
`false`; команда сразу завершала урок вместо шага просмотра чата.
Исправлены требования выходов `expectedOutputs` и `open-debug.tab` у
команды. Дополнительно исключена подмена результатов изменённой формой:
источник/текст записываются при запуске, выходы связаны с ID исполнения.
Десять новых тестов в `run-evidence.test.ts` проверяют также пропущенные,
ошибочные, устаревшие и допустимые ложные/нулевые значения.

Инструкции используют реальные названия «Да»/«Нет», «Сравнивать с»,
предупреждают о регистре и отдельном поле команды. Существующее значение
/start не требует искусственного клика. ID/число/порядок шагов не менялись.

**Граница покрытия:** полный браузерный обход есть у пяти интерактивных
уроков: Canvas, конвертеры, эхо-бот, условия, команды. Все 12 имеют
статическую валидацию и синтетический обход снимков, но это не полный E2E
курса. 07B остаётся открытым; следующий 07B3 — веб, модели и отладка.
