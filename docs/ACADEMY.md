# Академия NODEZZLE — движок, уроки и обучение

Академия — встроенное обучение продукту на русском языке. Ключевой
принцип: **урок — это данные, а не код**. Интерфейс, движок и
проверки универсальны; содержание уроков живёт в каталоге и
словарях локализации, поэтому новый урок добавляется без правки
движка.

> Статус частей подэтапа 5.11: движок (5.11A), интерфейс Академии и
> песочницы (5.11B), Tutorial Overlay (5.11C), базовый курс из 12
> уроков (5.11D + 5.11H), справочник деталей (5.11E), поиск помощи
> (5.11F), онбординг первого запуска (5.11G) и финальный аудит (5.11H)
> — **реализованы. Подэтап 5.11 закрыт.**

## Архитектура

```
src/academy/
  types.ts            — типы: урок, 12 типов шагов, снимок состояния, прогресс
  completion.ts       — чистая проверка шага по снимку (без React и DOM)
  validate.ts         — валидация урока/каталога относительно живого реестра
  progress.ts         — состояние прогресса + абстракция хранилища
  catalog.ts          — каталог уроков (наполняется данными, не хардкодом)
  lessons/base-course.ts — базовый курс «с нуля», 10 интерактивных уроков
  reference.ts        — справочник деталей: строится из реестра, фильтры/поиск
  search.ts           — поиск помощи, контекстные подсказки, «ошибки как обучение»
  catalog.test.ts, academy-engine.test.ts, reference.test.ts — тесты
src/store/
  tutorial-store.ts   — активный урок: шаг, подсказки, запись запусков
  academy-store.ts    — прогресс Академии (начат/завершён, проценты)
src/features/academy/
  AcademyPage.tsx     — раздел «Академия» (уровни, дорожки, поиск помощи)
  BlockReferencePage.tsx — справочник деталей (/academy/reference)
  GlossaryPage.tsx    — глоссарий терминов (/academy/glossary)
  OnboardingModal.tsx — онбординг первого запуска
  LessonPage.tsx      — карточка урока: шаги, требования, «Продолжить»
  TutorialWatcher.tsx — связывает урок с живым состоянием продукта
  TutorialOverlay.tsx — подсветка зон и карточка текущего шага
  snapshot.ts         — снимок состояния продукта для проверок
```

Маршруты: `/academy` (список) и `/academy/lesson/:lessonId`
(карточка). Урок запускается переходом в учебный проект со
ссылкой вида `/projects/<id>?lesson=<lessonId>`.

## Формат урока (данные)

```ts
interface LessonDefinition {
  id: string;                 // уникальный, без точек (ключи i18n)
  level: 1..9;                // уровень обучения
  track: 'basics' | 'telegram' | 'web' | 'models' | 'debug' | 'publish' | 'advanced';
  titleKey / descriptionKey;  // только i18n-ключи
  estimatedMinutes?: number;
  difficulty?: 'basic' | 'advanced';
  prerequisites: string[];    // другие уроки (без циклов — валидируется)
  sandbox?: boolean;          // нужен ли учебный проект
  relatedBlockIds?: string[]; // перекрёстные ссылки из справочника
  plannedNoteKey?: string;    // честная пометка о незавершённых функциях
  steps: LessonStep[];        // шаги по порядку
}
```

Весь пользовательский текст — только через ключи
`academy.lessons.<id>...` в `src/i18n/locales/ru.json`. Тест
каталога падает, если у шага нет текста, подсказки или вариантов
викторины.

## 12 типов шагов и их автопроверка

Проверка выполняется чистой функцией `evaluateStep(step, snapshot)`
(`completion.ts`) по снимку `AcademySnapshot` — составу схемы,
соединениям, выбранной детали, последнему запуску, открытости панели
отладки и маршруту. Никаких «Я сделал»: шаг засчитывается только по
фактическому состоянию продукта.

| Тип | Что требует | Проверка |
|---|---|---|
| `information` | прочитать | `acknowledge()` пользователем |
| `open-page` | перейти | маршрут начался с `route` |
| `add-block` | добавить деталь | блок `blockId` есть в узлах схемы |
| `connect` | соединить порты | ребро между блоками (+ опц. порты) |
| `configure` | настроить | `config[key]` равен значению / не пуст |
| `run` | запустить | последний запуск успешен (или завершён) |
| `send-simulator-message` | запустить из симулятора | запуск успешен, источник совпал, текст содержит подстроку (опц.) |
| `select-block` | выбрать деталь | выбран узел типа `blockId` |
| `create-model` | создать модель | появился узел «Вызов модели» |
| `open-debug` | открыть панель/вкладку | панель открыта; если задан `tab`, совпадает и вкладка |
| `publish-preview` | посмотреть публикацию | `acknowledge()` + честный статус в тексте |
| `quiz` | ответить | выбран правильный вариант |

У шага может быть `target` — зона интерфейса для подсветки
(`library`, `canvas`, `inspector`, `run`, `debug`, `simulator`,
`chat`, `history`, `toolbar`).

### Источник запуска

`TutorialWatcher` запоминает фактический источник завершения
запуска через `effectiveRunSource`: если на холсте триггеры только
веб (или только телеграм), исполнение идёт этим источником
независимо от настроек симулятора — проверка источника в шагах
`run`/`send-simulator-message` остаётся честной.

## Валидация каталога

`validateCatalog(lessons, blockRegistry)` запускается тестом и при
открытии Академии:

- каждый `blockId` в шагах и `relatedBlockIds` обязан существовать
  в **живом реестре блоков** — битые ссылки невозможны;
- идентификаторы уроков и шагов уникальны, уровень 1–9;
- у викторины минимум два варианта и есть правильный ответ;
- `prerequisites` ссылаются на существующие уроки, циклов нет;
- `configure`-шаг всегда с условием (`equals` или `notEmpty`).

## Прогресс

`progress.ts` — чистые функции поверх структуры `AcademyProgress`
(начатые/завершённые уроки, текущий шаг, проценты). Хранилище —
абстракция `AcademyStorage`; сейчас `createLocalStorageProgress()`,
при появлении сервера добавится реализация поверх АПИ без правки
движка. Функции: `startLesson`, `advanceLesson`, `resetLesson`
(«Начать заново» сбрасывает только учебное состояние),
`lessonPercent`, `levelPercent`, `totalPercent`, `isLessonAvailable`
(по `prerequisites`), `nextLesson`.

## Tutorial Overlay

`TutorialOverlay` рисует:

- **подсветку цели**: элемент размечен атрибутом `data-tutorial`
  (библиотека, холст, инспектор, «Запустить», панель отладки и её
  вкладки); цель выделяется тенью-маской вокруг без блокировки
  остального интерфейса — пользователя никогда не запирают в уроке;
- **карточку шага**: заголовок, текст, подсказка (по кнопке и
  автоматически через 25 с бездействия), викторина с локальным
  сообщением «неверно», «Прервать урок» с подтверждением,
  экран «Урок завершён» с переходом в Академию;
- клавиатура: `Esc` прерывает урок; анимации уважают
  `prefers-reduced-motion`; карточка объявлена `aria-live`.

Песочница: учебный проект помечен `meta.tutorial`, создаётся
отдельно (`createSandboxProject`) и не трогает реальные проекты; в
конце его можно сохранить, удалить или отвязать от урока
(`detachSandbox`).

## Курс (5.11D + 5.11H)

12 уроков, только реальные функции продукта:

1. `intro-what` — что такое деталь, INPUT/OUTPUT, поток данных (викторины);
2. `intro-canvas` — зоны холста, первая деталь, инспектор;
3. `basics-ports` — входы/выходы, форма маркеров (данные/событие/ошибка);
4. `basics-chain` — первая цепочка триггер → лог и первый запуск;
5. `logic-condition` — ветвление по условию «содержит»;
6. `data-converters` — типы и конвертер «Текст → Число»;
7. `telegram-first-bot` — бот-эхо в симуляторе, токен не нужен;
8. `telegram-command` — триггер «Команда» и ответ на `/start`;
9. `web-first-page` — веб-события и кнопка (честная пометка:
   элементы оформления страницы запланированы);
10. `models-first-model` — «Создать модель из выделенного», спуск внутрь;
11. `debug-why-not-working` — панель отладки: журнал, порты, история;
12. `publish-versions` — Черновик и LIVE: серверная публикация через API
    реализована, визуальный переключатель холста не загружает LIVE-документ.

Дорожки: основы, Телеграм (симулятор), Веб (превью), Модели,
Отладка, Публикация. Дальнейшие уроки (продвинутые темы уровня 9)
добавляются по мере готовности функций — со **честными статусами**
(`plannedNoteKey`), без обучения несуществующему как работающему.

Уроки без песочницы (`sandbox: false`, напр. знакомство и публикация)
идут на странице Академии: наблюдатель и оверлей смонтированы на уровне
приложения, учебный проект для них не создаётся.

## Как добавить урок

1. Опишите данные в `src/academy/lessons/base-course.ts` (или новом
   массиве, подключённом в `catalog.ts`): id без точек, шаги с
   нужными типами, `blockId` — только существующие в реестре.
2. Добавьте тексты в `src/i18n/locales/ru.json` →
   `academy.lessons.<id>`: `title`, `description`, `steps.<stepId>`
   с `title`/`text`, при необходимости `details`, `hint`, `question` и варианты.
   `detailsKey` в шаге ссылается на дополнительную теорию; основной текст
   содержит короткое действие, без обязательных условий в скрытом блоке.
3. Прогоните тесты каталога (`npx vitest run src/academy`): они
   проверят реестр, уникальность, зависимости и наличие **каждого**
   ключа текста.

## Справочник деталей (5.11E)

Маршрут `/academy/reference`, вход из Академии («📚 Справочник»)
и кнопка «?» у каждой детали в библиотеке и инспекторе (открывает
карточку с `?block=<id>`).

- строится автоматически из живого реестра (`buildReference`) —
  второго списка деталей не существует; каждая запись несёт статус
  (`effectiveStatus`), сложность, категорию, порты (вход/выход,
  вид и тип) и связанные уроки (`lessonsForBlock`);
- фильтры: категория, сложность, статус + поиск по названию,
  описанию, id и ключевым словам (`filterReference` — чистая функция,
  переиспользуется далее в поиске помощи);
- запланированные детали помечены явно: бейдж «Запланировано» и
  предупреждение в карточке;
- карточки раскрываются нативным `details/summary` (доступно с
  клавиатуры).

## Поиск помощи и контекстная помощь (5.11F)

`src/academy/search.ts` — чистые функции:

- `buildHelpIndex` + `searchHelp` — единый поиск по урокам и деталям
  (название, описание, id, ключевые слова; приоритет — начало
  названия). Встроен в страницу Академии: результаты ведут на урок
  или карточку справочника.
- `contextHelp` — подсказки на Canvas по ситуации: пустой холст →
  урок про Canvas; схема не запускалась или упала с ошибкой →
  урок первой цепочки; выбрана деталь → справочник. Показываются в
  панели «?» тулбара (нативный `details`, доступен с клавиатуры).
- «Ошибки как обучение»: `lessonForErrorCode`/`helpRouteForError`
  сопоставляют код ошибки рантайма с существующим уроком (типы
  данных, цикл, триггеры, модели); у записей `ERR_*` в журнале
  отладки появляется ссылка «Как исправить?». Неизвестные коды
  ведут в справочник — честный фолбэк.

## Критический QA и Completion Bridge (0.5.27)

Полный аудит цепочки «действие → сторы → снимок → правило» описан в
[ACADEMY_QA.md](ACADEMY_QA.md). Ключевое:

- Правило `select-block` сверяет **тип** детали (`core.text`), а не
  экземпляр узла — это чинит зависание шага 4/5 урока «Знакомство
  с Canvas».
- `src/academy/events.ts` — Completion Bridge: нормализованные события
  (детали, соединения, настройки, исполнения, симулятор, модели,
  отладка, маршруты) выводятся дифом снимков и пишутся в журнал урока;
  второго рантайма нет.
- Шаги «запустить» требуют НОВОГО выполнения после появления шага.
- `validate-deep.ts` статически отклоняет невозможные уроки (нет
  детали/порта/настройки/маршрута; холстовые шаги в уроках без
  песочницы). `lesson-walkthrough.test.ts` обязан пройти каждый шаг
  всех 12 уроков.
- Браузерный E2E: `npm run test:e2e` (Playwright, 4 сценария по
  `data-testid`); диагностика `?academyDebug=1`; фолбэк «Проверить
  шаг» (`tutorial-recheck`).

## Просмотр результатов без пропуска шага (0.5.30, 07B1)

`OpenDebugStep.tab?: DebugPanelTab` задаёт конкретную вкладку. Сейчас
это `ports` у конвертеров и `chat` у эхо-бота (с 0.5.31 — также у команд). `AcademySnapshot.debugTab`
берётся из `execution-store.panelTab`; наблюдатель проверяет шаг при её
изменении. Без `tab` старое правило «панель открыта» сохранено.

Для шага с `tab` подсветка больше **не открывает панель и не переключает
вкладку за пользователя**. Уже открытая нужная вкладка удовлетворяет
правилу: нового клика не требуется. Проверка самого содержимого результата
не добавляет второй рантайм — её выполняют E2E на реальном UI.

Цели `simulator`, `chat`, `history` разрешаются в маркеры `tab-*`. Если
панель закрыта, подсвечивается кнопка её открытия. Смена вкладки видна
в диагностике Completion Bridge как `DEBUG_TAB_CHANGED`.

Каталог конвертеров теперь явно задаёт ID обоих портов каждого соединения.
ID, порядок и количество шагов, формат проекта v1 и сохранённый прогресс
не менялись. Инструкции двух уроков уточнены, компактная подача сохранена.


## Проверка выходов запуска (0.5.31, 07B2)

Шаги `run` и `send-simulator-message` поддерживают необязательное
`expectedOutputs: Array<{ blockId, portId, equals? }>`. Каждый элемент
требует соответствующий выход хотя бы одной успешно выполненной детали
нужного типа. Без `equals` достаточно определённого собственного значения
порта, включая `0`, `false`, пустую строку и `null`; с `equals` сравнение
точное, через JSON, без приведения типов. Отсутствующие/унаследованные
порты, `undefined` и выходы неуспешных деталей не подходят. Это дополнение
к проверке времени, статуса и источника, не их замена.

- `logic-condition`: нужны `logic.condition.true` и `debug.log.value`.
  Общий успех схемы при выходе «Нет» больше не завершает задание.
- `telegram-command`: нужны `telegram.command.command === '/start'` и
  `telegram.send_message.message_id`. Ответ по другой настроенной команде
  не подменяет цель урока; просмотр ответа требует `open-debug.tab = chat`.
- Валидаторы проверяют ссылки на детали и выходные порты, а также
  отклоняют явно пустой список требований. Старые шаги без требований
  сохраняют прежнее поведение; другие уроки будут адаптироваться отдельно.

`AcademySnapshot.lastRun.results` строится из фактических `nodeInfo`, только
если их `nodeInfoRunId` совпадает с последней записью истории и схема не
выполняется. При начале запуска и сбросе ID очищается. В истории хранятся
фактические источник и текст, зафиксированные до исполнения, а не текущие
поля формы/наблюдателя. Изменение настройки без нового запуска не меняет
полученные выходы. Данные исполнения остаются временными: в документ
проекта v1 и сохранённый прогресс они не добавляются.

Это проверка наличия выходов по типам деталей, не отдельный анализ
происхождения каждого значения. Конкретные соединения проверяются своими
шагами; фактические значения, ветка и адресат проверены также в E2E.
Десять unit/integration в `run-evidence.test.ts` покрывают правило,
валидаторы, адаптер, сброс/устаревшие результаты и реальное выполнение.


## Веб, модели и отладка (0.5.32, 07B3)

- Веб-урок требует выход `web.button.data` и `debug.log.value`. Явное
  событие загрузки не считается кликом; можно отправить JSON с
  `event: "button_click"` в симуляторе либо нажать кнопку в превью.
  Финальный просмотр требует вкладку «Порты».
- `create-model` проверяет `config.modelId` узла вызова по
  `AcademySnapshot.modelIds` — это ID существующих моделей текущего
  проекта. Просто добавить ненастроенный «Вызов модели» недостаточно.
  Созданная модель может иметь пустой контракт: в уроке нет внешних связей.
- Запуск модели требует успешный `models.call.result`; запуск отладки —
  значение `debug.log.value`. Ошибка внутреннего выполнения теперь
  делает вызов неуспешным и не завершает учебный шаг.
- В отладке `open-debug` требует «Журнал», а прежние информационные
  `ports-tab` и `history-tab` стали `open-debug` с соответствующим `tab`.
  Нажать «Понятно» вместо просмотра нельзя. ID, индексы и число шагов
  сохранены, существующий прогресс продолжает работать без миграции.
- `TutorialWatcher` наблюдает ID последнего исполнения, не длину истории,
  ограниченной 30 записями. Проверка 31-го запуска пройдена через UI.

Инструкция по моделям использует фактический Ctrl/Cmd для множественного
выбора. «Спуск внутрь» остаётся информационным шагом с подтверждением;
E2E отдельно выполняет двойной клик и проверяет две детали и их связь.
Просмотр локальной истории не выдаётся за серверную публикацию/исполнение.
