# Академия NODEZZLE — движок, уроки и обучение

Академия — встроенное обучение продукту на русском языке. Ключевой
принцип: **урок — это данные, а не код**. Интерфейс, движок и
проверки универсальны; содержание уроков живёт в каталоге и
словарях локализации, поэтому новый урок добавляется без правки
движка.

> Статус частей подэтапа 5.11: движок (5.11A), интерфейс Академии и
> песочницы (5.11B), Tutorial Overlay (5.11C), базовый курс из 10
> уроков (5.11D) и справочник деталей (5.11E) — **реализованы**.
> Глобальный поиск помощи (5.11F), онбординг первого запуска (5.11G)
> — далее, не выдаются за готовые.

## Архитектура

```
src/academy/
  types.ts            — типы: урок, 12 типов шагов, снимок состояния, прогресс
  completion.ts       — чистая проверка шага по снимку (без React и DOM)
  validate.ts         — валидация урока/каталога относительно живого реестра
  progress.ts         — состояние прогресса + абстракция хранилища
  catalog.ts          — каталог уроков (наполняется данными, не хардкодом)
  lessons/base-course.ts — базовый курс «с нуля», 10 интерактивных уроков
  reference.ts        — справочник деталей: строится из реестра, фильтры/поиск
  catalog.test.ts, academy-engine.test.ts, reference.test.ts — тесты
src/store/
  tutorial-store.ts   — активный урок: шаг, подсказки, запись запусков
  academy-store.ts    — прогресс Академии (начат/завершён, проценты)
src/features/academy/
  AcademyPage.tsx     — раздел «Академия» (уровни, дорожки, прогресс)
  BlockReferencePage.tsx — справочник деталей (/academy/reference)
  LessonPage.tsx      — карточка урока: шаги, требования, «Продолжить»
  TutorialWatcher.tsx — связывает урок с живым состоянием продукта
  TutorialOverlay.tsx — подсветка зон и карточка текущего шага
  snapshot.ts         — снимок состояния продукта для проверок
```

Маршруты: `/academy` (список) и `/academy/lesson/:lessonId`
(карточка). Урок запускается переходом в учебный проект со
ссылкой вида `/projects/<id>?lesson=<lessonId>`.

## Формат урока (данные)

```ts
interface LessonDefinition {
  id: string;                 // уникальный, без точек (ключи i18n)
  level: 1..9;                // уровень обучения
  track: 'basics' | 'telegram' | 'web' | 'models' | 'debug' | 'publish' | 'advanced';
  titleKey / descriptionKey;  // только i18n-ключи
  estimatedMinutes?: number;
  difficulty?: 'basic' | 'advanced';
  prerequisites: string[];    // другие уроки (без циклов — валидируется)
  sandbox?: boolean;          // нужен ли учебный проект
  relatedBlockIds?: string[]; // перекрёстные ссылки из справочника
  plannedNoteKey?: string;    // честная пометка о незавершённых функциях
  steps: LessonStep[];        // шаги по порядку
}
```

Весь пользовательский текст — только через ключи
`academy.lessons.<id>...` в `src/i18n/locales/ru.json`. Тест
каталога падает, если у шага нет текста, подсказки или вариантов
викторины.

## 12 типов шагов и их автопроверка

Проверка выполняется чистой функцией `evaluateStep(step, snapshot)`
(`completion.ts`) по снимку `AcademySnapshot` — составу схемы,
соединениям, выбранной детали, последнему запуску, открытости панели
отладки и маршруту. Никаких «Я сделал»: шаг засчитывается только по
фактическому состоянию продукта.

| Тип | Что требует | Проверка |
|---|---|---|
| `information` | прочитать | `acknowledge()` пользователем |
| `open-page` | перейти | маршрут начался с `route` |
| `add-block` | добавить деталь | блок `blockId` есть в узлах схемы |
| `connect` | соединить порты | ребро между блоками (+ опц. порты) |
| `configure` | настроить | `config[key]` равен значению / не пуст |
| `run` | запустить | последний запуск успешен (или завершён) |
| `send-simulator-message` | запустить из симулятора | запуск успешен, источник совпал, текст содержит подстроку (опц.) |
| `select-block` | выбрать деталь | выбран узел типа `blockId` |
| `create-model` | создать модель | появился узел «Вызов модели» |
| `open-debug` | открыть панель | панель отладки открыта |
| `publish-preview` | посмотреть публикацию | `acknowledge()` + честный статус в тексте |
| `quiz` | ответить | выбран правильный вариант |

У шага может быть `target` — зона интерфейса для подсветки
(`library`, `canvas`, `inspector`, `run`, `debug`, `simulator`,
`chat`, `history`, `toolbar`).

### Источник запуска

`TutorialWatcher` запоминает фактический источник завершения
запуска через `effectiveRunSource`: если на холсте триггеры только
веб (или только телеграм), исполнение идёт этим источником
независимо от настроек симулятора — проверка источника в шагах
`run`/`send-simulator-message` остаётся честной.

## Валидация каталога

`validateCatalog(lessons, blockRegistry)` запускается тестом и при
открытии Академии:

- каждый `blockId` в шагах и `relatedBlockIds` обязан существовать
  в **живом реестре блоков** — битые ссылки невозможны;
- идентификаторы уроков и шагов уникальны, уровень 1–9;
- у викторины минимум два варианта и есть правильный ответ;
- `prerequisites` ссылаются на существующие уроки, циклов нет;
- `configure`-шаг всегда с условием (`equals` или `notEmpty`).

## Прогресс

`progress.ts` — чистые функции поверх структуры `AcademyProgress`
(начатые/завершённые уроки, текущий шаг, проценты). Хранилище —
абстракция `AcademyStorage`; сейчас `createLocalStorageProgress()`,
при появлении сервера добавится реализация поверх АПИ без правки
движка. Функции: `startLesson`, `advanceLesson`, `resetLesson`
(«Начать заново» сбрасывает только учебное состояние),
`lessonPercent`, `levelPercent`, `totalPercent`, `isLessonAvailable`
(по `prerequisites`), `nextLesson`.

## Tutorial Overlay

`TutorialOverlay` рисует:

- **подсветку цели**: элемент размечен атрибутом `data-tutorial`
  (библиотека, холст, инспектор, «Запустить», панель отладки и её
  вкладки); цель выделяется тенью-маской вокруг без блокировки
  остального интерфейса — пользователя никогда не запирают в уроке;
- **карточку шага**: заголовок, текст, подсказка (по кнопке и
  автоматически через 25 с бездействия), викторина с локальным
  сообщением «неверно», «Прервать урок» с подтверждением,
  экран «Урок завершён» с переходом в Академию;
- клавиатура: `Esc` прерывает урок; анимации уважают
  `prefers-reduced-motion`; карточка объявлена `aria-live`.

Песочница: учебный проект помечен `meta.tutorial`, создаётся
отдельно (`createSandboxProject`) и не трогает реальные проекты; в
конце его можно сохранить, удалить или отвязать от урока
(`detachSandbox`).

## Базовый курс (5.11D)

10 уроков, только реальные функции продукта:

1. `intro-what` — что такое деталь, INPUT/OUTPUT, поток данных (викторины);
2. `intro-canvas` — зоны холста, первая деталь, инспектор;
3. `basics-ports` — входы/выходы, форма маркеров (данные/событие/ошибка);
4. `basics-chain` — первая цепочка триггер → лог и первый запуск;
5. `logic-condition` — ветвление по условию «содержит»;
6. `data-converters` — типы и конвертер «Текст → Число»;
7. `telegram-first-bot` — бот-эхо в симуляторе, токен не нужен;
8. `telegram-command` — триггер «Команда» и ответ на `/start`;
9. `web-first-page` — веб-события и кнопка (честная пометка:
   элементы оформления страницы запланированы);
10. `models-first-model` — «Создать модель из выделенного», спуск внутрь.

Дорожки: основы, Телеграм (симулятор), Веб (превью), Модели.
Уроки 11–20 (отладка, Draft/LIVE/публикация, продвинутые темы)
добавляются по мере готовности функций — со **честными статусами**
(`plannedNoteKey`), без обучения несуществующему как работающему.

## Как добавить урок

1. Опишите данные в `src/academy/lessons/base-course.ts` (или новом
   массиве, подключённом в `catalog.ts`): id без точек, шаги с
   нужными типами, `blockId` — только существующие в реестре.
2. Добавьте тексты в `src/i18n/locales/ru.json` →
   `academy.lessons.<id>`: `title`, `description`, `steps.<stepId>`
   с `title`/`text`, при необходимости `hint`, `question` и варианты.
3. Прогоните тесты каталога (`npx vitest run src/academy`): они
   проверят реестр, уникальность, зависимости и наличие **каждого**
   ключа текста.

## Справочник деталей (5.11E)

Маршрут `/academy/reference`, вход из Академии («📚 Справочник»)
и кнопка «?» у каждой детали в библиотеке и инспекторе (открывает
карточку с `?block=<id>`).

- строится автоматически из живого реестра (`buildReference`) —
  второго списка деталей не существует; каждая запись несёт статус
  (`effectiveStatus`), сложность, категорию, порты (вход/выход,
  вид и тип) и связанные уроки (`lessonsForBlock`);
- фильтры: категория, сложность, статус + поиск по названию,
  описанию, id и ключевым словам (`filterReference` — чистая функция,
  переиспользуется далее в поиске помощи);
- запланированные детали помечены явно: бейдж «Запланировано» и
  предупреждение в карточке;
- карточки раскрываются нативным `details/summary` (доступно с
  клавиатуры).

## Задел под будущее (не реализовано)

- глобальный поиск помощи
  (5.11F) используют те же данные: `lessonsForBlock()` уже отдаёт
  уроки для перекрёстных ссылок из справочника;
- онбординг первого запуска (5.11G): структура прогресса содержит
  поле онбординга, интерфейс — далее;
- AI-помощник: движок чистый и не зависит от интерфейса, точкой
  входа станет функция проверки шага и снимок состояния —
  специально не реализуется в 5.11.
