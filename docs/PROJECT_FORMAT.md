# NODEZZLE — Формат проекта и хранение

## Принципы

- **Zod = источник правды.** Схема `nodezzleProjectSchema` (`src/core/project/schema.ts`) описывает формат; TS-типы выводятся из неё (`z.infer`). Разношорирование схемы и типов невозможно.
- **`formatVersion`** — версия формата (сейчас `1`). Загружаемые проекты с другой версией проходят мигратор (задел), неизвестные версии отклоняются.
- **Unknown-поля:** ядро не ломается от полей, которых не знает (forward compatibility); явные нарушения схемы отклоняются при загрузке.
- **Хранение абстрагировано** (`ProjectStorage`): MVP — LocalStorage, будущее — API backend. UI не знает, где лежат данные.

## Структура (formatVersion 1)

```jsonc
{
  "formatVersion": 1,
  "id": "uuid",
  "name": "Мой Telegram-бот",
  "kind": "telegram",               // telegram | web | telegram-web | empty
  "canvas": {
    "id": "uuid",
    "name": "Схема",
    "nodes": [
      {
        "id": "uuid",
        "blockId": "telegram.message_received",  // ссылка на Block Definition
        "label": "переименовано пользователем",  // опционально
        "position": { "x": 0, "y": 0 },
        "config": { "": "значения параметров экземпляра" }
      }
    ],
    "edges": [
      { "id": "uuid", "source": "nodeId", "sourcePort": "portId", "target": "nodeId", "targetPort": "portId" }
    ],
    "viewport": { "x": 0, "y": 0, "zoom": 1 },  // опционально
    "groups": [                                  // опционально (Этап 2, F ч. 2)
      { "id": "uuid", "label": "Оплата", "nodeIds": ["uuid1", "uuid2"] }
    ]
  },
  "models": [
    {
      "id": "uuid",
      "name": "Order Model",
      "version": 1,
      "contract": {
        "inputs":  [{ "id": "user_id", "name": "Пользователь", "type": "number", "required": true }],
        "outputs": [{ "id": "order_id", "name": "Заказ", "type": "number" }],
        "error":   { "id": "error_message", "name": "Ошибка", "type": "text" }
      },
      "canvas": { "...": "CanvasDocument (та же структура, что у проекта)" },
      "updatedAt": 0
    }
  ],
  "variables": [
    { "id": "uuid", "name": "greeting", "type": "text", "value": "Привет", "scope": "project" }
  ],
  "meta": { "createdAt": 0, "updatedAt": 0 }
}
```

**CanvasDocument** (общий для схемы проекта и схем моделей): `id, name, nodes[], edges[], viewport?, groups?`. Узлы и соединения валидируются (min length, наличие blockId/portId). `groups` — опциональные визуальные рамки: `{ id, label?, nodeIds[] }` (Этап 2, подэтап F часть 2); старые проекты без поля остаются валидными.

## Сериализация React Flow ↔ формат

`src/core/project/serialize.ts`:
- `canvasToFlow` / `flowToCanvas` — обратимое преобразование;
- формат хранилища **не содержит** UI-состояния React Flow (selected, measured…) — только канонические данные.

## Хранилище (ProjectStorage)

```ts
interface ProjectStorage {
  list(): Promise<ProjectSummary[]>;
  get(id): Promise<NodezzleProject | null>;
  save(project): Promise<void>;
  remove(id): Promise<void>;
}
```

**LocalStorageAdapter** (MVP): ключи `nodezzle.project.<id>`, JSON, валидация при чтении (повреждённые данные → `null`, список не ломается).

## Autosave

- Каждое изменение схемы (добавление/удаление/двиг/соединение/конфиг/имя) → **debounce 900 мс** → `ProjectStorage.save`.
- Статус в Toolbar: «Черновик» → «Сохранение…» → «Сохранено <время>».
- **Flush**: при `beforeunload` (закрытие вкладки) и при переходе между проектами — синхронное сохранение.
- History/версии (см. ниже) расширяют этот механизм без изменения UI.

## Undo/Redo

Явная история снапшотов canvas (до 100 состояний) в `project-store`: undo/redo (`Ctrl+Z` / `Ctrl+Shift+Z`), дубликаты/копирование/вставка, удаление. Снапшоты — канонические данные (nodes/edges/groups), не UI-состояние.

## Версии и миграции (задел)

- `formatVersion` в корне проекта; `version` у моделей.
- Мигратор: цепочка `v1 → v2 → …` (реализуется при первом изменении формата — этапы 3–4).
- История версий (сравнение, откат) — этап 7 ROADMAP: снапшоты проекта с метаданными (кто/когда/что).

## Правила

- Не добавлять в формат «служебные» UI-поля.
- Новые поля — опциональные (старые проекты остаются валидными).
- Удаление/переименование полей — только через migration + bump `formatVersion` + обновление этого документа.
- Секреты (токены, ключи) **не хранятся** в формате проекта (только ссылки на серверные секреты, в будущем).


### Копирование фрагментов (08A, 0.5.35)

Копия получает новые ID узлов и внутренних связей, прежние порты,
независимые настройки и единое смещение всех позиций. Внешние связи,
визуальные рамки групп и определения моделей не импортируются.
Формат остаётся v1: существующий `flowToCanvas` округляет каждую координату
до целого при сохранении. Дробные взаимные смещения сохраняются при самой
вставке, но после F5 подчиняются этому округлению. Буфер живёт только
в памяти вкладки, не сериализуется; вставленная схема сохраняется обычно.


### Web-текст/заголовок (09B1)

Project JSON остаётся v1. Используются прежние ID/порты, настройки text/level
в существующем config; неизвестные ранее/отсутствующие настройки не требуют
миграции. Дескриптор element — данные выполнения, а nodeInfoGraphKey —
транзиентный снимок UI, не новое поле проекта и не сохранённый HTML.


### Web-структура (09B2)

Формат v1 и прежние порты children:array/element:object сохраняются. Настройки
section.title/grid.columns живут в существующем config. Дерево — значение
выполнения, не новый формат холста/вложенная DOM-структура проекта. Никаких
добавленных ID родителей, координат вёрстки или миграции прогресса Академии.


### Изображения/ссылки (09B3)

Формат v1 неизменен. src/caption и href/text — настройки существующих
web.image/web.link. element остаётся object. Файлы/байты изображений и
согласие на загрузку не сохраняются в Project JSON. После F5 требуется
повторное разрешение внешнего запроса. Старые схемы/прогресс без миграции.


### Поля/формы и копирование (09B4)

Project JSON остаётся v1. Настройки web.input/web.textarea содержат
fieldName, formNodeId, initialValue, label, placeholder; web.form — formMode.
Без formMode используется json. Это поля существующего config, без миграции.
formNodeId — ID экземпляра формы активного холста. При копировании явных
field-блоков ссылка переназначается внутри фрагмента либо очищается, если
форма не скопирована. В произвольных JSON-значениях ссылки не переписываются.
Неотправленный ввод не сериализуется; после submit данные становятся частью
обычной истории выполнения. Прогресс Академии и контракты моделей прежние.


### Информационное окно (09B5)

Формат v1 сохранён. У прежнего web.modal добавлена необязательная настройка
title (fallback пустая строка); порты title/children → element прежние.
Состояние open, фокус и согласие на изображения не сериализуются ни в
проект, ни в undo/redo. Результат modal/title/children — обычные данные
runtime; дополнительные open/обработчики не принимаются рендерером.


### Telegram callback и исходящие действия (09C1)

Project JSON v1 сохранён: callbackDataFilter/text/show_alert — обычные
настройки прежних callback-блоков. Добавленные порты callback_id:text
не удаляют старые ID портов, существующие связи не требуют миграции.
Поля симулятора не сохраняются в проект. В runtime payload/истории появился
необязательный telegram.event (без него — прежнее сообщение).

Outbox — уже не только сообщения: новый kind=callback_answer имеет
callbackQueryId/text/showAlert и не имеет chatId. API-потребитель должен
сначала различать kind; старые text/photo записи не изменены. Это результат
исполнения, не изменение формата проекта. Токены в проект не добавлялись.


### Inline-клавиатура (09C2)

Формат v1 сохранён. Новое определение telegram.inline_keyboard хранит rows
в обычном config; третий вход keyboard у send_message не меняет ID старых
портов. Старым схемам клавиатура не обязательна. connectedInputs существует
только в контексте обработчика и не сериализуется в проект.

Текстовый runtime outbox дополнен необязательными keyboard/messageId.
messageId соответствует локальному порту message_id, не реальному ответу
Bot API. UUID id записи идентифицирует клики превью. Нажатия/сообщения не
сохраняются в Project JSON, после F5 нужно снова выполнить отправку.

## Явные серверные копии (10A, 0.5.46)

Dashboard дополняет, а не заменяет LocalStorageAdapter. После входа и явного
выбора пространства обычный локальный документ читается заново, проверяется
форматом v1 и сохраняется новым серверным проектом (`POST /api/projects`).
Новый root ID и даты meta; canvas/model/node/edge/group/variable ID,
внутренние ссылки (в том числе formNodeId) и настройки сохраняются.

Обратное действие: `GET /api/projects/:id` → проверка схемы и ожидаемого ID →
новый root ID → `ProjectStorage.save`. Коллизия ID или ошибка записи не
перезаписывает старый документ. Поздний ответ после ухода/смены контекста
не начинает локальную запись. Успех показывается только после подтверждения
POST либо успешного локального save. Записи автоматически не повторяются;
timeout POST может означать уже созданную копию — сначала обновить список.

Песочницы с meta.tutorial запрещены в обоих направлениях. Преобразование
через прежнюю кнопку Dashboard — отдельное осознанное действие. Прогресс
Академии, credentials, история запусков и UI-состояние не переносятся.
Ссылки secret_id остаются ссылками: сами секреты, подключения ботов,
снапшоты/версии и LIVE не копируются и не перепривязываются.

**Это не синхронизация.** Открытая восстановленная копия редактируется
локально. UI 10A не вызывает PUT. Условная запись добавлена в 10B1; отдельный
серверный Canvas реализован в 10B2 и открывается явно, без обещаний HTTP-flush в unload.
Формат v1 неизменён; валидация z.object может отбросить неизвестные поля,
поэтому сохранность произвольных полей будущих версий не обещается.

### Практика: перенести обычный проект в другой браузер

1. В Canvas дождитесь «Сохранено», вернитесь в Dashboard. Создайте аккаунт
   или войдите. Выберите рабочее пространство (не выбирается автоматически).
2. В «Серверных копиях проектов» выберите обычный локальный проект и нажмите
   «Сохранить новую серверную копию». Дождитесь подтверждения. Оригинал остаётся.
3. В другом браузере войдите в тот же аккаунт, выберите то же пространство.
   Нажмите «Создать локальную копию», затем «Открыть локальную копию».
4. Проверьте модель/схему после F5. Для новых правок понадобится ещё одна
   явная серверная копия; каждая отправка создаёт отдельный проект.
5. При неподтверждённой отправке обновите список до повтора. При ошибке
   квоты не удаляйте оригинал. На общем компьютере локальные проекты видны
   независимо от аккаунта; выход их не удаляет и не изолирует.

В UI есть та же краткая практика. Реальный межбраузерный сценарий проверяет
`e2e/server-projects.spec.ts`; небезопасные исходы — он же и unit-тесты копий.


## Ревизия API не меняет формат (10B1)

Серверная revision, workspaceId и updatedAt передаются **вне** поля project.
Они не добавляются к NodezzleProject и не переносятся в локальные копии.
Ревизия случайная, не монотонное число и не meta.updatedAt; каждая успешная
запись/restore выдаёт новую. При сохранении нужно передать исходную
expectedRevision, а не подставить метку другой вкладки/свежего списка.
Все детали и тестовая практика API — [PROJECT_API.md](PROJECT_API.md).
Автосохранение локального Canvas и учебный прогресс не изменены.


## Серверный режим редактора (10B2/C, 0.5.48)

`/projects/:id` — локальный режим; `/server-projects/:id` — отдельный
серверный. Одинаковые ID в этих хранилищах не связывают документы.
Серверная сессия получает полный документ с ревизией; `withActiveCanvas`
собирает также правки открытой модели. Смена уровня/ACK не подменяет новый
снимок редактора старой квитанцией. Метки времени не используются как CAS.

Изменения сериализуются последовательно после дебаунса; до отправки
пишется резерв. Новая правка во время запроса остаётся dirty и отправляется
только после ACK предыдущей с его ревизией. Ошибка останавливает цепочку.
Явный GET-пересмотр, подтверждение именно своих уже принятых данных либо
ручной выбор серверного/локального варианта — без слепого повтора.

Резерв — отдельный служебный JSON вокруг неизменного NodezzleProject v1.
Он не добавляется в document, не является обычным локальным проектом и
не переносит credentials. Правила/границы — DATABASE.md и
[SERVER_PROJECTS_GUIDE.md](SERVER_PROJECTS_GUIDE.md).
