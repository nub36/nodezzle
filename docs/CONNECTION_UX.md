# Визуальный жизненный цикл соединения (0.5.28)

Утверждённая UX-концепция: пользователь должен **видеть** каждый этап
соединения деталей. Документ фиксирует реализацию и источники истины.

## Состояния и их источники

| Состояние | Где хранится | Как выглядит |
| --- | --- | --- |
| Перетаскивание соединения | `project-store.dragPort` (ставится в `onConnectStart`, чистится в `onConnectEnd`) | исходный порт — `port-active` (кольцо + свечение) |
| Совместимый порт | чистая функция `getPortVisualState` (`checkCompatibility`) | `port-compatible`: свечение + небольшой масштаб |
| Несовместимый порт | там же | `port-incompatible`: приглушение (не скрывается) + тултип «Несовместимый тип: Текст → Число» |
| Готов к подключению (наведение) | `connection-fx-store.hoverPort` | `port-ready`: усиленное зелёное кольцо |
| Успешное соединение | `connection-fx-store.success` (~650 мс, таймер в сторе) | `port-connect-success` + `node-connect-success` (короткая вспышка), `nzz-edge-pulse` — одноразовый импульс по линии |
| Выполнение схемы | `execution-store.nodeStates` / `flowEdges` (движок `executeCanvas`) | `status-running/success/error/skipped`, анимация рёбер `animated` |

Соединение и выполнение — **разные события и разные сторы**:
`handleConnect` не трогает `execution-store`, вспышка соединения не
показывается как SUCCESS выполнения, и наоборот.

## Эфемерность (ничего в Project JSON)

`connection-fx-store` существует только в памяти: `hoverPort`,
`success` не сериализуются. `flowToCanvas` отдаёт канонический
документ (узлы/рёбра/порты) — поля вида `isGlowing`, `justConnected`,
`animationTime` в данные проекта не попадают (проверено тестом).

## Производительность

- Селекторы `connection-fx-store` в узле возвращают примитив,
  относящийся только к этому узлу: вспышку перерисовывают ровно два
  узла, наведение — один.
- Поиск цели при наведении (`elementFromPoint`) обновляет стор только
  при смене порта-цели — на движение мыши перерисовок нет.
- Состояния `dragPort` меняются дважды за жест (старт/конец).

## Режимы эффектов

Настройка тулбара (`data-testid="effects-mode"`): **полные →
уменьшенные → выключены**, сохраняется; старое поле `effectsEnabled`
мигрируется (`false` → «выключены», `true` → «полные»).

- `full` — свечение + пульс + небольшой масштаб;
- `reduced` — смена цвета/контура без движения (`transform` и
  анимации отключены);
- `off` — только статическая индикация совместимости/готовности.

Системное `prefers-reduced-motion` дополнительно понижает «полные» до
«уменьшенных» и гасит анимации в CSS.

## Академия

Шаг урока `connect` подсвечивает требуемые порты (`port-academy`,
янтарное кольцо): у узла `fromBlockId` — выход `fromPortId`, у узла
`toBlockId` — вход `toPortId` (если порт не указан — все порты
нужного направления). После правильного соединения пользователь
получает одновременно вспышку `CONNECT_SUCCESS` и продвижение шага
урока (проверка шага — по составу рёбер, как и раньше).

## Data-атрибуты для E2E

| Атрибут | Где | Значения |
| --- | --- | --- |
| `data-connection-state` | корень узла | `drag-source` / `connect-success` |
| `data-port-active` | порт | `true` у исходного порта жеста |
| `data-port-compatible` | порт | `true` / `false` во время жеста |
| `data-port-ready` | порт | `true` при наведении совместимого соединения |
| `data-port-id`, `data-port-direction`, `data-node-id` | порт | идентификация для автотестов |
| `data-effects` | обёртка холста | `full` / `reduced` / `off` |
| `data-effects-mode` | кнопка тулбара | текущий режим |

## Отличие от Runtime-анимации

При «Запустить» работает существующий механизм выполнения: движок
обходит реальный путь данных (`executeCanvas`), ставит узлам
`running → success/error`, непосшедшие ветки получают `skipped`,
`flowEdges` анимирует только рёбра, по которым реально шли данные.
Импульс `nzz-edge-pulse` — одноразовое подтверждение соединения и к
выполнению отношения не имеет.

## Геометрия компактных деталей (0.5.29)

Порты располагаются в двух колонках, каждый `Handle` — внутри своей
`position: relative` строки высотой 24 px. Это устраняет наложение
нескольких маркеров на общий центр узла. ID портов, направления,
совместимость, источники визуальных состояний и формат рёбер не менялись.
Полный тип остаётся в подсказке маркера, на самой детали — цвет и глиф.

Проверено в Chromium: разные выходы не пересекаются и доступны указателю;
совместимое соединение создаёт ребро и вспышку, несовместимое — нет;
соединение в уроке переводит на следующий шаг. Тесты:
`e2e/compact-layout.spec.ts`, `e2e/connection.spec.ts`.
