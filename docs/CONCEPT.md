# NODEZZLE — Концепция

## Смысл названия

**NODE + PUZZLE.** NODEZZLE — визуальная среда, в которой пользователь собирает работающие системы из соединяемых деталей, как пазл или LEGO.

## Философия

> **«Не программируй. Собери.»**
> Для Telegram: *«Не программируй бота. Собери его.»*

Рабочая философия продукта:

```
ДЕТАЛЬ
  ↓
СОЕДИНЕНИЕ
  ↓
ЛОГИКА
  ↓
МОДУЛЬ
  ↓
МОДЕЛЬ
  ↓
ГОТОВАЯ СИСТЕМА
```

NODEZZLE **не должен** выглядеть и ощущаться как обычный скучный Node Editor. Интерфейс создаёт ощущение цифрового Puzzle/LEGO: детали светятся, соединения «притягиваются», данные текут по схеме как частицы. При этом **читаемость Canvas и блоков важнее декоративных эффектов** — визуальные эффекты используются аккуратно (см. [UI.md](UI.md)).

## Что собирает пользователь

MVP — **только два основных направления**:

1. **TELEGRAM BOT** — боты из деталей (получение сообщений, команды, ответы, фото…).
2. **WEB / HTML** — веб-интерфейсы из визуальных элементов (страница, кнопки, формы…).

Сейчас **НЕ добавляются**: Discord, WhatsApp, Slack, CRM и другие платформы.
При этом архитектура **расширяема**: новые платформы подключаются поверх общего ядра (Block Definition + реестр + runtime) без переписывания системы (см. [ARCHITECTURE.md](ARCHITECTURE.md)).

## INPUT/OUTPUT — фундамент

Каждая деталь может иметь:

- один INPUT или несколько INPUT;
- один OUTPUT или несколько OUTPUT;
- **ERROR OUTPUT**;
- **EVENT INPUT / EVENT OUTPUT**.

Количество портов архитектурно **не ограничено** (дефиниция блока — произвольный массив портов). Каждый INPUT/OUTPUT **имеет тип**.

Базовые типы:

`Text · Number · Boolean · JSON · Object · Array · File · Image · User · Date · URL · Secret · TelegramMessage · Event · Any · Error`

Архитектура типов расширяема (TypeRegistry для пользовательских типов) — см. [BLOCKS.md](BLOCKS.md), раздел «Система типов».

## Умные соединения

NODEZZLE понимает совместимость INPUT/OUTPUT:

- разрешено: `Text → Text`, `Number → Number`, `Image → «Отправить фото»`;
- запрещено: несовместимые типы соединить «просто так» нельзя;
- для преобразований предусмотрены **Converter-блоки** (Текст→JSON, JSON→Текст, Number→Text, String→Boolean и др.).

Во время соединения:

- совместимые порты **подсвечиваются**;
- несовместимые — визуально приглушаются;
- подходящие соединения могут слегка **притягиваться** (задел в UI, см. IDEAS.md);
- после подключения — приятная анимация соединения.

## Canvas

Основная рабочая область — визуальный **Infinite Canvas**:

Drag & Drop · Zoom · Pan · Connections · Multi Select · Groups · Copy · Paste · Duplicate · Delete · Undo · Redo · Minimap · Search · Snap · Autosave · Keyboard Shortcuts.

Canvas проектируется с учётом **очень больших схем** (см. ARCHITECTURE.md, раздел «Производительность»).

## Живое выполнение

Пользователь видит выполнение схемы. Состояния:

```
IDLE → WAITING → RUNNING → SUCCESS | ERROR | STOPPED
```

- при **RUNNING** блок визуально активен (неоновый пульс);
- при **SUCCESS** — мягкая зелёная подсветка;
- при **ERROR** проблемный блок/порт подсвечен красным;
- по соединениям перемещаются светящиеся частицы, показывающие направление движения данных.

## Debug

Пользователь видит: что поступило в INPUT, что вышло из OUTPUT, JSON-значения, время выполнения, ошибки, историю выполнения. Архитектурно предусмотрены: **DEBUG · LOG · BREAKPOINT · execution history** (BREAKPOINT и более глубокий debug UI — ROADMAP, этап 2).

## Базовые системные детали

Предусмотрена архитектура (реализовано — ✅, зарезервировано — ⏳):

| Деталь | Статус | Деталь | Статус |
|---|---|---|---|
| INPUT | ✅ | SEND EVENT | ⏳ |
| OUTPUT | ✅ | RECEIVE EVENT | ⏳ |
| CONDITION (IF) | ✅ | VARIABLE | ⏳ |
| ELSE | ✅ | MEMORY (SHARED) | ⏳ |
| SWITCH | ✅ | DELAY / TIMER | ✅ / ⏳ |
| CONVERTER | ✅ | LOOP | ⏳ |
| DEBUG / LOG | ✅ | CALL MODEL | ✅ |
| ERROR (сигнал) | ✅ | | |

Регистрация блоков расширяема: новый тип блока не требует переписывания ядра Canvas.

## Модели — одна из главных функций

Пользователь собирает несколько блоков и сохраняет их как **модель** (отдельную деталь).

Пример: **ORDER MODEL**

Внутри: `Input → Validation → Logic → Processing → Output`.
Внешний контракт:

```
INPUT:  user_id: Number, product_id: Number, quantity: Number
OUTPUT: order_id: Number, price: Number, status: Text
ERROR:  error_message: Text
```

После сохранения модель автоматически становится новой деталью: её можно взять из библиотеки и добавить на другой Canvas.

**Модель внутри модели** — поддерживается архитектурно (рекурсивное выполнение):

```
ATOMIC BLOCK → MODULE → MODEL → MODEL OF MODELS → APPLICATION
```

Пользователь может открыть модель и посмотреть её внутреннее устройство (**Drill Down**):

```
Проект > Telegram > Заказы > Оплата
```

Контракты моделей автоматически формируют внешние порты. Механизмы взаимодействия моделей: **CALL MODEL, EVENT, REQUEST/RESPONSE, SHARED MEMORY, INPUT/OUTPUT**. Подробнее — [MODELS.md](MODELS.md).

## Telegram

Первое основное направление. Telegram-блоки (MVP ✅ / план ⏳):

| Блок | Статус | Блок | Статус |
|---|---|---|---|
| Telegram Bot (конфигурация) | ⏳ | Answer Callback | ⏳ |
| Message Received | ✅ | Get User | ⏳ |
| Command | ✅ | Get Chat | ⏳ |
| Callback Query | ⏳ | Inline Keyboard | ⏳ |
| Send Message | ✅ | Send Document | ⏳ |
| Send Photo | ✅ (симуляция) | Send File | ⏳ |
| Edit Message | ⏳ | Delete Message | ⏳ |

Названия, которые видит пользователь, — **на русском**: «Получено сообщение», «Команда», «Отправить сообщение», «Отправить фото», «Изменить сообщение».

Telegram-событие потенциально отдаёт: `message, text, user, user_id, username, chat, chat_id, photo, document, voice, video, location, callback, command`. Не всё реализовано сразу — архитектура позволяет расширять набор портов (см. [TELEGRAM.md](TELEGRAM.md)).

Пример схемы:

```
Сообщение Telegram → Текст → Условие → Модель → Результат → Отправить сообщение
```

## Web / HTML

Второе главное направление. Элементы (MVP — триггеры событий ✅, рендеринг страницы ⏳):

`PAGE · SECTION · CONTAINER · GRID · TEXT · IMAGE · BUTTON · INPUT · TEXTAREA · FORM · MODAL · MENU · LINK · HTML · CSS · JS`

В интерфейсе — русские названия: Страница, Секция, Контейнер, Сетка, Текст, Изображение, Кнопка, Поле ввода, Форма, Модальное окно, Меню, Ссылка.

Web-события: `Page Load, Button Click, Form Submit, Input Change, Modal Open, Modal Close` → «Загрузка страницы», «Нажатие кнопки», «Отправка формы», «Изменение поля», «Открытие окна», «Закрытие окна». События соединяются с общей логикой NODEZZLE. Пример: `Форма → Отправка формы → INPUT модели → Модель → OUTPUT модели → Окно «Успешно»`.

## Telegram + Web — одна система

Telegram и Web — **не** две отдельные системы. Они используют общее ядро NODEZZLE:

```
Telegram Bot → WebApp URL → Telegram WebApp → HTML Page → Button Click
→ Order Model → Order Created → Telegram Message
```

Один проект может одновременно содержать: Telegram-интерфейс + Web-интерфейс + общие модели + общие данные.

## AI

Архитектурно предусмотрена возможность AI-блоков (категория «AI», блоки зарезервированы). AI — **не единственный центр** NODEZZLE.

В будущем пользователь напишет: *«Создай Telegram-бота, который получает фотографию, анализирует её и отвечает пользователю»* — и AI визуально построит соответствующую схему. Возможности AI: создавать блоки, соединять блоки, создавать и изменять модели, искать ошибки, объяснять схему, предлагать исправления. **Ручное визуальное редактирование всегда остаётся доступным.**

## Визуальный стиль

**Premium Dark UI · Glassmorphism · Aurora Gradients · Neon Accents · Depth · Glow · Smooth Motion.**

Основные цвета: black, deep navy, deep blue, purple, cyan, electric blue. Дополнительный акцент: pink/magenta. Аккуратные эффекты: aurora gradient, blurred glow, медленно движущиеся переливы, canvas grid, noise, particles, parallax, depth. Не превращать приложение в визуальный шум. Токены и реализация — [UI.md](UI.md).

## Главная страница

Hero-анимация: отдельные светящиеся детали постепенно соединяются — например `Telegram + Логика + Модель + Ответ` — и из них получается работающая система.

- Основной текст: **NODEZZLE** — «Не программируй. Собери.»
- Основной CTA: **«Начать собирать»**.
- **Playground** — интерактивная демонстрация прямо на главной: `Сообщение Telegram → AI/Логика → Ответ Telegram`; пользователь соединяет детали (демо-поток) и нажимает «Запустить», рядом отображается демонстрационный Telegram-чат. Playground объясняет принцип NODEZZLE без регистрации.

## Autosave

NODEZZLE предусматривает Autosave: пользователь не теряет сложную схему после обновления страницы, закрытия вкладки, ошибки или разрыва соединения. Архитектурно предусмотрена будущая история версий (этап 7 ROADMAP).
